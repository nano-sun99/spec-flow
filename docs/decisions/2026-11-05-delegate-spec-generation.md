# ADR-20261105 · grill-me 专业澄清，spec-flow 负责规格与交付（V2）

- 状态：修订提案；V2 职责与流程已获用户确认，规格待确认送审，规则未实施。
- 日期：2026-11-05；修订：2026-11-08。
- 规格：`docs/specs/2026-11-05-spec-generation-wiring.md`。
- 决策人：用户；依据为 [PR #160 的 V2 确认记录](https://github.com/nano-sun99/spec-flow/pull/160#issuecomment-6720060856)。
- 形态：一次性决策记录，**不代表本仓采用 ADR 制度**。

## 背景

spec-flow 已有需求确认、草稿、设计对照、验收与交付闸口，但用户定位它为流程工具，而不是专业需求梳理技能。引入外部技能的目的，是在需求尚未定完时补足梳理能力，不是把外部技能放在末尾单纯写稿。

用户同时要求：流程精简而不省闸口；用户确认的是改哪里、怎么改、解决什么问题或带来什么能力；有页面时必须等用户设计，再由 agent 梳理页面与接口。

## 决定

1. **专业澄清交给 grill-me**：用户选择开 spec 后立即加载；本轮核对的入口实际调用 `grilling`，依赖检查必须覆盖实际被调用的技能。事实先查、必要决定逐题问并给推荐，不无止境铺开访谈。
2. **规格与流程归 spec-flow**：汇总方案、写和修订同一份 spec，承接目标、验收、路线、DoR、审核及交接；不保留“外部正文不可改 / 本体只能追加附录”的分工。
3. **只保留同一个方案确认循环**：用用户可读的方案说明替代独立机制卡；No 返回澄清，Yes 后立即分页面路径，不另设重复的澄清结果确认。
4. **页面设计后再完成接口与终稿**：有页面先写目标与验收草稿，按现行规则确认拆分，再暂停等用户设计；agent 梳理页面及所需接口后完善终稿。无页面用既有样例规范继续走。
5. **精简不等于省授权**：直接干仍走实现交付闸；spec 与实现分别派审、按需修订、明确合并；spec 合并后开单并等待明确实施委托。条件性卡按触发条件保留。
6. **外围说明不膨胀主图**：缺技能先请求安装授权，拒绝或失败则暂停；不静默换模板。不再依赖 superpowers，也不设置专门的 writing-plans 拦截步骤；不是新增实施计划阶段。

## 备选与取舍

- **原 brainstorming 接线提案，不再采用**：同时委托需求梳理和规格生成能力更完整，但用户选择保留 spec-flow 的规格职责，避免继续维护外部正文、独立附录及附带流程的覆盖关系。
- **仅用本体模板，不作为替代**：本体有基础规范不等于专业梳理能力已经补齐；本次选择外部专业辅助，不另造一套访谈技能。
- **grill-me 辅助澄清，采用**：与本体规格及交付职责分开，但仍须验证逐题推荐、确认循环和页面暂停点能否得到遵守，不能只凭技能名称认定接线完成。

## 影响与重开条件

- 外部技能的入口 / 被调用技能发生变化，重新核对调用关系；缺失时请求授权补齐，不把前置问题扩成另一张主流程图。
- 外部技能出现过度追问或越过页面暂停点，由规格 A2 / A4 的行为演练发现并修正接线，不因此自动增加兜底机制。
- 用户明确改变专业澄清与规格生成的职责，才重新讨论本决定；ADR 仍保持选修。
