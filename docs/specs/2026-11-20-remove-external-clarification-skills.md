# 从 spec-flow 移除外部需求梳理技能

状态：Draft，供用户确认；不是实施授权。日期：2026-11-20。

**目标：spec-flow 不再调用、推荐或要求安装 `grill-me`、`grilling`、`grilling-cards`，也不让 Superpowers 的 `brainstorming`、`writing-plans` 或其他同类技能接替这项职责。** 移除的是外部流程对任务走向的控制，不是用户决定范围和验收的权利。

依据：用户在本次对话中明确说「我的目标是移除」，并要求不要「只是生硬的将技能移除，但是其余相关部分根本就不动」。本规格覆盖当前默认 v1 和显式启用的 v2；不新增流程阶段，不把 v2 切为默认。

## 移除后，需求怎么走

- **需求已经说清**：从用户原话和已批准材料提取本次目标、非目标、验收；能从项目查到的事实自己查。不为证明“澄清过”再访谈，不把可能有用的想法写成本期交付。已有实施委托照原入口接手，不重开需求。
- **确实缺一个决定**：只有查完仍不能确定、且不同答案会改变本次范围、验收、权限或数据处置等关键结果时，才把这个具体问题和代价交给用户。可用现有选项卡；卡片是交互工具，不是设计树或固定轮次。真实缺口未闭合，仍不能把规格当成可实施。
- **保留证据，不保留访谈仪式**：规格或原任务 PR 引用用户原话、卡片选择或已批准记录，让接手者能核对决定来自哪里。有追问就保留实际问题和回答；没有就引用原需求，不补轮次、不写“未用工具原因”。不以 agent 自己的一句总结代替用户决定。
- **设计和授权照旧**：有页面仍等用户设计，再核对本次涉及的交互与接口；无页面仍用实际输入输出核验。范围确认、送审、合并、实施各沿用该版本原有权限。新想法不自动扩入，有实质变化走原范围确认。

## 必须一起改的地方

以下是同一行为的落点，不是多个子项目。基线为 `rebuild/v2@bc905cf`；本机默认读该检出的根 `SKILL.md`，不是 `references/v2/SKILL.md`。

| 落点 | 要消除的冲突 |
|---|---|
| v1：根 `SKILL.md`；`references/` 下的 `one-path.md`、`spec-maturity.md` | 改入口、方案梳理、设计后分析和流程图。不能正文说移除，图上还指示调用，或留下换名的逐轮访谈。 |
| v1：`gate-details.md`、`phase-handoff.md`、`apply-to-project.md`（均在 `references/`） | 去掉专用于梳理技能的发现检查、安装卡、缺失暂停、送审和交接中的调用证明。保留其他安装权限。v2 的 [项目接入](../../references/v2/50-adapters/README.md)复用 v1 接入正文，须验证从这条路也不会触发。 |
| v2：`references/v2/30-playbooks/{spec,new-spec}.md`、`10-stages.md`、`15-records.md`（后两份在 `references/v2/`） | 同时改“推荐、不可用才手动”、阶段证据和交接字段。缺工具、零访谈轮次不再是失败；决定来源不可核仍是缺口。无需修改铁律或新增用户决策。 |
| 对外说明和重建资料：双语 README；`docs/rebuild/` 的盘点、覆盖审计、演练、v1 漂移记录 | 两份 README 均反映实际入口和依赖；区分旧基线与新行为，重新核对受影响的覆盖项和剧本。旧 18 卡是历史比较基线，不把已移除的安装卡当作当前必经。 |

**版本与历史边界**：[旧接线决定](../decisions/2026-11-05-delegate-spec-generation.md)、[v2 总纲的澄清记录字段](2026-11-13-spec-flow-v2-master.md)、R36/R38 和[旧建议 #167](https://github.com/nano-sun99/spec-flow/issues/167)是此前做法的依据。本规格获批后，只取代其中与上述目标相反的部分；以新的依据和取代指针衔接，不改写旧决定、历史验证结果或据此关闭旧单。远端 `main@4e797a1` 在开 spec 后才接入 `grill-me`，与重建分支的入口不同；交付时按实报覆盖的分支，不把修改草案等同于已更新默认发行版。

## 验收：看行为，不看删了几个名字

在隔离环境用同一输入分别走默认 v1 和显式 v2，对比相关技能**可见 / 不可见**的实际记录；不改用户机器上的安装。不把下面的预期当作已跑结果。

| 输入或入口 | 通过条件 |
|---|---|
| 明确要求“只把导出表头 A 改成 B，顺序不变”，已明确直接干 | 零额外需求访谈，不问是否新增导出格式；保留原交付确认。不能因没有访谈记录而补问或阻断。 |
| 导出范围只有“本人数据 / 全组数据”两种业务口径，现有授权和材料未给出答案 | 只问谁的数据可以导出；未确认不自行选全组。选择可追溯，不派生新的权限管理功能。 |
| 走到页面设计对照，或续接有明确委托的既有任务 | 前者照设计核本次交互与接口；后者按获批范围接手。都不另起访谈、计划或第二份规格。 |
| 从普通入口及 v2 的项目接入指针进入，分别在技能可见和不可见时观察 | spec-flow 发起的发现、读取、调用、安装提示均为零；不因缺技能暂停。两种环境下范围、验收及必要批准相同。 |

实现验收还需运行 `scripts/check-docs.sh`、检查受改链接和流程图，并人工区分“历史记载”与“仍可执行的指令”。脚本绿、关键词零命中均不能替代行为回放；没有实际轨迹的场景标未验证。

**不做**：不卸载或改写外部技能，不改全局指令、客户端自动触发或采用项目，不禁止用户独立使用这些工具；不新建替代技能、检查平台或审批环节。本次交付只有这份规格草案。
