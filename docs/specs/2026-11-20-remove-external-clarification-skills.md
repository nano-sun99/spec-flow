# 仅从 spec-flow v2 移除外部需求梳理技能

状态：Draft，未批准实施。日期：2026-11-20。范围决定：用户在本 PR 审核时明确答复「只做 v2」。

**目标：显式启用 v2 后，spec-flow 自己完成必要的需求澄清，不查找、读取、调用、推荐或提示安装 `grill-me`、`grilling`、`grilling-cards`；也不用 Superpowers 的 `brainstorming`、`writing-plans` 或其他同类技能接替。** 是否装有这些技能，不改变任务范围、验收和授权。

不改默认 v1（包括 `rebuild/v2` 分支的根 `SKILL.md`、旧 `references/`、根目录双语 README），不补 `main`，不切默认入口。**未明确启用 v2 的使用者仍可能遇到旧行为。** 不卸载本机技能、不改全局指令或采用项目，不限制用户在本流程外自行调用；不新增替代技能、检查平台或审批环节。

## 什么算移除成功

- **已有答案不再问。** 用户的原话、卡片选择或已批准材料能说明目标、边界和验收，就引用其来源，不补访谈轮次、不写“未用工具原因”。能查的事实先查；查完仍有影响范围、验收、权限或数据的关键决定，只问那个缺口，未获答复不擅定。可用原有选项卡；不按设计树扩题。未经确认的旁支不进入本期交付。
- **记录决定，不记录仪式。** 有真实追问才记实际问答；零追问也可以有充分证据。反过来，无论有多少轮访谈，决定无可核来源或承重缺口未解，仍不能判规格可实施。
- **其余行为不变。** 有页面仍等用户设计、再核对本次交互和接口；无页面按实际输入输出验证。已有实施委托不重开访谈。v2 原有计划卡的触发条件及范围、送审、合并、实施等独立授权不变；不另起一份澄清流程或实施计划。

## 验收：在显式 v2 上观察实际动作

隔离回放中固定客户端、模型、项目事实、输入和 v2 入口，只改变相关技能是否可见；不动用户安装。以下是预期，不是本 PR 已跑结果。

| 输入或入口 | 通过条件 |
|---|---|
| “只把导出表头 A 改成 B，顺序不变，直接干” | 引用原要求，不为留记录追问，不引入新格式；原有交付确认仍在。 |
| “导出数据”，但材料没有说明导出本人还是全组 | 问数据范围，未答不扩大授权；答复后可追溯，不引入权限管理功能。 |
| 已有用户设计的页面进入规格对照；另一个样例是已有明确委托的实施单 | 前者继续分析实际交互和接口；后者直接接手。两者都不另起需求访谈或第二份规格。 |
| 明确按 v2 应用到临时项目，经过 v2 的适配入口读取借用的 v1 说明 | 完成适用的正常接入检查；不探测、不读取外部梳理技能、不推荐安装，缺技能不暂停。 |

每次保留规则提交、输入与可见技能、文件读取和工具调用轨迹、对话中推荐/安装/暂停以及最终范围。每个样例在两种可见性下都须满足表内结果；受测技能的**流程主动动作应为零**，客户端预载技能目录不是 v2 调用。用旧 v2 基线的同一新需求做一次阳性对照：须能从轨迹看见旧指南触发读取、推荐或不可用回落中的至少一种。轨迹不可见、归因不清或旧对照未触发，记“未验证”，不能凭没看到提示判通过。实施时另跑 `scripts/check-docs.sh`、核受改链接和范围差异；文档检查不替代行为回放。
