# v2 B1：盘点现有规则 + 写铁律（批次 spec）

- 状态：Draft
- 日期：2026-11-13
- 总纲：`docs/specs/2026-11-13-spec-flow-v2-master.md`；本文件只引用总纲 §五、§十，不复制铁律正文
- 批次：B1 / P0 盘点 + P1 铁律
- 依赖：无
- 下游：B2、B3、B4

## 一、目标

把现有规则逐条归类，写出一页铁律，并给后续批次一个可读的 v2 入口骨架。B1 不写阶段合同、决策目录、playbook 或案例。

## 二、交付物

| 文件 | 内容 |
|---|---|
| `docs/rebuild/inventory.md` | 旧规则逐条处置表：来源、规则摘要、归类（铁律/阶段合同/决策/playbook/案例/丢弃）、新落点、理由 |
| `docs/rebuild/v1-drift.md` | P0-P6 期间对 v1 的任何改动；没有就写“无” |
| `references/v2/00-constitution.md` | 8 条铁律；每条写条文、为什么、执行方式、验收例子；≤60 行 |
| `references/v2/SKILL.md` | v2 入口骨架：是什么、何时用、循环、五层导航、异常协议、硬闸清单；B4 再定稿 |

## 三、执行方法

1. **列全旧文件**：`references/*.md` 全部 17 个 + `docs/specs/2026-11-11-branch-release-flow-drill.md`；漏一个就是阻断。
2. **逐条盘点核心三份**：`one-path.md`、`gate-details.md`、`phase-handoff.md` 每一节、每一张卡、每一个状态都进处置表；按总纲 §十 的映射归类。
3. **给每个处置写理由**：保留的写“服务哪条铁律/合同/决定”；合并的写“并入哪里”；丢弃的写“为什么砍、砍了以后不保证什么”。
4. **写 drop 列表**：单独一节，列所有不进入 v2 的规则；这是“替代品”而不是“并行副本”的证据。
5. **写铁律**：按总纲 §五 的 8 条，每条写条文、为什么、执行方式、验收例子；不新增第 9 条。
6. **写入口骨架**：只写导航和循环，不写批次细节；B4 再补链接检查。
7. **记 v1 漂移**：P0-P6 期间如果改了 v1，记入 `v1-drift.md` 并回填盘点表。

## 四、验收

- [ ] 盘点表覆盖全部旧 `references/*.md` + drill。
- [ ] 核心三份的每一节/每一张卡/每一个状态都有处置，无“无落点”。
- [ ] 每条处置有归类、新落点、理由。
- [ ] drop 列表存在，每条有“砍掉后不保证什么”。
- [ ] 8 条铁律，每条有执行方式和验收例子；≤60 行。
- [ ] 入口骨架能一跳到达五层；不引用不存在的 v2 文件。
- [ ] 根 `SKILL.md`、旧 `references/`、adopt 行为未改。
- [ ] `docs/rebuild/v1-drift.md` 存在（没有就写“无”）。

## 五、不做

- 不写阶段合同、决策目录、playbook、案例库。
- 不移动、不删除旧文件。
- 不改根 `SKILL.md`。
- 不建 later 批次的 issue。

## 六、风险

| 风险 | 对策 |
|---|---|
| 盘点变成抄文件清单 | 每条必须有归类和理由；没有处置的规则就是漏 |
| 铁律写成流程 | 每条 ≤8 行；装不下就降级到阶段合同/playbook |
| drop 列表被省略 | 验收单列一项；没有 drop 列表就是 B1 未完成 |
