## 1. 起点、终点与主路

**起点**：用户提出新需求，或明确委托实施已获批的 issue。

**终点**：交付按规格验收，审核与修订按用户选择闭合，并对最终 PR 取得该 PR 单独的合并授权；否则停在清晰命名的待决定状态。

| 步 | 触发 → 响应 | 失败 / 未答 | 落点与证据 |
|---|---|---|---|
| 1 需求 | 新代码需求 → 核对是否已有获批 spec；动笔前核工作区、范围、目标与 diff（R2-11） | 无获批规格 → 先完成方案；不得按大小自判豁免 | spec 链接 / 当前 issue |
| 2 方案 | 方案页四格各自独立点；新增机制单摆机制卡（R2-10）；判页面，判不了停 | 用户未批准 → 不写代码；纯事实查询不造 spec | 用户回复 + spec 版本 |
| 3 交接 | spec PR 合并 → 报 `SPEC_READY` → 开执行 issue 与交接区 | issue 建失败留在 `SPEC_REVIEW` 重试 | `phase-handoff.md` 交接区字段 |
| 4 授权 | 用户按闭集表述委托（「开始实施 #N」等） | 表述不在闭集 → 不开工 | `phase-handoff.md:105-108`；授权记录 |
| 5 实施 | 一次授权覆盖整份 spec；步骤不跳、不合并（R2-9） | 只在六个停止点停（`phase-handoff.md:56` 原文，不复制） | 变更与验收证据 |
| 6 审核档 | 每份交付物合并前摆派审卡，卡上带「文档检查」一行 | 卡未展示不算过闸；展示后未答按「不审」自查（R2-1），仍不得省合并卡 | 机制 1 的记录 |
| 7 修订 | 有 findings → 按项分类，摆修订卡；改判据前读 `spec-revision-sync.md`（R2-P） | 未答、阻断/高未闭合 → 不合并 | 每条 finding 的落点与证据 |
| 8 合并 | 最终 diff、目标、head 确定后，**每份 PR 单独**摆合并卡 | 沉默、拒绝、head 变化 → 重新核对该 PR 的合并授权 | PR、目标、head、验证、未处理项 |

越界（diff 出了「改」清单）不进修订卡：停，走变更单（`one-page.md:45-55`），用户点头才纳入清单。越界文件从未被批准，用「全改」顺手修等于绕过批准。

## 2. 授权边界

### 2.1 卡片留痕（机制 1）

- 记录只准两种事实：`用户：<原话> · <消息定位>`（用户答过）或 `未答 → 按不审`（没有回答）。
- **禁止**在未答时写「用户：」开头的内容；伪造回答 = 未摆卡，按 `gates.md` 的「卡未展示」处理。
- 字段：`卡：<卡名> · <时间> · 对象 <PR/head> · 选项 <列出的选项> · 文档检查 <绿/红+摘要/无入口>`；合并卡另加 `head <sha>`。
- 落点：审核卡记 `gate-details.md` §一，合并卡记 §四；`gates.md` 只留一句指针。
- 一卡盖批（`gate-details.md:40`）记一条，写明「N 份 × 档位」与成员清单。
- 项目禁的审核档（`project-integration.md:37`）在卡上写「项目禁档：不摆、不派」，视同已展示已答。
- 拿不准算不算要摆卡时不自判，摆卡并在卡上写明归属（R2-4）。
- 无 PR 的交付只走派审卡，记录写「交付确认」，不产生合并授权（R2-6）。

### 2.2 委托与停止点

- 委托入口按 `phase-handoff.md:105-108` 的闭集判断，不写「等价的明确委托」。
- 一次授权覆盖整份 spec；阶段完成不是停点，停止点以 `phase-handoff.md:56` 六项为准。

### 2.3 免方案期口径（机制 3）

免方案期只有三个入口：纯查事实；用户当场点名「这小活直接改」；用户说「直接干 / 别走流程」。agent 不据文件数、行数自判，也不在用户没点名时引用本条。

## 3. 越界与 findings 分类

- 越界 = 停 + 变更单；修订卡只处理已批准范围内的 findings。
- 范围外的增强与更优解进建议池，不阻断本单（`gates.md:44`）。
- 严重度按 `gate-details.md:20`，不新增分类法。
- 「闭环前提未定」只在两条件同时成立时用：缺该前提则某条 AC 不可验证；能指出缺什么证据。

## 4. E5 修正（机制 2）

1. **缺「改」清单 fail closed**：给了 `--base`/`--diff` 且 diff 非空、spec 没有「改」清单时，E5 报红，提示含「缺「改」清单」字样与「闸一 E1–E4 不受影响」。没给 `--base`/`--diff` 时仍为「跳过」。
2. **「不改」参与比对**：diff 命中「不改」路径即报红。同一文件同时命中两边时更具体者胜（段数多者 → 字符串更长者 → 「不改」胜）。
3. **路径归一化**：清单项先剥句末标点再剥反引号，避免 `` `references/rationale.md`。 `` 不命中自己；补「清单每项必须命中自己」fixture。
4. **改名成对**：`--diff` 里 `--- a/旧` 与 `+++ b/新` 同时出现时，按新路径判，旧路径列入豁免并在输出里列出。
5. **不判语义**：仍只按路径检查。
