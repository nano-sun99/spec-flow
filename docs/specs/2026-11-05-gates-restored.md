### 1.4 原始触发逻辑（本次恢复的基准）

基线取 `75c11fd^`（瘦身前、含 R30 修补）。

| 授权点 | 触发 | 没回答 | 授权范围 |
|---|---|---|---|
| 方案页四格 | 需求确认后，逐格独立点 | 页面判不了就停，其余按保守默认 | 只定方案形状 |
| 拆分卡 | 骨架成形后 | 不拆，保留 1 份 | 只定拆不拆 |
| 派审卡 | 每份交付物合入目标分支前（段一第 4 步、段二第 9 步） | 按「不审」走，不阻塞、不追问 | 只定审不审、哪一档 |
| 修订卡 | 审核有发现（零发现不摆） | 不合并 | 只定改哪些 |
| 合并卡 | 每次合入目标分支，含纯文档 / 机械回填 | 不合并，沉默不算同意 | 只授权该 PR、该目标、该最终改动 |
| 实施委托 | spec 合并、issue 开完并报告后 | 不开工 | 只授权实施 |

三条容易恢复错的：

1. **摆卡与点档是两件事**：摆了没点 → 按不审继续；没摆 → 不算过闸。
2. **顺序是三张卡依次出现**：派审 →（有发现才有）修订 → 合并；不得并卡、不得跳序。这句话原本只在 `gate-details.md`，默认面没有。
3. **Ready 不是闸**：原始第 4 步是「开 PR → 过闸」，没有 Ready。Ready 是 Draft PR 引入后的 PR 状态，把派审卡绑上去会造出「没 Ready 不必审」。

### 1.5 外部依据

- Skills 分层：description 常驻、body 触发时加载、references 第三层按需（[Anthropic](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)）。判定规则属前两层。
- 执行意图比目标意图有效（[Gollwitzer & Sheeran 2006](https://www.sciencedirect.com/science/chapter/bookseries/abs/pii/S0065260106380021)）：「每份合并前 → 摆派审卡」是可执行的事件，「审核由用户点档」不是。

### 6.3 恢复的五句（逐字）

1. 每份交付物合入目标分支前摆派审卡，agent 不自派。
2. 摆过算过，没摆不算；未答派审卡按「不审」走，不阻塞、不追问。
3. 有发现摆修订卡（全改 / 只改阻断 + 高 / 不改）；没答不合并。
4. 派审 → 修订 → 合并依次出现，不得并卡、不得跳序；过闸不授权合并。
5. 机械变更只免派审卡；合并卡每次都要，沉默不算同意。

### 6.4 明确不复原的两处

- **不复原** 10-17 版「只含 spec / 文档的 PR 长期合并授权」：R30 已删，照抄会把洞带回来。
- **不复原**「Ready 是闸」：Ready 只是 Draft 转可合的状态，不是授权点；派审卡绑「合并前」这个动作。

### 6.5 自定细节

- 机制上限取 3，超了弹拆分卡；恢复旧机制、替换措辞不计入新增名额。
- 报备制：一句话说完直接做，不摆卡；判不准（拿不准是不是改一行）照摆卡。
- 四格锚字段不可省、顺序固定；「闸」一格写当前卡与状态（如「派审：待点」）。
- 交付三行只对用户说，不进 PR 正文；PR 正文仍走 §6.3 的回填骨架。
- 五句判定只落 `SKILL.md` 一处；`gates.md` 保持审核协议，不复制判定。
- W1 的黄来自 §0 决策来源里的用户原话（含「以后」二字），原话不改，黄照留。

## 9. 风险与对策

- **R1 文字服从率有上限**：闸仍会被跳过。对策：二值判据 + 每轮「闸」格 + 交付三行，让用户在当场看见；不承诺 100%。衡量看用户抓到漏闸的次数。
- **R2 五句挤进第 5 步读不动**：一句话塞了顺序、默认、边界。对策：若超出 2,800 字符，先删第 5 步里的「最多 2 轮」（轮次已在 `gates.md`）。
- **R3 报备制被读成免审**：一句话报备不等于跳过方案期。对策：措辞写「直接做」不写「免方案期」；判不准照摆卡。
- **R4 机制上限误伤**：把「恢复」误算新机制。对策：§6.5 写明计数口径。
- **R5 与 `one-path.md` 重复**：卡选项两处出现。对策：`one-path.md` 只作场景包展开，判定以 `SKILL.md` 为准，本轮不改它。
