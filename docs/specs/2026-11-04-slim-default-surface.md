## 1. 背景与现状

- 8 周：44 行 → 2,945 行（`SKILL.md` + 17 份参考），250 个 commit，单调上涨。
- 构成：`SKILL.md` 118 行；核心场景细则 784 行；项目制度 1,391 行；依据 652 行。
- 35 条依据里，明确的「停用」只有 R27；R13、R23 两次「瘦身」都是把细则挪进 `references/`，主文件短了、总量没降；R35「一份 spec 一条路」新增 `one-path.md` 122 行、同时改 6 份参考。
- 全仓没有一处把进度交给 harness 的 goal / todo / plan 状态。
- 结果：默认面 = 17 份；审核面随参考数量膨胀；目标只存在开场几句话里。

结论：不是纪律问题，是机制——每翻一次车加一条规矩，规矩不可执行，下次再补。要停的是「默认面继续长」，不是「把所有历史删掉」。

## 3. 目标与非目标

### 目标

- **默认面 3 份**：`one-page.md`、`gates.md`、`project-integration.md`；加 1 个 `scripts/spec-check.py`。
- **现有 17 份参考全部保留**（场景包 / 归档 / 按需）；每份一行触发条件；默认路径不读第 4 份。
- **审核固定四进三出**：输入 AC、diff + 证据、上轮 findings、已拍板决定；输出 AC / 证据 / 过不过三列 + 建议池；最多 2 轮。
- **目标锚**：spec 第一屏三行（目标 / 不做 / 验收）；复杂活每轮回复第一行「目标 / 本轮推进 / 还差」。
- **依据按需**：默认面只读与 3 闸相关的 rationale 条目，其余查时再读。
- **覆盖不丢**：普通单端、大 spec 拆分、方案交接、观察式完成、撞锁、接入新项目，都能按触发表找到入口。

### 非目标

- 不删、不移动现有 17 份参考；不承诺仓库总行数下降（降的是默认面）。
- 不改 PR / issue / worktree 主流程；不装插件；不改 DSH / Claude Code。
- 本 spec 不写业务代码；脚本在实施 PR 落地。
- 不新增阶段、卡片、审核档位；`SKILL.md` 预算从 4,700 降到 2,800（只降不升）。
- 不重写历史 spec；不批量改已合并文档。
- 不把 35 条依据删光；只让默认面不读它们。

1. **本 spec 自身**：`python3 scripts/spec-check.py docs/specs/2026-11-04-slim-default-surface.md --base origin/main` → E1–E4 绿、E5 绿、7 条 AC、exit 0；W1 绿。

3. **E5 三反例**：untracked `src/c.py` → E5 红；`--diff` 补丁含 `src/b.py` → E5 红；`--base no-such-ref` → E5 红；base 无差异 → E5 绿。

样例回答不了「输入输出 / 失败怎么办 / 重跑会怎样」就不算合格；上面 3 组都给了命令与输出。
