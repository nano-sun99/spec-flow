## 1. 背景：不是写得不够，是默认面等于全部

- 8 周：44 行 → 2,945 行（SKILL + 17 份参考），250 个 commit，单调上涨。
- 构成：SKILL 118 行；核心场景细则 784 行；项目制度 1,391 行；依据 652 行。
- 35 条依据里，明确的「停用」只有 R27；R13、R23 两次「瘦身」都是把细则挪进 `references/`，主文件短了、总量没降；R35「一份 spec 一条路」新增 `one-path.md` 122 行、同时改 6 份参考。
- 全仓没有一处把进度交给 harness 的 goal / todo / plan 状态。
- 结果：默认面 = 17 份；审核面随参考数量膨胀；目标只存在开场几句话里。

结论：不是纪律问题，是机制——每翻一次车加一条规矩，规矩不可执行，下次再补。要停的是「默认面继续长」，不是「把所有历史删掉」。

## 5. 方案

### 5.1 三层，各管各的

- **持久层（仓库）**：`one-page.md` + spec 正文 + issue/PR。跨会话、跨 harness。
- **会话层（harness）**：DSH 用 goal + plan + todo；Claude Code 用 plan + todo。不跨家同步。
- **闸层（脚本）**：`spec-check` + 3 道闸 + 审核协议。两边都能跑。

### 5.2 常驻 3 份的内容边界

| 文件（目标行数） | 只放什么 | 不放什么 |
|---|---|---|
| `references/one-page.md`（~40） | 目标 / 不做 / 验收；范围（改 / 不改）；R / AC / 验证；页面 / 机制 / 例外 / 改旧 spec 四格默认值；变更单 | 8 卡细则、拆分规则、审核档位 |
| `references/gates.md`（~60） | 3 闸（规格 / 范围 / 完成）；审核四进三出；2 轮上限；建议池；文档检查；观察式 / 修订 / 撞锁各 3 行判定 | 四档派几个、多份叠加算法、完整完成例外 |
| `references/project-integration.md`（~40） | PR / issue / worktree / 回填 / 标签；项目制度只放指针 | ADR / 发布 / 文档生命周期正文 |
| `scripts/spec-check.py`（~150） | 5.4 的检查项 | 不做 LLM 判断、不自动改文件 |

同一规则只有一个 owner：常驻写判定和指针，场景包写细则；常驻不复制细则。改判定时同步改指针指向的场景包，避免两处当前真相。

### 5.4 `spec-check` 接口

命令：`python3 scripts/spec-check.py <spec> [--base <ref>] [--diff <file>] [--json]`（纯标准库，零依赖）

读 spec 的三块：第一屏三行（目标 / 不做 / 验收）、范围（`改：` / `不改：`）、AC 表（`AC | 验收 | 验证 | 结果` 或等价 bullet）。

| 编号 | 级别 | 检查 |
|---|---|---|
| E1 | error | 三行锚缺失或为空 |
| E2 | error | AC 为空，或某条 AC 没有验证方法 |
| E3 | error | 占位符 `{{...}}`、`TBD`、`待补` |
| E4 | error | AC 结果有 ❌，同条没有「处置」说明 |
| E5 | error | diff 命中「改」清单之外的文件（需 `--base` / `--diff`） |
| W1 | warn | 模糊词：顺便 / 以后 / 尽量 / 可能 / 应该 / 等等 |
| W2 | warn | 「不改」为空 |

输出固定三列：`检查项 | 结果 | 证据（file:line）`；末行 `绿 / 红`；有 error 退出 1，只有 warn 退出 0。豁免写在同条：`<!-- spec-check:ignore E4 理由 -->`，理由必须可见。历史 spec 没有「改 / 不改」清单时，E5 跳过并 warn，E1–E4 照跑。
