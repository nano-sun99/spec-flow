# 项目接入总则（50-adapters）

> 本页是项目接入、显式升级、指针模板、5 个选修模块采纳动作与资产边界的**唯一自足正文**。
> 接入不是两段流程的一步；普通任务不顺手接入、不补制度、不自动开启选修；本 skill 不维护采用名单。

## 一、只读检查与拟稿边界

当用户要求「先检查、给出拟写指针，本轮不写」时，只用只读工具核项目入口、链接目标与现有制度，然后交付两项即结束本轮（不列多余备选写法，不追问「现在写入吗」）：

1. **检查结果**：分清已核实事实与未核事项（能核文件元数据、软链与末字节就实际核对）。
2. **拟写指针**：指向本次实际读过的中央入口（默认根 `SKILL.md`）；远端分支与客户端路径须有可核来源，未核实的行省略，未采用的选修省略；不为填模板枚举客户端技能目录。

## 二、只指向式契约与目标文件判定树

- **只指向式**：项目入口只放指针块，指向中央真身，**不复制流程正文、不做同步机制**（静止副本会静默过期）。
- **前置检测（写入前必做）**：
  - `AGENTS.md` / `CLAUDE.md` 若是符号链接：指向仓内另一指令文件时只写目标文件；指向**仓外**共享文件（如 `~/.agents/AGENTS.md`）时**停手报告，不写**。
  - 目标文件末行无换行（`tail -c1`）时先补换行并留空行，防止新标题被吞进上一行。
- **目标文件判定**（指针本体只写 `AGENTS.md`，双工具共用单源）：
  - 无 `AGENTS.md` 无 `CLAUDE.md` → 新建 `AGENTS.md`，不建 `CLAUDE.md`。
  - 无 `AGENTS.md` 有 `CLAUDE.md` → 新建 `AGENTS.md` + 在 `CLAUDE.md` 补独立一行 `@AGENTS.md`。
  - 有 `AGENTS.md` 无 `CLAUDE.md` → 仅向 `AGENTS.md` 追加指针节。
  - 两者皆有 → 向 `AGENTS.md` 追加指针节 + 核 `CLAUDE.md` 存在有效 `@AGENTS.md` 行（必须单独一行、不在反引号或代码块内，锚定匹配 `^@AGENTS.md$`）。
- **幂等与旧副本处置**：
  - 已有指针节判定需**同时**命中「spec-flow」与「唯一真相源 / 不复述 / 不放副本」语义；已存在则只校验形制，过期才就地更新。
  - 发现项目内有流程全文副本或复述步骤的指令段落：一律**报告并交用户定夺**，不自动删除或改写；项目自有制度与中央冲突时报告来源并停受影响部分，不宣布中央覆盖项目。

### 核心指针块模板（写入 `AGENTS.md`，按实际路径替换）

```markdown
## 流程规矩：来自 spec-flow

本仓复杂任务按 spec-flow 执行；规则唯一真相源在中央真身，**本文件不复述正文、不放副本、不做同步机制**。

- 使用 spec-flow 时读取：<本次核实的中央入口路径或远端 SKILL.md 链接>
- 认领既有 issue 实施同样从 spec-flow 交付段进入；改中央规矩去改真身并提交。
- 项目自有入口与已采用选修不会因中央改动自动改写；需补齐时显式要求更新接入。
```

## 三、5 个选修模块（默认全部关闭）

所有选修模块支持两种模式：**本次按需读取**（不写项目规则）与**项目级持久采用**（写 `AGENTS.md` 短入口与允许的非可执行资产）。未知修饰词当场问用户，不猜测。

| 修饰词 | 项目入口（`AGENTS.md`） | 默认项目资产 | 执行时点 | 唯一正文 |
|---|---|---|---|---|
| `adr` | `## 已启用：决策记录（ADR）` | `docs/decisions/README.md`（若无自带制度） | 开工检索；拍板长期决定时写入；spec 只链不抄；收尾核本次 | [adr.md](../30-playbooks/adr.md) |
| `doc-lifecycle` | `## 已采用：文档生命周期` | 无（不新建规则页） | 先核现状文档与现行 ADR；实施前必读获批 spec | [15-records.md](../15-records.md) §四 |
| `issue-status` | `## 已采用：issue 状态标签` | 8 个状态 / 卡点标签 | 开发、验收、合入、上线分拣、关单与盘点 | [labels.md](../30-playbooks/labels.md) §一 |
| `issue-type` | `## 已采用：issue 类型标签` | 8 个类型标签（含授权迁移与 open 回填） | 新建 issue 挂类型；首次采用迁移旧标与回填 open | [labels.md](../30-playbooks/labels.md) §二 |
| `release` | `## 已采用：发布纪律` | 发布记录（项目现有位置）；不建分支 / tag / 脚本 | 开分支、形成候选、发布前对齐、发布后回填与应急 | [release.md](../30-playbooks/release.md) |

### 各模块采纳动作要点

- **`adr`**：先查项目是否已自带 ADR 目录 / 规则页；自带则直接复用路径与命名，不建第二套。无自带制度时建 `docs/decisions/README.md`（只留载体分工 + 命名默认 + 中央链接，不抄细则），并在 `AGENTS.md` 写短入口（含开工检索、拍板即写、spec 只链不抄、收尾核本次四项指令）。
- **`doc-lifecycle`**：确认项目现状文档路径（没有先问用户，不代挑）与已有文档规则页；在 `AGENTS.md` 写短入口（现状文档唯一正文路径、默认读序、历史冲突以现状和实测为准），不新建规则页。
- **`issue-status`**：先 `gh label list --limit 200`（同名不覆盖，旧语义标只报不自动迁）；建齐 8 个标签，向用户核清有无测试环境后写 `AGENTS.md` 短入口：
  - 颜色与名称：`未开始` `EDEDED`、`进行中` `1D76DB`、`待测试` `5319E7`、`测试完成` `006B75`、`待上线` `0E8A16`、`待验证` `C2E0C6`、`等拍板` `D93F0B`、`受阻` `B60205`。
- **`issue-type`**：先统计旧标（`enhancement` / `documentation` / `type:*`）挂单数与无类型 open 单数并报告；用户点头后按 [labels.md](../30-playbooks/labels.md) §二 迁旧标、建 8 个类型标签、只回填 open 单，最后写 `AGENTS.md` 短入口：
  - 颜色与名称：`feat` `1D76DB`、`bug` `D73A4A`、`docs` `0075CA`、`refactor` `6F42C1`、`perf` `FBCA04`、`test` `0E8A16`、`chore` `BFD4F2`、`security` `B60205`。
- **`release`**：先只读核长期分支、发布约定与现有标签接入（核 `issue-status` 前提，缺项只报不顺便启用）；由用户选定形态（单主线 / 三层 / staging 线）与真实分支映射，仅将获批形态与映射写入 `AGENTS.md` 短入口，不自动创建分支、tag、开关或发布脚本。
- **代码地图**：默认停用；普通应用 / 升级不探测也不配置。仅用户另行明确要求试用或持久恢复时，按源码交叉核对分母与写入授权后再登记入口，不因工具已安装推定恢复。

## 四、默认资产边界与可执行资产升级闸

- **默认资产**：仅限文档入口与上表「默认项目资产」列出的非可执行资产。脚本、CI、Hook、Workflow、生成器、机器人（**可执行资产**）绝不随采纳自动创建。
- **可执行资产升级闸**：确需新增可执行资产时停在「材料备好」，列齐 5 项——`路径与类型`、`解决的问题`、`触发方式`、`维护成本`、`Markdown-only 替代方案`——经用户明确同意后才建；授权仅覆盖当次列明路径，不外推。
- **收尾报告**：分别报告规则入口、工具、配置、跳过项、旧物与本次验证末态，不以「已启用」冒充全部就绪；验收演练只在假仓进行，不污染真实采用项目。
