# 项目接入总则（50-adapters）

> 本页是项目接入、显式升级、指针与选修入口模板、5 个选修模块采纳动作与资产边界的**唯一自足正文**。
> 接入不是两段流程的一步；普通任务不顺手接入、不补制度、不自动开启选修；本 skill 不维护采用名单。

## 一、只读检查与拟稿边界

当用户要求「先检查、给出拟写指针，本轮不写」时，只用只读工具核项目入口、链接目标与现有制度，交付两项即结束本轮（不列多余备选写法，不追问「现在写入吗」）：

1. **检查结果**：分清已核实事实与未核事项（能核文件元数据、软链与末字节就实际核对）。
2. **拟写指针**：指向本次实际读过的中央入口（默认根 `SKILL.md`）；远端分支与客户端路径须有可核来源，未核实的行省略，未采用的选修省略；不为填模板枚举客户端技能目录。

## 二、只指向式契约、目标文件判定树与显式升级

- **只指向式**：项目入口只放指针块，指向中央真身，**不复制流程正文、不做同步机制**（静止副本会静默过期）。
- **前置检测（写入前必做）**：
  - `AGENTS.md` / `CLAUDE.md` 若是符号链接：指向仓内另一指令文件时只写目标文件；指向**仓外**共享文件（如 `~/.agents/AGENTS.md`）时**停手报告，不写**。
  - 目标文件末行无换行（`tail -c1`）时先补换行并留空行，防止新标题被吞进上一行。
- **目标文件判定**（指针本体只写 `AGENTS.md`，双工具共用单源）：
  - 无 `AGENTS.md` 无 `CLAUDE.md` → 新建 `AGENTS.md`，不建 `CLAUDE.md`。
  - 无 `AGENTS.md` 有 `CLAUDE.md` → 新建 `AGENTS.md` + 在 `CLAUDE.md` 补独立一行 `@AGENTS.md`。
  - 有 `AGENTS.md` 无 `CLAUDE.md` → 仅向 `AGENTS.md` 追加指针节。
  - 两者皆有 → 向 `AGENTS.md` 追加指针节 + 核 `CLAUDE.md` 存在有效 `@AGENTS.md` 行（必须单独一行、不在反引号或代码块内，锚定匹配 `^@AGENTS.md$`）。
- **幂等与旧副本检测**：
  - 已有指针节判定须**同时**命中「spec-flow」与「唯一真相源 / 不复述 / 不放副本」语义；已存在则只校验形制，过期才就地更新。
  - **旧副本检测**：按是否含流程全文特征句（如 `name: spec-flow`、流程步骤表、审核档位表等）或大段复述步骤判定，**不用行数相似度阈值**（过期副本常与新版行数差很大）；命中一律报告交用户定夺，不自动删除或改写。
- **显式升级（「更新本项目的 spec-flow 接入」）**：
  - 仅在用户明确要求升级时执行，重复执行幂等；只校验并补齐本次获准的缺项，**不借升级自动启用未采用选修，也不恢复已停用的代码地图**。
  - 已采用 `adr` 同步核检索 / 写入 / 只链不抄 / 收尾四项动作；已采用 `doc-lifecycle` 同步旧读序并实核「实施前必读当前获批施工 spec」落点；项目自有明确条款与中央冲突时报告来源并停受影响部分，不宣布中央自动覆盖项目。
- **普通任务零补写与 ADR 断链保护**：
  - 普通任务缺入口或工具查询需未授权写入时，只报告并回落源码，对项目指令、配置与共享 Git 元数据**零补写**。
  - **已采用 ADR 断链**：只读找回并遵守现行 ADR，**不静默改成未采用**；持久修复交显式升级。

### 核心指针块模板（写入 `AGENTS.md`，按实际路径替换）

```markdown
## 流程规矩：来自 spec-flow

本仓复杂任务按 spec-flow 执行；规则唯一真相源在中央真身，**本文件不复述正文、不放副本、不做同步机制**。

- 使用 spec-flow 时读取：<本次核实的中央入口路径或远端 SKILL.md 链接>
- 认领既有 issue 实施同样从 spec-flow 交付段进入；改中央规矩去改真身并提交。
- 项目自有入口与已采用选修不会因中央改动自动改写；需补齐时显式要求更新接入。
```

## 三、5 个选修模块（默认全部关闭）

所有选修支持两种模式：**本次按需读取**（不写项目规则）与**项目级持久采用**（写 `AGENTS.md` 短入口与允许的非可执行资产）。未知修饰词当场问用户，不猜测。

**项目持久入口最低 6 项要求**：① 已采用哪个模块；② 中央唯一正文链接；③ 本仓本地落点；④ 后续任务动作指令；⑤ 本仓差异或验收命令；⑥ 「不复制正文、不建第二真相源」边界。

| 修饰词 | `AGENTS.md` 入口标题 | 默认项目资产 | 执行时点 | 唯一正文 |
|---|---|---|---|---|
| `adr` | `## 已启用：决策记录（ADR）` | `docs/decisions/README.md`（若无自带制度） | 开工检索；拍板长期决定时写入；spec 只链不抄；收尾核本次 | [adr.md](../30-playbooks/adr.md) |
| `doc-lifecycle` | `## 已采用：文档生命周期备忘录` | 无（不新建规则页） | 先核现状文档与现行 ADR；实施前必读获批 spec | [15-records.md](../15-records.md) §四 |
| `issue-status` | `## 已采用：issue 状态标签` | 8 个状态 / 卡点标签 | 开发、验收、合入、上线分拣、关单与盘点 | [labels.md](../30-playbooks/labels.md) §一 |
| `issue-type` | `## 已采用：issue 类型标签` | 8 个类型标签（含授权迁移与 open 回填） | 新建 issue 挂类型；首次采用迁移旧标与回填 open | [labels.md](../30-playbooks/labels.md) §二 |
| `release` | `## 已采用：发布纪律` | 发布记录（项目现有位置）；不建分支 / tag / 脚本 | 开分支、形成候选、发布前对齐、发布后回填与应急 | [release.md](../30-playbooks/release.md) |

### 1. `adr` 与 `doc-lifecycle` 采纳动作与最小模板

- **`adr`**：先查项目是否已自带 ADR 目录 / 规则页；自带则直接复用路径与命名，不建第二套。无自带制度时新建 `docs/decisions/README.md`（只留「启用声明 + 载体分工表 + 命名默认 `ADR-YYYYMMDD-<slug>` + 指向中央 `adr.md` 链接」，不抄细则），并写 `AGENTS.md` 短入口。
- **`doc-lifecycle`**：先确认现状文档路径（无则问用户，不代挑）与已有文档规则页；不新建规则页。若同项目已启用 ADR，向其规则页载体表补一行「现状文档（唯一正文）」。

```markdown
## 已启用：决策记录（ADR）
本仓已启用 ADR（<日期> 拍板），唯一规则页：`<规则页路径>`，完整口径见中央 `references/30-playbooks/adr.md`（本文件不复述）。
- 开工先按业务词 / 表名 / 接口名检索现行 ADR；拍板命中长期影响条件即新增或取代（旧 ADR 正文不改）；spec 只链不抄；收尾核引用现行与取代两端一致。

## 已采用：文档生命周期备忘录
本仓已采用文档生命周期口径（<日期> 拍板），完整口径见中央 `references/15-records.md` §四（本文件不复述）。
- 现状文档（唯一正文）：`<路径>`；默认读序：先核现状文档与生效 ADR，实施前必读当前获批施工 spec 与验收，历史记录按需读；历史与实测冲突时以后者为准且不据此取消获批目标或改现行 ADR。
```

### 2. `issue-status` 与 `issue-type` 采纳命令与防冲突保护

- **授权边界**：用户说「应用 `issue-status`」仅授权新建缺失标签；**改 / 删已有标签或给已有 issue 挂标签不在本次授权内，须另问**。先 `gh label list --limit 200`，同名已存在不覆盖颜色与描述，只报差异。
- **老项目 `待验收` 防重名规则**：若 2026-10-06 前接入的项目存在旧名 `待验收`，**建标签时必须跳过新建 `待验证`**（否则后续改名会重名失败）；向用户报告并经点头后执行 `gh label edit "待验收" --name "待验证" --description "阶段：已上线，剩现在能由我方主动去正式环境验的项，或方案期批准的长尾项；正文首行写下次看"`，再按 `labels.md` 上线分拣重分原挂单。

```bash
# issue-status（8 个标签；同名跳过，有「待验收」时跳过「待验证」）
gh label create "未开始" --color EDEDED --description "阶段：开了单还没动手（含挂账、待复现、待评估）"
gh label create "进行中" --color 1D76DB --description "阶段：已认领，改动还没合进 issue 分支"
gh label create "待测试" --color 5319E7 --description "阶段：开发完成，预期交付已合入 issue 分支，等分支验收"
gh label create "测试完成" --color 006B75 --description "阶段：issue 分支验收通过，等整条合入 staging"
gh label create "待上线" --color 0E8A16 --description "阶段：整条已合入 staging（不可逆），批次失败切 fix 修"
gh label create "待验证" --color C2E0C6 --description "阶段：已上线，剩现在能由我方主动去正式环境验的项，或方案期批准的长尾项；正文首行写下次看"
gh label create "等拍板" --color D93F0B --description "卡点：等 owner 做决定，拍完摘掉"
gh label create "受阻"   --color B60205 --description "卡点：等外部条件；正文首行写下次看"

# issue-type（8 个类型标签；先统计旧标并按 labels.md §二 获准迁移后再建缺项，只回填 open 单）
gh label create feat --color 1D76DB --description "类型：新功能或能力变更"
gh label create bug --color D73A4A --description "类型：行为不符合预期（含线上故障、回归）"
gh label create docs --color 0075CA --description "类型：文档、spec、README"
gh label create refactor --color 6F42C1 --description "类型：不改外部行为的代码重构"
gh label create perf --color FBCA04 --description "类型：性能优化，需有可对比指标"
gh label create test --color 0E8A16 --description "类型：测试、用例、测试基建"
gh label create chore --color BFD4F2 --description "类型：依赖、构建、CI、配置、杂务"
gh label create security --color B60205 --description "类型：安全整改或漏洞，可叠加在 bug/feat 上"
```

```markdown
## 已采用：issue 状态标签
本仓已采用状态标签（<日期> 拍板），完整口径见中央 `references/30-playbooks/labels.md` §一（本文件不复述）。
- 测试环境：<有 / 无，无则记本地或 CI 替代>；「待上线」「待验证」「关单」须用户确认；完成判据读 `references/10-stages.md`。

## 已采用：issue 类型标签
本仓已采用类型标签（<日期> 拍板），完整口径见中央 `references/30-playbooks/labels.md` §二（本文件不复述）。
- 新建 issue 挂 1 个主类型（`security` 可叠加在 `bug`/`feat`）；本仓差异 / 验收：`gh label list` 含 8 类，历史只回填 open。
```

### 3. `release` 与代码地图边界

- **`release`**：先只读核长期分支、发布约定与 `issue-status` 前提（缺项只报不顺便启用）；由用户选定形态（单主线 / 三层 / staging 线）与真实分支映射，仅写入 `AGENTS.md` 短入口，不自动创建分支、tag、开关或发布脚本：

```markdown
## 已采用：发布纪律
本仓已采用发布纪律（<日期> 拍板），唯一正文见中央 `references/30-playbooks/release.md`（不复制）。
- 已选形态：<单主线 / 三层 / staging 线>；分支映射：<实际分支名>；发布记录落点：<路径或 issue 约定>；差异与验收：<命令或无>。
```

- **代码地图**：默认停用；普通应用 / 升级不探测也不配置。用户仅要求当次试用时**不写长期启用声明**；配置请求**不含本机工具安装许可**；持久恢复须先交叉核对分母、扫描范围与写入授权后再登记入口，不因工具已安装推定恢复。

## 四、默认资产边界与可执行资产升级闸

- **默认资产**：仅限文档入口与上表「默认项目资产」列出的非可执行资产。脚本、CI、Hook、Workflow、生成器、机器人（**可执行资产**）绝不随采纳自动创建。
- **可执行资产升级闸**：确需新增可执行资产时停在「材料备好」，列齐 5 项——`路径与类型`、`解决的问题`、`触发方式`、`维护成本`、`Markdown-only 替代方案`——经用户明确同意后才建；授权仅覆盖当次列明路径，不外推。
  - **用户拒绝回落**：回落 Markdown-only，在项目入口写明人工执行部分，并在报告写明「未加脚本，因此没有机械拦截」。
- **收尾报告**：分别报告规则入口、工具、配置、跳过项、旧物与本次验证末态，不以「已启用」冒充全部就绪；验收演练只在假仓进行，不污染真实采用项目。
