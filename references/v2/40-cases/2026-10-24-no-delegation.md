# Case: 2026-10-24 未获实施委托就开工

- **来源**：v1 rationale R29；用户报告的 dsh-tui-nano 会话（未独立复核）

- **情况**：dsh-tui-nano 的一次会话里，spec PR 已合并、执行 issue 已创建；随后没有新的人工实施指令，agent 认领了 issue 并修改代码。
- **预期**：方案交付后停下，等用户另行发起实施。
- **实际**：agent 自行继续。仓内没有独立会话记录；这是用户报告，未作独立复核，仓名只作一次性的证据。
- **意外**：交接报告之后没有一个物化的「停」状态；「spec 已合并 / issue 已建 / 锁空着」被当成了可以开工。
- **学到什么**：方案完成 → 交接 → 停；实施授权绑定 issue。定向入口是「请做 #N」这类明确绑定；同窗口入口只在交接报告是最后一条 agent 消息、用户开始意图紧接、恰好一张未授权执行单时成立，且开始意图属于闭集「开始实施 / 开始干 / 开工」。中间有问答、工具结果、压缩、新窗口或多执行单时，同窗口入口不成立，只有点名 `#N` 才构成定向委托；授权记录写在认领之前。

- **用户是否批准偏离**：否。没有新的实施委托。
