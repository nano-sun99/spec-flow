# Case: 2026-09-11 判据只改一句

- **来源**：v1 rationale R1（`references/rationale.md`）；反爬专项实例；2026-11 #1195 / #190 复发

- **情况**：反爬专项要把 IDC 判据从「CIDR 段」扩成「CIDR ∪ ASN」。2026-11 的 #1195 连续 30+ 轮闭合不了，反复出现同一模式：改口径时只追加新句，旧作废口径留在正文里，同一决定出现两份冲突正文。
- **预期**：改判据那一句就完成这次变更。
- **实际**：只改了判据那一句；机制、实现、实施步骤、验收四处仍是旧口径，父文档总纲 §0 也没改。照当时的 spec 施工会做成 CIDR-only。#190 想加一条「必须删旧句 + 反向扫描 0 残留」抬成 L1 完成条件，但在 5 个文件各加一句，没有旧→新台账，也没扫反向冲突；结果与「拍板记录只追加不篡改」「已合并 spec 不改正文」「旧 ID 留作别名」同时生效。
- **意外**：独立审核抓出 2 处严重；问题不在判据本身，而在它散落在多个落点。
- **学到什么**：判据不是孤立句子。规则正文、实现 / 数据源、工作与验收、父文档和引用锚点，都会各自留着一份旧口径；只改眼前一句，等于留下几份互相矛盾的真相。反向冲突的反话常用旧词汇写（「只追加不篡改」「不改正文」「不重写获批正文」「默认不动冻结正文」「留作历史别名」）；只 grep 新词，必然 0 命中。正确做法是旧→新台账 + 双扫描（活跃残留 + 反向冲突）+ 载体分流；「0 残留」改为「0 活跃引用 + 白名单」。
- **影响提议**：已落为 v2 [change-protocol](../30-playbooks/change-protocol.md)：v2 规则变更按台账 / 双扫描 / 载体分流；L1 完成条件引用它，不新增闸。L0-8 的「新增必须替换或合并一条」保持铁律层不变。
- **用户是否批准偏离**：不适用。
- **被哪条规则覆盖 / superseded_by**：覆盖于 `30-playbooks/change-protocol.md`、`10-stages.md` 设计段与交付段；superseded_by：无。
