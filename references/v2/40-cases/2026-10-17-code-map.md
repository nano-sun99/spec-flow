# Case: 2026-10-17 代码地图自报完整仍漏引用

- **情况**：在真实 Java / TS / Go 多项目仓试用 codemap 4.6.0；另在临时假仓复现五个样例。
- **预期**：工具自报 `complete` 就可以作为影响分析依据。
- **实际**：三个 TS 样本从整仓根只找到 24 / 2 / 1 个引用，换到所属子项目根找到 87 / 54 / 26 个，与 TypeScript 编译器解析的文件集合一致；Go 工具包从 0 恢复到 8；Java 样本源码有 3 个引用，换根后仍为 0。真实 diff 的 3 个 Go 变更文件虽被列出，影响列表却为 0，而源码存在调用方。假仓里 TS 目标有 3 个调用方，整仓根与子项目根都只找到 2 个，且两份结果数量相同、文件集合不同，都报 `complete`。
- **意外**：当日官方最新稳定版与 main 相同，没有待合并修复；Java 符号关系未建模写在固定版本源码里；换子项目根只是局部补救，不是整仓影响分析已可靠。
- **学到什么**：工具自报不是证据。结构图、导入方、影响查询各有独立的可信边界，不能互相担保；抽查一致不证明全仓覆盖；未验证的结论回落到源码、真实 diff 与相关测试。试用结论由用户决定去留。
- **影响提议**：无。已进 L0-3 证据口径与 [review playbook](../30-playbooks/review.md) 派发材料要求。
- **用户是否批准偏离**：是。用户了解风险与补救办法后要求停用默认代码地图。
- **被哪条规则覆盖 / superseded_by**：覆盖于 L0-3「证据先于结论」；superseded_by：无（默认查图已停用，验证经验留档）。
