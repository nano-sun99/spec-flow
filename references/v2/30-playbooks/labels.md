# Playbook: 标签（阶段 / 类型）

> **示例非必须**：本页的走法是一条走通过的路，不是必须顺序；按实际情况调整。
> **规范性**：只有标「（规范性）」的章节；它们引用 L0-L2，不新增、不放宽闸口。

- **适用**：项目已采用 `issue-status` 或 `issue-type`；需要回答「每个 issue 卡在哪、下一步谁动」或给 issue 分类。
- **一条走通过的路**：读事实 → 提议标签与证据 → 用户确认（仅三个标签必须）→ 换标签 → 盘点。
- **失败模式**：把标签当状态机；合并即关单；用自动关单关键词；批量改标签不给用户过目；回填 closed 单。
- **证据**：当前标签、事实与证据、用户确认记录（[15-records](../15-records.md) 第 10 类）。
- **注意**：这是示例，不是必须顺序；闸口相关章节是规范性的，不能自行放宽；改动闸口证据须用户批准。

## 阶段标签与视图（示例非必须）

阶段标签：未开始 → 进行中 → 待测试 → 测试完成 → 待上线 → 待验证 → 关单。卡点标签：等拍板、受阻，可叠加在任何阶段上。

| 标签 | 事实 | 下一步谁动 |
|---|---|---|
| 未开始 | 开了单还没动手 | 谁认领谁动 |
| 进行中 | 已认领，改动还没合进 issue 分支 | 做的人 |
| 待测试 | 预期交付都有对应 PR 且已合入 issue 分支，构建通过 | 做的人（按验收路径验） |
| 测试完成 | issue 分支按 spec 验收路径测试通过，证据已回填 | 做的人或合并者 |
| 待上线 | 整条 issue 已合入候选（staging 线） | owner 同意后跟班车发版 |
| 待验证 | 已上线，剩现在能由我方主动去正式环境验的项，或方案期批准的长尾项 | 做的人 |
| 等拍板 | 卡在 owner 做决定 | 拍完就摘 |
| 受阻 | 卡在外部条件 | 条件满足就摘 |

- **「下次看」行**：`⏰ 下次看：YYYY-MM-DD · 看什么`，放 issue 正文第一行；「待验证」「受阻」必填，其余有明确日期的选填。
- **上线时分拣**：对每条未勾验收项问一句「这条现在能不能由我们自己动手验？」能 → 留「待验证」；不能但方案期批准过 → 留「待验证」到批准结束日；不能且未批准 → 转出，不勾、不挡关单，当场评论核对时机。
- **盘点**：用户说「盘一下 issue」时只读执行；输出顺序为到期 → 等拍板 → 按阶段分组；可疑清单：没挂阶段标签、同时挂多个、待验证 / 受阻缺「下次看」、日期解析不了、同阶段 14 天无更新。盘点只报不改；批量改标签先给 owner 过目。

## 类型标签（示例非必须）

8 类裸名小写：`feat` / `bug` / `docs` / `refactor` / `perf` / `test` / `chore` / `security`。一单一个类型；`security` 可叠加在 `bug` / `feat` 上。类型不是阶段、不是范围、不是优先级；类型不清先问，不猜。

迁移：`enhancement` → `feat`、`documentation` → `docs`、`type:*` → 裸名（`type:fix` → `bug`）；机械迁移覆盖 open + closed；语义回填只做 open，closed 不补；同名已存在不覆盖颜色 / 描述，删旧标签前给用户看清单。

## 失败模式（示例非必须）

- 标签被当成流程状态机；标签与交接区正文冲突时，agent 自行选一个继续。
- 合并即转「待验证」、合并即关单；上线后的分拣被跳过。
- PR 正文写了 `Closes` / `Fixes` / `Resolves`；合并瞬间自动关单，回填与分拣全部跳过。
- 盘点顺手批量改标签；改远端是对外可见动作，用户没过目。
- 回填把 closed 单也补类型；历史分类被改写。
- 类型不清时猜一个；一个单同时挂 `feat` + `bug`。

## 证据（示例非必须）

| 时点 | 证据 |
|---|---|
| 每次换标签 | 当前标签、事实与证据、用户确认记录（三标签必须有） |
| 上线分拣 | 未勾验收项的逐条处置；转出评论；「下次看」行 |
| 盘点 | 只读查询输出；可疑清单；批量修改前的用户确认 |
| 类型迁移 | 旧标签 / 挂单数、改名或合并清单、用户过目记录、回填统计 |

## 闸口（规范性）

- **标签是视图，不是状态机**：标签与交接区正文状态冲突时停下报告，不自行选一个继续（[20-decisions](../20-decisions.md) 标签规则）。
- **必须用户确认**：「待上线」「待验证」「关单」三类标签转换必须用户确认；其余标签无歧义时 agent 可换并报告，有歧义时问。
- **PR 关联**：只用「关联 issue：#N」；不写 Closes / Fixes / Resolves 等自动关单关键词（[15-records](../15-records.md) 第 3 类补充记录）。
- **完成判据不在本页**：完成与关单按 [10-stages](../10-stages.md) 与 [15-records](../15-records.md) §五；标签不证明完成。
- **不自动迁移老单**：语义重叠的旧标签只报告；要迁老单另开 issue，清单先给 owner 过目。
- **不改 adopt 行为**：采用方式与项目资产按项目已采用的模块；本页不维护采用名单。
- **不新增闸**：本页不新增决定类型或完成条件；与 L0-L2 冲突时以 L0-L2 为准。
