# Playbook: main 分叉 / 生产分支快照

> **示例非必须**：本页的走法是一条走通过的路，不是必须顺序；按实际情况调整。
> **规范性**：只有标「（规范性）」的章节；它们引用 L0-L2，不新增、不放宽闸口。

- **适用**：生产验证通过后，生产分支需要与成功 tag 同树；或生产分支已分叉，需要在不改写历史的前提下留下快照。
- **一条走通过的路**：核生产分支与 tag → 能快进则快进；分叉则用快照提交 → 核 `diff --quiet` = 0 → 回填。
- **失败模式**：merge / reset / read-tree 覆盖生产快照；移动共享主仓已检出分支；快照提交丢 tag 父提交；快照后不核 diff；把 tag 当所有服务实时同版。
- **证据**：生产分支完整提交、快照提交、`git diff --quiet <tag> origin/<prod>` 输出、tag 类型与父提交。
- **注意**：这是示例，不是必须顺序；闸口相关章节是规范性的，不能自行放宽；改动闸口证据须用户批准。

## 一条走通过的路（示例非必须）

1. **核事实**：`git fetch origin --tags`；确认成功 tag 的完整提交与生产分支当前提交；确认 tag 是附注 tag（`git tag -a`），否则可达性与 `git describe` 可能不成立。
2. **单主线且可快进**：把生产分支快进到最终 tag 的同一提交。
3. **分叉时用快照提交**：以 tag 的树为内容、以原生产分支 HEAD 与 tag 提交为父，创建快照提交并 push 到生产分支；不移动、不删除 tag。
4. **核一致性**：`git fetch` 后 `git diff --quiet <tag> origin/<prod>` = 0；不一致就停，不宣布成功。
5. **不碰共享引用**：不用 `git update-ref` 移动共享主仓里已检出的分支；不直改另一个 worktree 的引用；不在共享主仓切分支或做快照。
6. **回填**：快照提交、diff 结果写进发布记录；快照之后产生的结果 / 台账进开发线，不倒灌固定 tag。

## 失败模式（示例非必须）

- 用 merge 把 tag 合进生产分支；生产分支的树包含 tag 之外的提交。
- 用 reset / read-tree 硬覆盖生产快照；历史被改写，来源断掉。
- 快照提交不保留 tag 父提交；可达性 / `git describe` 断掉。
- 快照后只看「push 成功」，不核 `diff --quiet` = 0。
- 在共享主仓移动已检出分支引用；别的工作区被污染。
- 把 tag 当成「所有服务此刻在线同版」；发布记录不区分部署单元。

## 证据（示例非必须）

| 时点 | 证据 |
|---|---|
| 快照前 | tag 完整提交、tag 类型、生产分支当前提交 |
| 快照 | 快照提交及其父提交、push 结果 |
| 快照后 | `git diff --quiet <tag> origin/<prod>` 退出码 0；发布记录回填 |
| 后续 | 开发线前进方向、快照之后的结果去向 |

## 闸口（规范性）

- **L0-1**：覆盖生产分支快照、移动 / 删除 tag、保护分支直推都必须用户明确确认；拿不准按不可逆处理。
- **发布安全不变式**（[10-stages](../10-stages.md) §三）：只从不可变 tag 构建；三层 / staging 的生产分支树等于最近成功生产 tag 的树；不用 merge / reset / read-tree 覆盖；tag 不移动 / 不删除；不在共享主仓切分支或做快照；不直改另一个 worktree 已检出的引用。
- **单主线例外**：单主线不要求主线树等于旧 tag，只要求 tag 不可变、构建自 tag；快照仍不得改写历史。
- **不新增闸**：本页不新增决定类型或完成条件；与 L0-L2 冲突时以 L0-L2 为准。
