# Playbook: 发布（批次 → rc → 生产）

> **示例非必须**：本页的走法是一条走通过的路，不是必须顺序；按实际情况调整。
> **规范性**：只有标「（规范性）」的章节；它们引用 L0-L2，不新增、不放宽闸口。

- **适用**：项目已采用 release（单主线 / 三层 / staging 线），要把候选变成可复现的生产版本。未采用 release 的项目本段跳过，不因此补 tag、分支或部署。
- **一条走通过的路**：定批次范围 → 批次测试 → rc 附注 tag → 从 rc tag 验收 → D6 批准 → 同一提交打最终 tag → 从 tag 构建部署 → 监控 15 分钟 → 生产分支快照 → 回填。
- **失败模式**：从 HEAD 构建；rc 后不重跑批次；rc 与最终 tag 不在同一提交；未知搭车项静默放行；把 tag 当已部署 / 已验证；移动或删除 tag；未获批就打 tag / 部署。
- **证据**：批次记录、rc tag、最终 tag、构建产物、部署单元、监控结果、生产分支 diff=0、发布记录。
- **注意**：这是示例，不是必须顺序；闸口相关章节是规范性的，不能自行放宽；改动闸口证据须用户批准。

## 一条走通过的路（示例非必须）

1. **读项目映射**：确认当前形态与实际分支名、版本规则、发布手册、监控办法；不套本页示例分支名。
2. **定批次范围**：范围 = 上一个实际生产 tag（含 hotfix tag）..当前候选；按 PR 正文「关联 issue：#N」归位；未知来源 / 搭车项显式纳入或移出并记录；已通过 hotfix 上线的提交排除。
3. **批次测试**：在当前候选 HEAD 构建、部署测试环境，跑回归和跨 issue 验收；候选有新合入即失效，打最终 tag 前重跑。
4. **rc 附注 tag**：批次通过后，在已测提交打 rc 附注 tag（如 `-rc.1`）。
5. **rc 验收**：从 rc tag 构建、部署测试环境跑验收；rc 不做 15 分钟监控。
6. **D6 发布批准**：卡列批次范围、排除项、未知搭车项处置、必要依赖、四类结论、rc tag、最终 tag（同一提交）、产物 / 部署单元、验证、回滚目标；用户批准后才继续。
7. **最终 tag 与部署**：在同一提交打附注最终 tag；只从该 tag 构建并部署生产；按项目手册执行生产步骤。
8. **生产监控**：部署后启动 Monitor 15 分钟（项目另有规定的按手册）；崩溃或异常 HALT，停住上报，不自动回滚（L0-4）。
9. **生产分支快照**：按 [main-snapshot playbook](main-snapshot.md) 让生产分支的树等于成功 tag 的树；回填发布记录与标签。

## 失败模式（示例非必须）

- 从任何 HEAD 构建而不是不可变 tag；同一 tag 名在不同时间构建出不同产物。
- rc tag 后不再跑批次测试；最终 tag 基于的候选已经前进了。
- rc 与最终 tag 指向不同提交；事后说不清 rc 验收的是不是这一版。
- 范围里的未知 / 搭车提交静默放行；发布记录看不到它们。
- `待上线` 只是一个标签，没有通过的测试结果或验收评论，就被当成「可以发」。
- 发布卡上写着「tag 已打、已合入候选、快照成功」，但没有生产验证。
- 打错 tag 后移动或删除它；旧基线被悄悄改写。
- 生产监控崩溃后自动回滚，把失败改写成通过。

## 证据（示例非必须）

| 时点 | 证据 |
|---|---|
| 批次测试 | 通过的候选完整提交、构建与部署记录、回归与跨 issue 验收结果 |
| rc | rc 附注 tag、从 tag 构建的记录、测试环境验收结果 |
| 发布前 | D6 卡：范围、排除项、未知项处置、依赖、四类结论、rc / 最终 tag、产物、部署单元、验证、回滚目标 |
| 发布后 | 最终 tag、构建产物摘要、部署单元与时间、15 分钟监控结果、生产分支 `git diff --quiet <tag> origin/<prod>` = 0 |
| 回填 | 发布记录更新、hotfix / 失败处置、待验证 / 转出项、关单结论 |

## 闸口（规范性）

- **D6 生产发布**：触发、证据、选项与默认以 [20-decisions](../20-decisions.md) D6 为准；候选有新合入、批次测试失效未重跑、rc 与最终 tag 不同提交、范围或回滚目标变化时批准失效。
- **L0-1 不可逆动作**：发布、回滚、移动 / 删除 tag、从非 tag 构建、覆盖生产分支快照都必须用户明确确认；拿不准按不可逆处理。
- **发布安全不变式**（[10-stages](../10-stages.md) §三）：只从不可变 tag 构建；生产分支的树等于最近成功生产 tag 的树；不用 merge / reset / read-tree 覆盖生产快照；tag 不移动 / 不删除；不在共享主仓切分支或做快照；保护分支直推不在普通授权范围。
- **批次测试与 rc 验收**：定义以 [10-stages](../10-stages.md) 术语为准；最终 tag 的提交必须是最近一次通过的批次测试所基于的候选 HEAD。
- **失败停住**：生产监控崩溃或异常按 L0-4 停住上报；回滚走 D7，不自动发生。
- **关单与标签**：按 [15-records](../15-records.md) 与 [labels playbook](labels.md)；「待验证」「关单」必须用户确认。
- **不新增闸**：本页不新增审核档位、决策类型或完成条件；与 L0-L2 冲突时以 L0-L2 为准。未采用 release 的项目不因本页产生分支 / tag / 发布记录义务。
