# Playbook: 批次测试失败 → fix

> **示例非必须**：本页的走法是一条走通过的路，不是必须顺序；按实际情况调整。
> **规范性**：只有标「（规范性）」的章节；它们引用 L0-L2，不新增、不放宽闸口。

- **适用**：staging 线；整批候选在批次测试中失败，需要定位归属并在候选上修复后重跑。
- **一条走通过的路**：停住记录 → 定位归属 → 切 `fix/<N>-<slug>` → 最小修复 → D4 合回候选 → 标签不回退 → 重跑批次。
- **失败模式**：回退标签；把失败改写成通过；在已冻结的 issue 分支上修；静默重试；新合入后不重跑批次。
- **证据**：失败记录（输入 / 预期 / 实际 / 证据 / 结论 / 范围）、归属判定、修复提交、D4 合并、重跑结果。
- **注意**：这是示例，不是必须顺序；闸口相关章节是规范性的，不能自行放宽；改动闸口证据须用户批准。

## 一条走通过的路（示例非必须）

1. **停住记录**：失败即停；按 [15-records](../15-records.md) 原任务字段记输入、预期、实际、证据、结论、验证范围；不猜、不改写。
2. **定位归属**：判断失败属于本 issue、别的 issue、环境，还是多个改动的组合；用真实日志 / 构建 / 验收证据，不靠印象。
3. **切修复分支**：staging 线从当前候选切 `fix/<N>-<slug>`；直接干任务切 `fix/<slug>`；不回已冻结的 issue 分支。
4. **最小修复**：只修失败点；修复提交按 D4 走审核 / 修订 / 合并，合回候选。
5. **标签**：「待上线」不回退（该标签转换仍需用户确认）；失败结论写进记录。
6. **重跑批次**：批次测试在当前候选 HEAD 重新跑；任何新合入使之前的批次结果失效，打 tag 前重跑。
7. **回填**：发布记录记失败原因、修复、重跑结果；必要时调整本批范围或排除项（D6 重新批准）。

## 失败模式（示例非必须）

- 批次失败就把「待上线」退回「测试完成」；下一步该谁动又说不清。
- 把失败记录改写成「环境问题」了事；没有归属证据。
- 在已冻结的 issue 分支上继续改；整条合入时的 merge commit 与测试对象不一致。
- 静默重试或自动回滚；失败次数和原因没有留下。
- 修复合入后没重跑批次；最终 tag 基于的候选与通过记录不是同一个。
- 修复夹带新功能；批次范围悄悄变大。

## 证据（示例非必须）

| 时点 | 证据 |
|---|---|
| 失败 | 批次提交、失败输出 / 日志、影响范围、初步归属 |
| 修复 | `fix` 分支、修复提交、D4 审核与合并确认 |
| 重跑 | 候选完整提交、重跑构建与验收结果 |
| 回填 | 发布记录中的失败 / 修复 / 重跑条目；范围调整记录 |

## 闸口（规范性）

- **D4 每份 PR**：修复 PR 同样两个时点，触发、证据、选项与默认以 [20-decisions](../20-decisions.md) D4 为准。
- **D6 重新批准**：修复导致范围、排除项或回滚目标变化时，原 D6 批准失效，重新摆卡。
- **L0-4**：失败停住上报；不自动回滚、不静默重试、不把失败改写成通过。
- **批次测试定义**：以 [10-stages](../10-stages.md) 术语为准；候选有新合入即失效。
- **标签**：按 [labels playbook](labels.md)；「待上线」不可逆指不回退标签，不等于批次一定通过。
- **不新增闸**：本页不新增决定类型或完成条件；与 L0-L2 冲突时以 L0-L2 为准。
