# Playbook: ADR（决策记录）

> **示例非必须**：本页的走法是一条走通过的路，不是必须顺序；按实际情况调整。
> **规范性**：只有标「（规范性）」的章节；它们引用 L0-L2，不新增、不放宽闸口。

- **适用**：项目已采用 ADR（决策记录）模块；需要查现行长期决定、记录用户明确拍板的长期决定、或处理取代关系。默认关闭，不因项目复杂自动启用。
- **一条走通过的路**：开工先检索现行 ADR → 命中就按约束做 → 用户明确拍板且命中长期影响条件时新增 / 取代 → spec 只链不抄 → 收尾核本次。
- **失败模式**：自动启用；启用前反复推销；每个选择都写 ADR；静默改写已取代 ADR 正文；知道命中才搜索；一次请求偷换成永久制度。
- **证据**：命中 ADR 与取代链、用户原话与可核日期、spec 中的沿用 / 新增 / 取代 / 无、收尾核对记录。
- **注意**：这是示例，不是必须顺序；闸口相关章节是规范性的，不能自行放宽；改动闸口证据须用户批准。

## 三种使用状态（示例非必须）

| 状态 | 怎么判定 | agent 怎么做 |
|---|---|---|
| 未启用（默认） | 用户没提，项目规则也没声明 | 不创建 ADR，不加步骤 / 字段 / 检查，不追问是否启用 |
| 本次一次性 | 项目未采用，用户明确说「这次写一条 ADR」 | 只写本次记录，从当前 spec 链过去；不升格成项目制度 |
| 项目级采用 | 用户明确要求项目启用，或项目规则已声明 | 按项目已有规则页、目录、命名、状态和语义字段执行 |

## 一条走通过的路（示例非必须）

1. **开工先检索**：需求调查、从旧 issue 进入实施、免方案期任务首次实施前，按业务词、表名、接口名、组件名和已知 ID 搜相关现行 ADR；读命中记录及取代关系。不要求通读全部 ADR；不命中留检索词与结论，不把「没找到」说成历史没有决定。
2. **命中就按约束做**：现行 ADR 与 spec 指向同一决定但内容不一致时，停下报告具体来源，交用户裁决；agent 不擅自选一个继续（L0-7）。
3. **什么时候写**：必须先有用户明确拍板；「倾向」「先试试」这类表态先用选择卡确认真实承诺。拍板后命中任一长期影响条件才写：
   - 会影响另一个 issue、spec 或 worktree；
   - 会改变对外接口、数据范围 / 结构、组件边界、安全、部署或长期运行约束；
   - 明确否决了未来很可能再被提出的合理方案；
   - 改变了已有 ADR。
4. **不写的**：可实测的客观事实、局部实现、命名、普通重构、进度、临时排障、尚未拍板的候选方案。
5. **最小格式**：决定、依据、否决了什么、接受的代价、允许重开的条件；稳定 ID、状态、适用范围、取代关系。项目已有体例的随项目。
6. **取代**：新建 ADR 状态「生效中」并链接旧 ADR；旧 ADR 只把状态改为「已被取代」并链接新 ADR，正文不改；两端同一变更；历史 spec / 已完成 issue 不回写。
7. **spec 与 issue**：spec 分清沿用、新增、取代、无及原因，只链不抄；issue 默认只链 spec，一跳可达 ADR（项目明确覆盖时才直链）。
8. **收尾核本次**：引用现行、取代两端一致、已拍板长期决定已落地。

## 失败模式（示例非必须）

- 「这项目很复杂」被当成授权，自动启用 ADR。
- 用户没提时，在每个复杂任务上追问一遍要不要 ADR。
- 用户说「这次写一条」，结果改了项目指令、模板和收尾规则。
- 口头启用但没有项目入口；下个 agent 就丢失。
- 所有选择都写 ADR；局部实现和临时排障淹没真正的长期裁决。
- 默认抄重型项目的全套模板、固定三时点 Gate 和检查脚本。
- 知道命中才搜索；旧 issue 和免方案期都不检索。
- 把倾向当定稿；或明确拍板后还在问要不要记 ADR。

## 证据（示例非必须）

| 时点 | 证据 |
|---|---|
| 开工检索 | 检索词、命中 ADR、取代链、结论 |
| 拍板后写入 | 用户原话与可核时间、命中的长期影响条件、ADR 文件 |
| spec | 沿用 / 新增 / 取代 / 无及原因；只链不抄 |
| 收尾 | 引用现行、取代两端一致、落地位置 |

## 闸口（规范性）

- **只对已采用项目生效**：项目未采用 ADR 时不新增 ADR 前置、字段、目录或检查（[10-stages](../10-stages.md) 设计段完成条件）。不把「文件存在」当成「制度已采用」。
- **用户拍板才写**：ADR 记录的是用户已明确作出的长期决定；不能从代码倒推，不能把演练的模拟批准写成真实业务决定。
- **取代不静默**：旧 ADR 正文不改；状态与取代链接两端一致（[15-records](../15-records.md) §四）。
- **不改 adopt 行为**：采用、入口与项目资产按项目已采用的模块；本页不新增修饰词或采用动作。
- **不新增闸**：本页不新增决定类型或完成条件；与 L0-L2 冲突时以 L0-L2 为准。
