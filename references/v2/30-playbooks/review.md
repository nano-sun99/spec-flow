# Playbook: 审核与修订

> **示例非必须**：本页的走法是一条走通过的路，不是必须顺序；按实际情况调整。
> **规范性**：只有标「（规范性）」的章节；它们引用 L0-L2，不新增、不放宽闸口。

- **适用**：spec 期或实施期，当份 PR / 当批 PR 需要审核、修订与复审；或交付物含文档改动、摆派审卡前需要跑文档检查。
- **一条走通过的路**：文档检查 → 选档位与修订范围（D2 / D4 ①）→ 派发（派审词写明这次回答整案（全文重审）闭合还是只复核上轮；材料见「给材料」）→ 报告（先判处置类型，再列严重度、成因与能不能不修；写清核了什么/没核什么）→ 原样贴评论 → 修订 → 复审（R1-R3）→ 合并卡（D4 ②）。
- **失败模式**：审核完自动全改；把自测 / 自查说成独立审核；沿用规格期档位；把零发现或审核结论当合并同意；每轮新增规则不做范围检查；拆文件/换 agent 重置轮次；把同步失误升级成设计变更；把已拍板决定换个角度当新岔路；把整案重审静默降成上轮复核；报告不写未核范围；把范围盘点表漏项直接改成设计变更；审核范围扩成质量意见；文档检查在派审卡之后才跑；有索引/决定节却先摆岔路，没先推导；推导出的答案没写回，下一轮又问；把实现违反决定当「可推导」关闭；审核方被要求先冻结索引 / 改视图。
- **证据**：审核结论原文、修订记录、文档检查三态、轮次与范围检查、合并卡、D4 记录。
- **注意**：这是示例，不是必须顺序；闸口相关章节是规范性的，不能自行放宽；改动闸口证据须用户批准。

## 一条走通过的路（示例非必须）

1. **摆卡前跑文档检查**：在交付物自己的工作区跑；卡上固定写「文档检查：绿 / 红 + 摘要 / 无入口」。
2. **选档位与修订范围（D2 / D4 ①）**：档位名称、agent 数（成本口径）、选择权与时点引用 [10-stages](../10-stages.md) 术语表与 [20-decisions](../20-decisions.md) D2 / D4；本 playbook 只写派发方法，不重定义选项。成本口径建议：默认仍按 D2 / D4 的「不审」；规格期文档 PR 可建议轻审 1 个，重审才 2 个；规则 / 闸口 PR 可附 #177 / #179 / #180 三场景回放；文件多不自动加人。
3. **派发**：
   - **不审**：不派 agent；主 agent 按 diff 对获批范围与已采用约束自查。
   - **轻审**：1 个。规格期审文档：规格符合性 + 方案 / 自定细节两项；实施期审代码：对抗找 bug + 范围外对账。
   - **重审**：2 个。规格符合性（含适用清单 / 范围）+ 对抗找 bug。
   - **重审 + 变异**：重审 + 主 agent 换错判据并跑全量相关测试；仍全绿说明没护栏。变异不是多派一个 agent；只在独立测试工作区做、恢复变异、不把坏判据带入交付；无可跑测试如实报无法变异。
4. **给材料**：清单与轮次规则见下方闸口的「给材料」；要求逐条核 `file:line` 与「现状是 X」断言，不拿未经实测的假设当事实。审核只读不改文件。
5. **报告格式**：报告开头先输出「已拍板清单」（ID / 来源 / 状态 / 覆盖），再列关闭清单，再列发现；摘要与索引/决定节冲突时先判摘要错，不把摘要当决定依据。每条发现给 `文件:行` / 问题 / 证据（现状 vs 期望）/ 推导链（决定 ID → 条款/验收 → 结论）或「无决定 ID」/ 处置类型 / 严重度（阻断 / 高 / 中低）/ **成因** / **能不能不修** / **依据决定 ID** / **新事实** / **主动改范围**（见下文 #158 五机制与「可复制派审契约」）。`依据决定 ID` 指这条发现违反或关联的决定；`新事实` 指拍板时不存在的可核事实；`主动改范围` 指是否要求改变已批准范围。三栏都写不出时，按 spec bug 处理（按 [15-records](../15-records.md) §四 标「待核」或阻断，补决定 ID 或回对应闸），不当作新决策问用户。处置类型先判——`重复已拍板（引决定 ID 核对后关闭）` / `口径内漏项（补表；D2 确认前补，D2 确认后回 D2，已合并走 D3）` / `口径外新增（回 D1）` / `新事实·仅换实现方法（本轮修）` / `新事实·影响已拍板决定（回 D1/D2/D3，用户定）` / `按现行决定替换旧条款（仅限未合并、无人依赖的草案；索引/决定节足够时替换旧实施条款和相反验收；已被采用/已对外承诺/已生效的长期决定保留取代链并核对引用）` / `需裁决（索引/决定节不足或正文矛盾且无法按现行决定唯一推导；报阻断交用户）` / `实现细节（按原决定推导）`。判定顺序：先问「不修，本期哪个已承诺场景会失败」；索引/决定节足够时先按现行决定替换旧条款和相反验收；只有新事实但只换实现方法时本轮修，影响已拍板决定时回对应闸口由用户定；「引决定 ID 关闭」必须核对正文，正文与 ID 不一致 = 阻断；「实现细节」不得用于已承诺场景失败；索引/决定节不足以判定时不得自行选一边。“已拍板不能覆盖”的待核对项必须写缺哪条决定、为什么推导不出、影响哪个验收，标「待定」；「待定」是记录状态，不是与「需裁决」并列的处置类型，由主 agent 汇总一次问，不逐条问。报告另列关闭清单（每条给决定 ID / 来源 / 推导链 / 结论；关闭项不是发现，但仍须逐条留链）；报告头加关闭项 N 条（引决定 ID 关闭）；写回清单按「可复制派审契约」第 9 条。
6. **结论原样贴 PR 评论**（无 PR 贴对话）：不改写、不删条、不降严重度；可加一行头（日期 · 档位 · agent 数 · 阻断 / 高 / 中低计数）；审核报告头按契约第 8 条（含 lane、整案（全文重审）/仅复核、关闭项与关闭清单）。零发现只贴结果，不摆修订卡；有派生条写回时按第 9 条机械回填并记录。
7. **修订范围（规范性）**：有发现时由用户选 D2 / D4 的修订范围：全改 / 只改阻断 + 高 / 不改 / 砍掉相关路径 / 写明本期不保证。不自动改；选不改且仍有阻断 / 高时不合并。subagent 只读；其余修复由主 agent 按用户选的修订范围执行；第 9 条的派生条写回是机械回填，不占修订范围选项。
8. **甲类只做对账**：判为「甲 · 同步失误」的发现，只跑五问对账，不为此新增规则（见下文）。
9. **复审**：每次复审重新摆当份派审卡；修订同意不授权再派。
10. **合并卡（D4 ②）**：卡列 PR、目标分支、修订后完整提交、验证结果、未处理项；确认后才合并。
11. **收尾**：修订处置追加到规格末尾「审核修订记录」或原任务 PR；不重写获批正文。

## #158 五机制（规范性）

> 来源与完整复盘见案例 `2026-11-07-review-scope-explosion`；五条按总纲 §九 写成运行规则。

1. **审核报告加「成因」列**：每条发现标 `甲 · 同步失误` / `乙 · 设计固有` / `丙 · 岔路没拍`。严重度答「挡不挡合并」，成因答「怎么修」，两者并列。
2. **审核报告加「能不能不修」列**：`必须加规则` / `可砍路径` / `可写明本期不保证` / `不用修（引 ID 关闭）` / `不适用（按处置类型走）`。处置类型另列，不塞进这一列；不是每条洞都必须用新规则补。
3. **修订卡可直接选 D2 / D4 的「砍掉相关路径」「写明本期不保证」**：它们已是 L2 修订范围的选项；仍由用户选。
4. **甲类只许五问对账，不许改设计**：甲类发现只跑下列五问，不为此新增规则——
   - 我引用的每个锚点、文件、章节，真的存在吗？
   - 机制清单里的每一项，正文有对应段落吗？
   - 这条路径的每一步，别处都覆盖了吗？
   - 我声明「已新增 / 已改为」的东西，这个 PR 里真的建了吗？
   - 需要人拍板的事，写进「未定项」了吗？
5. **每轮范围检查 + 每批轮次上限**：每轮后问「本轮新增规则里，有几条是原问题必需？答不出来就是扩了」；每批设轮次上限（默认按 R1-R3 计，见下节），触发上限即停，由用户选**重画 / 砍范围 / 停**。

## 严重度（规范性）

- **阻断**：走不通；必要证据不可执行；同一决定多 owner；承重选择未定；数据 / 安全 / 权限问题。
- **高**：会导致返工或跨份不一致，但本轮可修。
- **中 / 低**：不挡合并，留未处理项。
- 数据 / 安全 / 权限问题不因标中 / 低而降格；扩展建议只作建议，不自动成为新机制；发现须对应具体获批要求、行为、交付或证据，不强求步号。

## 轮次（规范性）

- **R1 全量**：走完整路径，核正常 / 失败 / 证据，以及是否有该走没走的分支。
- **R2 默认只核闭合**：只核上轮发现是否闭合，以及新增的阻断 / 高；新出现的中 / 低只记录。
- **R3 停**：仍有阻断 / 高则停，由用户选重画 / 砍范围 / 停；不派第 4 轮。
- **轮次绑 PR，不绑 agent、文件或切片**：换 agent、换审核角度、拆文件都不重置 R1-R3；R2/R3 默认只核闭合，不重开全文。**例外**：用户明确要求全文/整案重审时，当轮按全量范围执行并记明，仍占当前轮次，不重置 R1-R3；报告标题写「全文重审」或「仅复核」，不静默替换。

## 文档检查（规范性）

- **时点**：交付物为 spec / 纯文档，或代码 diff 含文档改动时，**摆派审卡前**在交付物自己的工作区跑；选「不审」也先跑。免审核闸的机械回填按 D4 默认（不审）处理并记录，不单独摆卡；若含文档改动，文档检查仍按 L1 完成条件执行。
- **入口发现顺序**：项目指令自报且真实存在的入口 → 首个存在的 `scripts/check-docs.sh` → `scripts/check-doc-links.sh` → 无入口。自报路径不存在落下一档；存在但跑不起来 / 崩溃 = 红，不冒充无入口。
- **三态**：绿 / 红 + 摘要 / 无入口；卡上固定写结果。
- **处置**：本次 diff 引入的红必须修复、重跑绿后再摆卡；无关存量红注明数量 / 摘要与不相关依据，不阻本次合并，交用户处置；用户可当场明示一次豁免并记理由。
- **边界**：检查绿 / 标存量 / 豁免都不授权合并；静态绿不证明客户端或生产行为。

## 批次与豁免（规范性）

- **批次审核**：一卡盖一个实施批次时，须列每份 PR / 分支，写「N 份 × 该档 = X 个 agent」，逐份按 [10-stages](../10-stages.md) 术语表的档位 agent 数累计；文档检查逐成员在其工作区跑并列结果。批卡只管审核，**不授权批量合并**。
- **免审核闸**：无新内容的机械编号 / 状态 / 索引 / 验收回填、不进仓的草稿 / PR 底稿免审核闸；归属拿不准时摆卡问，不自判。无 PR 的交付前仍摆审核卡并给 diff。机械回填按 D4 默认（不审）处理并报告，不单独摆卡；若含文档改动，文档检查仍按 L1 完成条件执行。
- **worktree 豁免**：只有用户当场明确说「直接改 / 不开 wt」才成立；这是 [10-stages](../10-stages.md) §三 交付前置写明的用户级例外，须记录理由；agent 不自判、不主动建议；真并行仓的认领锁仍执行。
- **豁免不免合并**：以上任何豁免都不免实际存在 PR 的独立合并确认（L0-5）。

## 修订同步（示例非必须）

改判据、定义、常量或术语时，按语义找间接落点，而不是只改眼前一句：

- 规则 / 原理：同一判定的唯一正文、理由与适用条件。
- 实现 / 数据源：实际键、接口、脚本或产物是否存在，与文字相符。
- 工作与验收：真正做了什么、如何判对错，相关失败路径是否仍成立。
- 跨文档：总纲、共享合同、兄弟规格及引用锚点是否指向当前 owner。
- 历史：旧决定确被取代时保留原内容与来源，以取代说明或链接区分，不批量改成新口径。

表达 / 引用的修正不自动成为新机制；实质改变获批目标 / 范围、冻结决定或外部合同，回 D1 / D2 / D3。

## 失败模式（示例非必须）

- 审完默认全改；经用户卡片确认的只有个别条目。
- 「不审」档被当成免自查；或自测 / 草拟被说成独立审核。
- 实施期沿用了规格期的档位与修订范围。
- 零发现、检查绿、reviewer 说可合并被当成用户同意。
- 每轮都在正确地找洞，但没人问「这条能不能不修」，规则越加越多。
- 甲类同步失误被当成设计缺陷，每条都升级成一次设计变更。
- 拆分后轮次重置，同一个 PR 实际审了六轮而每份文件都像 R1。
- 审核 prompt 写得太狠，反向逼实施方加防御层；范围外对账膨胀成质量意见。
- 文档检查在派审卡之后才跑，卡上「绿」是空白。

## 证据（示例非必须）

| 时点 | 证据 |
|---|---|
| 派审前 | 文档检查三态结果（命令 / 摘要 / 无入口） |
| 派审 | 档位与修订范围选择记录；派审问题（整案（全文重审）/仅复核）；提供的 spec（草稿或获批版本）/ 决定索引或决定节 / 范围盘点表或等价清单 / diff 基准 / 项目入口 / ADR；base/head 完整 SHA |
| 审核后 | 审核结论原文（含处置类型、成因、能不能不修、推导链、关闭清单、写回清单）；轮次记录；核了什么/没核什么 |
| 修订 | 用户选择的修订范围；逐条处置；甲类五问对账结果；派生条写回执行记录 |
| 复审 | 上轮闭合核对、新增阻断 / 高；范围检查 |
| 合并 | D4 ② 合并卡与确认；未处理项 |

## 闸口（规范性）

- **D2 / D4 审核档位与修订范围**：触发、证据、选项与默认以 [20-decisions](../20-decisions.md) D2 / D4 为准；每份、每阶段当场选，不沿用规格期档位。
- **D4 ② 合并**：每份 PR 单独确认；不审、零发现、同意改、已修完、reviewer 说可合并都不等于用户同意（L0-5）。
- **判断权在用户**：agent 不自判核心、不自动派审；项目禁用的档位不展示（等于该档不存在于当次选项）。
- **给材料（规范性）**：至少包含当前 spec（草稿或获批版本；无 spec 时用 PR 正文的目标/范围/验收替代并写不适用及事实理由）、决定索引或决定节（冻结版，含来源 / 状态 / 覆盖图；由主 agent 提供，审核方不代冻结；采用 ADR 时：长期决定索引 + 短期决定节；未采用 ADR 时：spec 决定节；有短期决定但缺决定节 = 阻断；无短期决定写无及理由；无 spec 才用 PR 正文替代）、范围盘点表（或项目已有的等价范围清单）相对本 PR base/head 或上次冻结版本的 diff（无表时写不适用及事实理由）、base/head 完整 SHA、真实工作区 / diff 基准、项目入口、已采用约束、现行 ADR（如适用）。R1 默认给全文；R2/R3 默认只给上轮发现、闭合证据和新增 diff；用户明确要求全文/整案重审时，当轮给全文并按全量执行，仍占当前轮次。
- **报告字段（规范性）**：报告开头先输出「已拍板清单」（ID / 来源 / 状态 / 覆盖），再列关闭清单，再列发现；报告头按契约第 8 条（日期、档位、agent 数、lane（A/B）、整案（全文重审）/仅复核、关闭项 N 条并附关闭清单、阻断 / 高 / 中低计数、核了什么 / 没核了什么）；关闭清单每条给决定 ID / 来源 / 推导链 / 结论，关闭项不是发现但仍须逐条留链；每条发现至少给 `文件:行` / 问题 / 证据（现状 vs 期望）/ 推导链或「无决定 ID」 / 处置类型 / 严重度 / 成因 / 能不能不修 / 依据决定 ID / 新事实 / 主动改范围；写回清单按「可复制派审契约」第 9 条；处置类型见步骤 5 的清单。
- **派审前对齐问题**：派审词写明这次回答「整案（全文重审）是否闭合」还是「上轮修订是否闭合」；任何新的「重审」先确认整案（全文重审）/仅复核，先找上轮约定，找得到就沿用，找不到先问清，不默认缩窄；用户明确要求全文/整案重审时按全量执行。
- **结论覆盖范围**：报告头写核了什么/没核什么；结论只覆盖证据证明的范围，不简称整案通过。
- **只做修订复核时**：先说明全文委托尚未完成，不提前请用户选修订或定稿；报告标题写「仅复核」，不简称整案通过。
- **独立审核边界**：子 agent 是执行分身；自测、草拟和检索不能冒称独立审核。审核分身只做一致性检查与找 bug，不产出新决定；发现与决定索引/决定节冲突，先引 ID 对账；索引/决定节足够且只涉及未合并、无人依赖的草案时，按现行决定替换旧条款和相反验收，不升级成用户选项；已合并 spec 走 D3 新 spec；已被采用/已对外承诺/已生效的长期决定保留取代链并核对引用；索引/决定节不足或无法唯一推导时，报阻断并交用户，不自行选一边。真正要求另一方裁决时，材料备好后停，等用户指定方（L0-2：事实 agent 查，决定用户拍）。
- **不新增闸**：本页不新增审核档位、决定类型或完成条件；与 L0-L2 冲突时以 L0-L2 为准。

## 可复制派审契约（规范性）

给 Lane A（规格符合性 / 决定与范围一致性）审核方或用户自定审核 prompt 的通用契约，可直接粘贴。它只引用 L0-L2，不新增档位、闸口或决定类型；与 L0-L2 冲突时以 L0-L2 为准。Lane B（对抗找 bug）用下方 B 派发说明。

```text
你是本次交付的 Lane A 审核方（规格符合性 / 决定与范围一致性）。只审给出的 diff 与材料，只读不改；修复不由你执行，主 agent 按用户选的修订范围修。
本契约的「决定 ID」指决定索引/决定节里的具体 ID（项目自定义格式，如 D12）；D0-D7 是决定类型，不是 ID。三档不变：轻审同一 agent 按交付物类型做浅审（文档：A；代码：B；两者都有：A+B）；重审 A/B 分开发；变异 = 重审 + 主 agent 变异。Lane B 用下方 B 派发说明，不适用本契约。

1. 先读决定索引或决定节与范围清单，输出「已拍板清单」：每条列 ID / 来源 / 状态（已拍板或待核）/ 覆盖（章节、验收、范围清单）。索引/决定节缺失、字段不全、字段自相矛盾或编号分叉时，报阻断，不自行补决定；同一决定在 ADR 与 spec 各有一个编号，或编号口径分叉时，同样报阻断；记录存在但覆盖不到该条款的，按第 2 条标「索引/决定节不足」。
2. 候选发现先过清单：能引决定 ID 唯一推导的，写出推导链（决定 ID → 条款/验收 → 结论），按结论分流——覆盖（实现/表述不构成偏离）：记入关闭清单，不摆成用户岔路；违反（实现/表述偏离决定）：进入发现列表，按严重度报，不得按「引决定 ID 关闭」处理；数据、安全、权限、不可逆偏离尤其不得关闭。引不出决定 ID 的，看是否有新事实或主动改范围；有的进入发现列表并标新事实/改范围；都没有，按 spec bug 或实现细节处理（spec bug 按 15-records §四 标「待核」或阻断，补决定 ID 或回对应闸），不当作新决策。记录存在但覆盖不到该条款 = 索引/决定节不足；记录缺失 / 字段不全 / 字段自相矛盾 / 编号分叉 = 阻断；只有前者（及同一决定多 owner / 无法唯一推导）才标「需裁决」。
3. 审核范围：本次 diff；标「待核」的行；两个已拍板来源之间的矛盾。已拍板的决定不复审；实现是否按决定落地仍要审；历史规格与现状文档只在核对来源时读。
4. 只有三种情况允许上报「需裁决」（由主 agent 汇总一次问用户）：① 索引/决定节不足 / 同一决定多 owner / 无法唯一推导；② 新代码或生产事实，且已拍板决定覆盖不到；③ 主动改范围。其余一律先按已拍板推导；能推出的不进「需裁决」。必须问时只汇总一次「缺哪条决定、为什么推导不出、影响哪个验收」，不逐条问。
5. 每条发现必须写齐：文件:行 / 问题 / 证据（现状 vs 期望）/ 推导链（决定 ID → 条款/验收 → 结论）或「无决定 ID」 / 处置类型 / 严重度（阻断、高、中低）/ 成因（同步失误、设计固有、岔路没拍）/ 能不能不修 / 违反或关联哪条决定 ID / 新事实 / 主动改范围。依据决定 ID 指这条发现违反或关联的决定；新事实指拍板时不存在的可核事实；主动改范围指是否要求改变已批准范围。依据决定 ID、新事实、主动改范围三栏都写不出的，按 spec bug 处理（按 15-records §四 标「待核」或阻断，补决定 ID 或回对应闸），不当作新决策问用户。数据、安全、权限问题不因标中低而降格；Lane A 只报与决定/范围相关的这类阻断，深审归 Lane B/重审。
6. 摘要、总览只作决定索引/决定节的视图，不作决定依据；范围清单的枚举部分是范围唯一正文，处置 / 阶段 / 授权 / 例外规则只引决定 ID。与索引/决定节冲突时先判视图错，报视图冲突和建议改法，由主 agent 改，不拿视图推翻已拍板决定。同一决定多 owner / 两个来源都自称正文 = 阻断；先判 owner，再判对错。
7. 用户明确要求全文重审时，只对冻结的决定索引或决定节做一致性核对，不产生新决定；发现的新事实或范围变化按第 5 条标注后交用户。索引/决定节未冻结时只报阻断，要求主 agent/用户先冻结；审核方不冻结、不改索引、不新造索引；已作废、已被取代的 ADR 不审。
8. 报告先列已拍板清单，再列关闭清单，再列发现；报告头写日期、档位、agent 数、lane（A/B）、整案（全文重审）/仅复核、关闭项 N 条（引决定 ID 关闭，附关闭清单）、阻断/高/中低计数、核了什么、没核了什么。关闭清单每条给决定 ID / 来源 / 推导链（决定 ID → 条款/验收 → 结论）/ 结论；关闭项不是发现，但仍须逐条留链；计数只是汇总。结论只覆盖证据证明的范围。零发现、检查绿、审核通过都不等于用户同意合并。
9. 写回（报告字段 + 主 agent 执行）：推导出的答案，报告里给写回清单——只改应用/表述的，写成「由 <决定 ID> 推出」的派生条，补到摘要/覆盖图（项目有 FAQ 时同）；改变范围/验收/例外的，不得写回派生条，标「新决定」，走 D1/D2/D3。写回是机械回填（L0-6「单纯补稿或换内部方法不重问」），由主 agent 在报告后执行并记录，不受修订范围「不改/只改阻断+高」阻挡；零发现但有派生条时同样执行，不摆修订卡。写入位置按 15-records：草案期可补 spec 视图；已合并/基线 spec 记 issue/PR 修正记录并链 spec，或走 D3，不直接改决定正文；覆盖图只补「由 <决定 ID> 推出」的派生覆盖，不改既有决定正文或 ID。其余修复由主 agent 按用户选的修订范围执行。
```

```text
你是本次交付的 Lane B 审核方（对抗找 bug）。只审给出的 diff 与材料，只读不改；修复不由你执行。
只报可复现的失败场景（输入 / 期望 / 实际）、范围外改动和测试缺口；不产出决定、不做推导/关闭/写回、不向用户提问；决定/范围一致性归 Lane A。
每条发现写：文件:行 / 问题 / 复现步骤 / 证据（现状 vs 期望）/ 严重度（阻断、高、中低）/ 成因 / 能不能不修。
零发现、检查绿、审核通过都不等于用户同意合并。
```

用法：A = 规格符合性（含适用清单 / 范围）；B = 对抗找 bug。轻审 1 个 agent：文档做 A 浅审（规格符合性 + 方案 / 自定细节），代码做 B 浅审（对抗找 bug + 范围外对账），两者都有则 A+B 浅审；重审 A/B 各 1 份，各带同一份决定索引/决定节和同一组 base/head；变异 = 重审 + 主 agent 变异。主 agent 汇总时保留「引决定 ID 核对后仍成立」的发现，单列「引决定 ID 关闭」的候选（字段同关闭清单），并按用户选的修订范围执行；派生条写回按第 9 条机械回填。
