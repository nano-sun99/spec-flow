# Playbook: 审核与修订

> **示例非必须**：本页的走法是一条走通过的路，不是必须顺序；按实际情况调整。
> **规范性**：只有标「（规范性）」的章节；它们引用 L0-L2，不新增、不放宽闸口。

- **适用**：spec 期或实施期，当份 PR / 当批 PR 需要审核、修订与复审；或交付物含文档改动、摆派审卡前需要跑文档检查。
- **一条走通过的路**：文档检查 → 选档位与修订范围（D2 / D4 ①）→ 派发 → 报告（含成因与能不能不修）→ 原样贴评论 → 修订 → 复审（R1-R3）→ 合并卡（D4 ②）。
- **失败模式**：审核完自动全改；把自测 / 自查说成独立审核；沿用规格期档位；把零发现或审核结论当合并同意；每轮新增规则不做范围检查；拆文件重置轮次；把同步失误升级成设计变更；审核范围扩成质量意见；文档检查在派审卡之后才跑。
- **证据**：审核结论原文、修订记录、文档检查三态、轮次与范围检查、合并卡、D4 记录。
- **注意**：这是示例，不是必须顺序；闸口相关章节是规范性的，不能自行放宽；改动闸口证据须用户批准。

## 一条走通过的路（示例非必须）

1. **摆卡前跑文档检查**：在交付物自己的工作区跑；卡上固定写「文档检查：绿 / 红 + 摘要 / 无入口」。
2. **选档位与修订范围（D2 / D4 ①）**：档位名称、agent 数（成本口径）、选择权与时点引用 [10-stages](../10-stages.md) 术语表与 [20-decisions](../20-decisions.md) D2 / D4；本 playbook 只写派发方法，不重定义选项。
3. **派发**：
   - **不审**：不派 agent；主 agent 按 diff 对获批范围与已采用约束自查。
   - **轻审**：1 个。规格期审文档：规格符合性 + 方案 / 自定细节两项；实施期审代码：对抗找 bug + 范围外对账。
   - **重审**：2 个。规格符合性（含适用清单 / 范围）+ 对抗找 bug。
   - **重审 + 变异**：重审 + 主 agent 换错判据并跑全量相关测试；仍全绿说明没护栏。变异不是多派一个 agent；只在独立测试工作区做、恢复变异、不把坏判据带入交付；无可跑测试如实报无法变异。
4. **给材料**：当前获批 spec、真实工作区 / diff 基准、项目入口、已采用约束、现行 ADR（如适用）；要求逐条核 `file:line` 与「现状是 X」断言，不拿未经实测的假设当事实。审核只读不改文件。
5. **报告格式**：严重度（阻断 / 高 / 中低）之外，每条发现另加两列——**成因**与**能不能不修**（见下文 #158 五机制）。
6. **结论原样贴 PR 评论**（无 PR 贴对话）：不改写、不删条、不降严重度；可加一行头（日期 · 档位 · agent 数 · 阻断 / 高 / 中低计数）。零发现只贴结果，不摆修订卡。
7. **修订范围（规范性）**：有发现时由用户选 D2 / D4 的修订范围：全改 / 只改阻断 + 高 / 不改 / 砍掉相关路径 / 写明本期不保证。不自动改；选不改且仍有阻断 / 高时不合并。
8. **甲类只做对账**：判为「甲 · 同步失误」的发现，只跑五问对账，不为此新增规则（见下文）。
9. **复审**：每次复审重新摆当份派审卡；修订同意不授权再派。
10. **合并卡（D4 ②）**：卡列 PR、目标分支、修订后完整提交、验证结果、未处理项；确认后才合并。
11. **收尾**：修订处置追加到规格末尾「审核修订记录」或原任务 PR；不重写获批正文。

## #158 五机制（规范性）

> 来源与完整复盘见案例 `2026-11-07-review-scope-explosion`；五条按总纲 §九 写成运行规则。

1. **审核报告加「成因」列**：每条发现标 `甲 · 同步失误` / `乙 · 设计固有` / `丙 · 岔路没拍`。严重度答「挡不挡合并」，成因答「怎么修」，两者并列。
2. **审核报告加「能不能不修」列**：`必须加规则` / `可砍路径` / `可写明本期不保证`。不是每条洞都必须用新规则补。
3. **修订卡可直接选 D2 / D4 的「砍掉相关路径」「写明本期不保证」**：它们已是 L2 修订范围的选项；仍由用户选。
4. **甲类只许五问对账，不许改设计**：甲类发现只跑下列五问，不为此新增规则——
   - 我引用的每个锚点、文件、章节，真的存在吗？
   - 机制清单里的每一项，正文有对应段落吗？
   - 这条路径的每一步，别处都覆盖了吗？
   - 我声明「已新增 / 已改为」的东西，这个 PR 里真的建了吗？
   - 需要人拍板的事，写进「未定项」了吗？
5. **每轮范围检查 + 每批轮次上限**：每轮后问「本轮新增规则里，有几条是原问题必需？答不出来就是扩了」；每批设轮次上限（默认按 R1-R3 计，见下节），触发上限即停，由用户选**重画 / 砍范围 / 停**。

## 严重度（规范性）

- **阻断**：走不通；必要证据不可执行；同一决定多 owner；承重选择未定；数据 / 安全 / 权限问题。
- **高**：会导致返工或跨份不一致，但本轮可修。
- **中 / 低**：不挡合并，留未处理项。
- 数据 / 安全 / 权限问题不因标中 / 低而降格；扩展建议只作建议，不自动成为新机制；发现须对应具体获批要求、行为、交付或证据，不强求步号。

## 轮次（规范性）

- **R1 全量**：走完整路径，核正常 / 失败 / 证据，以及是否有该走没走的分支。
- **R2 只核闭合**：只核上轮发现是否闭合，以及新增的阻断 / 高；新出现的中 / 低只记录。
- **R3 停**：仍有阻断 / 高则停，由用户选重画 / 砍范围 / 停；不派第 4 轮。

## 文档检查（规范性）

- **时点**：交付物为 spec / 纯文档，或代码 diff 含文档改动时，**摆派审卡前**在交付物自己的工作区跑；选「不审」也先跑。免审核闸的机械回填无卡，免此检查。
- **入口发现顺序**：项目指令自报且真实存在的入口 → 首个存在的 `scripts/check-docs.sh` → `scripts/check-doc-links.sh` → 无入口。自报路径不存在落下一档；存在但跑不起来 / 崩溃 = 红，不冒充无入口。
- **三态**：绿 / 红 + 摘要 / 无入口；卡上固定写结果。
- **处置**：本次 diff 引入的红必须修复、重跑绿后再摆卡；无关存量红注明数量 / 摘要与不相关依据，不阻本次合并，交用户处置；用户可当场明示一次豁免并记理由。
- **边界**：检查绿 / 标存量 / 豁免都不授权合并；静态绿不证明客户端或生产行为。

## 批次与豁免（规范性）

- **批次审核**：一卡盖一个实施批次时，须列每份 PR / 分支，写「N 份 × 该档 = X 个 agent」，逐份按 [10-stages](../10-stages.md) 术语表的档位 agent 数累计；文档检查逐成员在其工作区跑并列结果。批卡只管审核，**不授权批量合并**。
- **免审核闸**：无新内容的机械编号 / 状态 / 索引 / 验收回填、不进仓的草稿 / PR 底稿免审核闸；归属拿不准时摆卡问，不自判。无 PR 的交付前仍摆审核卡并给 diff。机械回填无卡；若含文档改动，文档检查仍按 L1 完成条件执行。
- **worktree 豁免**：只有用户当场明确说「直接改 / 不开 wt」才成立；这是 [10-stages](../10-stages.md) §三 交付前置写明的用户级例外，须记录理由；agent 不自判、不主动建议；真并行仓的认领锁仍执行。
- **豁免不免合并**：以上任何豁免都不免实际存在 PR 的独立合并确认（L0-5）。

## 修订同步（示例非必须）

改判据、定义、常量或术语时，按语义找间接落点，而不是只改眼前一句：

- 规则 / 原理：同一判定的唯一正文、理由与适用条件。
- 实现 / 数据源：实际键、接口、脚本或产物是否存在，与文字相符。
- 工作与验收：真正做了什么、如何判对错，相关失败路径是否仍成立。
- 跨文档：总纲、共享合同、兄弟规格及引用锚点是否指向当前 owner。
- 历史：旧决定确被取代时保留原内容与来源，以取代说明或链接区分，不批量改成新口径。

表达 / 引用的修正不自动成为新机制；实质改变获批目标 / 范围、冻结决定或外部合同，回 D1 / D2 / D3。

## 失败模式（示例非必须）

- 审完默认全改；经用户卡片确认的只有个别条目。
- 「不审」档被当成免自查；或自测 / 草拟被说成独立审核。
- 实施期沿用了规格期的档位与修订范围。
- 零发现、检查绿、reviewer 说可合并被当成用户同意。
- 每轮都在正确地找洞，但没人问「这条能不能不修」，规则越加越多。
- 甲类同步失误被当成设计缺陷，每条都升级成一次设计变更。
- 拆分后轮次重置，同一个 PR 实际审了六轮而每份文件都像 R1。
- 审核 prompt 写得太狠，反向逼实施方加防御层；范围外对账膨胀成质量意见。
- 文档检查在派审卡之后才跑，卡上「绿」是空白。

## 证据（示例非必须）

| 时点 | 证据 |
|---|---|
| 派审前 | 文档检查三态结果（命令 / 摘要 / 无入口） |
| 派审 | 档位与修订范围选择记录；提供的 spec / diff 基准 / 项目入口 / ADR |
| 审核后 | 审核结论原文（含成因与能不能不修两列）；轮次记录 |
| 修订 | 用户选择的修订范围；逐条处置；甲类五问对账结果 |
| 复审 | 上轮闭合核对、新增阻断 / 高；范围检查 |
| 合并 | D4 ② 合并卡与确认；未处理项 |

## 闸口（规范性）

- **D2 / D4 审核档位与修订范围**：触发、证据、选项与默认以 [20-decisions](../20-decisions.md) D2 / D4 为准；每份、每阶段当场选，不沿用规格期档位。
- **D4 ② 合并**：每份 PR 单独确认；不审、零发现、同意改、已修完、reviewer 说可合并都不等于用户同意（L0-5）。
- **判断权在用户**：agent 不自判核心、不自动派审；项目禁用的档位不展示（等于该档不存在于当次选项）。
- **独立审核边界**：子 agent 是执行分身；自测、草拟和检索不能冒称独立审核。真正要求另一方裁决时，材料备好后停，等用户指定方（L0-2：事实 agent 查，决定用户拍）。
- **不新增闸**：本页不新增审核档位、决定类型或完成条件；与 L0-L2 冲突时以 L0-L2 为准。
