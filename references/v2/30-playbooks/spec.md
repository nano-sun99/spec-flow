# Playbook: 规格成熟度与拆分

> **示例非必须**：本页的走法是一条走通过的路，不是必须顺序；按实际情况调整。
> **规范性**：只有标「（规范性）」的章节；它们引用 L0-L2，不新增、不放宽闸口。

- **适用**：写一份 spec 时判断它到了什么成熟度；或在方案期评估「拆 / 不拆」、表达交付物地图与依赖。不适用于已有获批 spec 的实施单。
- **一条走通过的路**：骨架 → 对照 → 终稿；结构复杂时先评估拆分，再按交付物与依赖边组织。
- **失败模式**：把成熟度当三道审批；固定列数 / 样例数当格式闸；按行数或目录硬拆；只划文件地盘不看语义依赖；父单冒充阻塞；后加子件不同步地图。
- **证据**：同一份 spec 的骨架 / 对照 / 终稿、拆分卡与候选拆法代价、交付物地图与依赖边、DoR 表达。
- **注意**：这是示例，不是必须顺序；闸口相关章节是规范性的，不能自行放宽；改动闸口证据须用户批准。

## 成熟度（示例非必须）

草稿、对照、终稿是同一份文件 / 同一个 PR 的成熟度，不是新增阶段。

1. **公共骨架**：用最少内容承接已确认的目标、范围、非目标与可判验收；把尚未解决的设计、接口、业务口径和验收问题标出来。不提前猜页面分支、完整接口或最终拆法。
2. **对照**：
   - **有页面**：等用户设计稿到位，再结合骨架沿实际行为梳理角色、交互、状态、数据、异常、权限和接口读写；不代画、不凭猜测补完整接口。缺页、关键状态、合同或验收空白集中返回公共缺口。
   - **无页面**：选最便宜且能判对错的材料，例如脚本的实际输入 / 命令 / 输出 / 退出码、后端调用的请求 / 响应 / 错误 / 重试、数据报表的输入输出与边界。「正常、边界、失败或重跑」是覆盖风险提示，不是固定三个例子；不为凑数量虚构数据。
3. **终稿**：把对照结果回到同一正文；承重规则、接口 / 数据、适用异常 / 兼容、验收与自定选择彼此一致；检查「文字说做了、落地物其实没有」、验收无法执行、同一决定多个正文、范围外新增承诺。

## 拆分评估（示例非必须）

1. **先找可验收成果**：从目标、实际改动面和依赖找可独立说明的交付结果；不只按行数、章节、前后端或会话长度机械切。
2. **给真实比较**：每个候选子件交什么、范围多大、还保留哪些阶段、依赖谁、能否并行，以及总纲 / 执行 spec / 父子 issue 的维护代价；通常多阶段值得拆，不可分则说明为什么。不确定工期写估计，不说成实测。
3. **拆后组织**：总纲保持共享设计与索引；子件各承接一个完整成果和本份验收；不用总纲再重复派一份全范围任务。拆成 N 份对应 1 总纲、N 执行 spec、N 执行单、1 跟踪父单。
4. **交付物地图**：稳定组标识 / 编号、规格链接、产出、消费与边界；谁负责共享件、各自独占 / 不碰哪些范围；开始、合入、发布分别依赖什么事实。
5. **依赖边**：用「提供方 → 消费方」有向边，交代具体契约 / 数据 / 配置 / 运行时 / 发布验收产物、就绪条件、证据、责任方和挡住哪一步。文件重叠不自动等于语义依赖；既有共享文件又有接口依赖时分别看清。
6. **三种就绪分开**：能开工不等于能合入，能合入不等于能上线。硬前置不伪装并行，软协调不伪装阻塞；共同发布不必倒退成巨型规格。
7. **稳定身份与父子**：编号是身份不是波次；不因排期变化重编号。父子关系表示归属，真正挡进度的才是阻塞；总览只跟踪，不等待父单关闭才允许所有子件开工。
8. **后加子件**：先对照当前设计来源，把变化写清并同步真实现行地图 / 依赖；已合并正文需实质修改时回 D3 / D2，不用新子件悄悄覆盖旧决定。

## DoR 表达（示例非必须）

可实施不是「照抄了模板」。当份终稿需要可核的下列信息，允许表格、段落、图或其他充分表达：

- 承重规则和已确认做法一致，无未决定的承重问题；agent 自定的默认值、判断、命名、落点可识别，不夹带方案外承诺。
- 澄清记录可核（轮次、问题、用户决定）；未用结构化澄清写明原因。
- 行为有触发、响应及必要失败 / 空态处理；适用写路径有明确入口与唯一归属，不虚构本任务没有的数据状态机。
- 验收能判对错，有命令、断言、截图或适用人工确认入口，正常 / 异常 / 边界和必要回归覆盖充分。
- 适用的数据迁移、回填、回滚、兼容及外部合同 / 版本影响明确，或写不适用及事实理由。
- 已采用 ADR 时当前决定 / 取代链与正文一致；未采用不新增 ADR 前置。

表达方式可替换：固定四列表、三个例子、3–5 条岔路、每条挂步号都不是 v2 的格式闸；项目 / 用户明确约定的具体格式仍有效。

## 失败模式（示例非必须）

- 骨架版 / 对照版被当成合同送去合并；实施者照未定稿的图纸开工。
- 把成熟度写成三道审批或三次派审。
- 为了凑「三个例子」虚构数据；或用「无页面」跳过接口 / 业务分析。
- 按行数硬阈值强拆；拆完只划文件地盘，不写语义依赖。
- 把父子归属当阻塞；所有子件等父单关闭才开工。
- 后加子件不改地图 / 台账；后来读的人拿的是旧账。
- 把「必须同批合入 / 发布」误判成拆分失败；它其实是一条依赖边。

## 证据（示例非必须）

| 时点 | 证据 |
|---|---|
| 骨架 | 已确认目标 / 范围 / 非目标 / 验收；未决项清单 |
| 对照 | 设计版本或真实样例；缺口清单；接口读写关系 |
| 终稿 | 一致的规则 / 接口 / 数据 / 验收；可执行验收 |
| 拆分 | 候选拆法、推荐与代价；交付物地图；依赖边与三种就绪 |
| 后加子件 | 变化说明；同步后的地图 / 依赖；回 D3 / D2 的记录 |

## 闸口（规范性）

- **D1 范围与结构**：拆 / 不拆是 D1 的选项；证据含真实交付物、里程碑、改动面、依赖、候选拆法、推荐及代价；不以工时 / 行数硬阈值强制拆（[20-decisions](../20-decisions.md) D1）。
- **设计段完成条件**：承重规则一致、澄清记录可核、行为有触发 / 响应 / 失败态、验收可判、数据与契约影响写明、已采用 ADR 一致（[10-stages](../10-stages.md) 设计段）。
- **改已合并 spec**：新增、取消或改变范围 / 验收含义一律走 D3 新开一份；不在旧正文上「维护」。
- **不新增格式闸**：本页的表格、例子、岔路数只是方法提示；不按推荐写法的字面顺序或数量判违规。
- **不新增闸**：本页不新增决定类型或完成条件；与 L0-L2 冲突时以 L0-L2 为准。
