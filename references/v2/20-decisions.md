# v2 决策目录（L2，D0-D7）

> 只列「只有用户能拍」的决定。**硬闸 = 这 8 类决定类型**；每类可多次触发，类型不增，无第 9 类。八类之外遇到 L0-7 承重缺口（数值/接口/范围/权限/数据这类选错要返工或越权的决定）同样要停——本目录不是「可以停的完整清单」，只是「必须停的固定类型」。L0-1 里不在 D0-D7 的不可逆动作（force push、删分支、生产写、不可逆迁移、密钥、新增外部依赖、tag 移动/删除等）仍须用户确认，只是不占 D 类型。
>
> agent 能判的（入口/落点、非关键标签、预演做法、分支命名、提交格式）不进目录，进 playbook。铁律见 [00-constitution](00-constitution.md)，阶段见 [10-stages](10-stages.md)，记录字段见 [15-records](15-records.md)。
>
> **共同失效规则**（L0-6）：批准绑定当次列明的对象、范围和版本；新增实质内容、换目标、返修、暂停、撤销或要求重审，旧批准即失效，回对应确认。单纯补稿或换内部方法不重问。各条「失效」只写该类特有的失效点。

## D0 实施委托

- **触发**：spec 已合并、执行 issue 已建，且用户明确表示实施（「请做 #N」「开始实施 #N」「按 #N 开工」等）。父单、PR 号、已有锁、审核通过都不算委托。
- **证据**：spec 版本/合并提交（与当前应实施版本一致）、issue 仍 `open`、本次范围、当前锁、无第二份生效授权；同窗口入口另核交接报告相邻性（报告是最后一条 agent 消息、用户开始意图紧接、恰好一张未授权执行交接）；上下文压缩后或多候选时必须点名 `#N`。
- **选项**：委托 / 先不委托。**默认**：不委托。
- **失效**：issue 已关闭、范围扩大、spec 合并提交不再是当前应实施版本、出现第二份生效授权、交接报告不再相邻。

## D1 范围与结构

- **触发**：新需求进入，或已有确认范围内发生范围/结构实质变化。
- **证据**：目标、范围、非目标、验收；有 spec 时另含页面/无页面与拆/不拆；观察式例外（如适用）；承重未知（数值/接口/权限/数据）已列出。
- **选项**：确认 / 调整 / 不做。**默认**：不做。
- **失效**：目标或验收含义改变；结构实质变化（范围、里程碑、依赖或 owner 变化影响既有拆法）。

## D2 设计与规格确认

- **触发**：方案或规格草稿完成。
- **证据**：方案、备选及代价、验收、依赖、数据库变更清单（如适用）、文档检查结果、审核档位、修订范围。
- **选项**：确认 / 改 / 重做；审核档位：不审 / 轻审 / 重审 / 重审 + 变异；修订范围：全改 / 只改阻断 + 高 / 不改 / 砍掉相关路径 / 写明本期不保证。**默认**：不审（0 个 agent，主 agent 自查）、修订范围不改、不合并。
- **失效**：方案实质改变；换了审核档位或修订范围；出现新的阻断/高发现。

## D3 spec 合并

- **触发**：审核与修订完成。
- **证据**：审核结果、修订记录、文档检查结果、最终版本、目标分支。
- **选项**：合并 / 先不合。改已合并 spec：新开一份 / 改旧的（默认不动冻结正文）；勘误标记只限「原文事实写错且会误导读者」，新增/取消/改变范围或验收含义一律新开 spec。**默认**：不合并。
- **失效**：修订后版本变化；仍有未处理的阻断/高。

## D4 每份 PR（含 hotfix 合回）

- **触发（同一决定类型，两次时点）**：① PR 提交后、审核开始前——选当份审核档位与修订范围；② 审核与修订完成后——确认合并。
- **证据**：① PR、目标分支、完整提交、本次范围；② PR、目标分支、修订后完整提交、本次范围；审核结论（原样贴 PR 评论）、修订记录、文档检查结果、验证结果、未处理项。hotfix 另加基于的生产 tag、修复提交、临时 tag、验证证据。
- **选项**：① 审核档位：不审 / 轻审 / 重审 / 重审 + 变异；修订范围：全改 / 只改阻断 + 高 / 不改 / 砍掉相关路径 / 写明本期不保证。② 合并 / 先不合。每份 PR 单独选档，不沿用规格期档位；同批另一份 PR 的同意不延伸到本份（L0-5）。**默认**：不审（0 个 agent，主 agent 自查）、修订范围不改、不合并。
- **失效**：PR 有新提交（档位与修订范围绑定当时提交）；目标分支前进到需重核；仍有未处理的阻断/高。

## D5 整条 issue 合入 staging（仅 staging 线）

- **触发**：issue 分支验收通过 + 合入预演绿 + 四类核对齐。
- **证据**：issue #N、`issue/<N>`、完整提交、预演分支/提交、staging 基线、合并后构建与本 issue 验收、四类逐项（含文档检查结果）、未处理项、目标 staging 完整提交。
- **选项**：合入 / 先不合。**默认**：不合入。
- **失效**：staging 基线前进需重跑预演；issue 分支有新提交；四类缺少结论（「不适用及原因」是有效结论）；仍有未合入的实现 PR。

## D6 生产发布（仅采用 release 的项目）

- **触发**：批次测试通过 + rc 验收通过。
- **证据**：本批批次测试的提交与通过结果、批次范围（上一个生产 tag..当前候选）、排除项、未知搭车项处置、必要依赖、四类核对结论、rc tag、最终 tag（同一提交）、产物/部署单元、验证、回滚目标、直接干任务清单。
- **选项**：发布 / 先不发。**默认**：不发布。
- **失效**：候选有新合入；批次测试失效未重跑；rc 与最终 tag 不在同一提交；范围或回滚目标变化。

## D7 回滚

- **触发**：生产异常。
- **证据**：目标 tag/快照、范围、影响、异常证据（监控/日志/验收失败）、回滚目标可用性。
- **选项**：回滚 / 不回滚。**默认**：不回滚。
- **失效**：异常范围变化；目标快照不可用或与生产树不一致。

## 标签规则

- 标签是视图，不是状态机；标签与交接区正文状态冲突时停下报告，不自行选一个继续。
- **必须用户确认**：「待上线」「待验证」「关单」。
- **agent 可换 + 报告**：其余标签，无歧义时；有歧义时问。
- 不改现有 adopt 行为；采用方式见项目已采用的标签模块。

- 纳入 / 不纳入（D1 的适用子项），**默认不纳入**；触发类型与字段见 [15-records](15-records.md) §六。
