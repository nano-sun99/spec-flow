# v2 阶段合同（L1）

> 本页是「什么算完成」的唯一正文。4 段各写目标、完成（全部为真）、证据、出口、常见失败；段内顺序由 agent 按这一单的情况决定，本页不规定步骤。铁律见 [00-constitution](00-constitution.md)，用户决定见 [20-decisions](20-decisions.md)，记录字段见 [15-records](15-records.md)。
>
> 设计来源：总纲 §六。术语与发布安全不变式在本页写成运行正文；与总纲不一致时以总纲为准并按 L0-7 报告。对外仍是两段：澄清 + 设计 = 方案期，交付 + 发布 = 实施期；4 段是内部分细，只用于判断这一单在哪一段、能不能出段。

## 一、术语（L0-L2 自足）

| 术语 | 定义 |
|---|---|
| 四类 | spec、实现/必要测试、配套文档、必要依赖 |
| 页面 | 只有可交互 GUI 才算；CLI 输出、导出报表、接口响应本身不算。判错只影响是否等用户设计，不影响接口与业务缺口分析 |
| 候选 | 三层：候选分支（如 staging）的当前 HEAD；staging 线：staging HEAD；单主线：生产主线 HEAD |
| 合入预演（仅 staging 线） | 把当前 staging 合入 issue 分支（或临时预演分支），在真实 merge 树上构建并跑本 issue 验收；记录预演分支/提交、staging 基线、合并后构建与验收结果。允许 rebase/CI，但必须证明结果树与真实 merge 树一致，否则不算预演绿 |
| 批次测试 | 在当前候选上构建、部署测试环境，跑回归和跨 issue 验收；候选有新合入即失效。最终 tag 的提交必须是最近一次通过的批次测试所基于的候选 HEAD |
| rc 验收 | 从 rc 附注 tag 构建、部署测试环境跑验收；不做 15 分钟监控 |
| 生产监控 | 从最终 tag 构建、部署生产后启动 Monitor 15 分钟（项目手册另有规定的按手册）；崩溃或异常 HALT，停住上报，不自动回滚 |
| 生产分支快照 | 单主线：主线前进到同一提交并打 tag；三层/staging：生产分支的树等于该成功 tag 的树，不 merge / reset / read-tree 覆盖 |
| 搭车项 | 候选里未列入本批、来源未登记的改动 |
| 交接区 | issue 正文的「spec-flow 交接」区或等价字段；无 issue 时由任务 PR 承接 |
| 授权方式 | `issue-direct`：用户点名执行 issue；`same-window-handoff`：agent 交接报告是最后一条 agent 消息且用户开始意图紧接；`takeover`：接管已认领工作，需新用户委托 |
| 审核档位 | 不审 = 0 个 agent（主 agent 按 diff 自查）；轻审 = 1 个；重审 = 2 个（规格符合性 + 对抗）；重审 + 变异 = 重审 + 主 agent 换错判据跑相关测试（文档类无可跑测试则如实报无法变异） |
| 严重度 | 阻断 = 走不通 / 必要证据不可执行 / 同一决定多 owner / 承重选择未定 / 数据安全权限；高 = 导致返工或跨份不一致但可修；中、低不挡合并，留未处理项 |
| 文档检查 | 入口按序发现：项目指令自报且真实存在 → `scripts/check-docs.sh` → `scripts/check-doc-links.sh` → 无入口（自报路径不存在落一档；存在但跑不起来 = 红，不冒充无入口）。三态：绿 / 红+摘要 / 无入口；本次 diff 引入的红须修复，存量红注明数量/摘要与不相关依据 |

## 二、四段合同

### 澄清

- **目标**：把需求变成可判断的范围、验收和约束。
- **完成（全部为真）**
  - 改哪里 / 怎么改 / 带来什么能力或优化，具体到能被否掉。
  - 范围与非目标明确。
  - 验收可判对错：有命令、断言、截图或人工确认入口。
  - 页面 / 无页面、拆 / 不拆、观察式例外（如适用）已由用户定。
  - 承重未知已闭合：数值、接口、范围、权限、数据无悬空。
  - 入口（直接干 / 开 spec）已判定并报告；用户可按 L0-6 否决。
- **证据**：澄清记录（轮次、每轮问题、用户原话与可核时间或卡片选择）、需求摘要、验收清单。
- **出口**：用户确认范围（D1），agent 判定直接干或进入设计并报告。
- **常见失败**：澄清记录只写结论不写轮次或原话；验收写成「功能正常」；把接口当页面；承重问题留给实施期。

### 设计

- **目标**：把方案变成可执行的 spec / 计划。
- **完成（全部为真）**
  - 方案、备选及代价、验收、依赖、数据库变更清单（如适用）齐备。
  - 承重规则与已确认做法一致；澄清记录可核（只写结论不算）。
  - 行为有触发、响应及必要的失败/空态处理。
  - 验收能判对错，覆盖正常、异常、边界和必要回归。
  - 数据迁移、回滚、兼容、外部契约影响已写明，或写不适用及事实理由。
  - 已采用 ADR 时当前决定/取代链与正文一致；未采用不新增前置。
  - 审核档位与修订范围已选（D2）；审核与修订已按所选完成，结论原样贴 PR 评论或对话。
  - 文档检查已跑：本次 diff 引入的红已修复；存量红已注明数量/摘要与不相关依据。
- **证据**：spec、审核记录、修订记录、文档检查结果。
- **出口**：spec 合并（D3）+ 执行 issue 已建 + 等待明确实施委托（D0）。
- **常见失败**：spec 写步骤不写状态；审核档位从规格期沿用；文档检查在派审卡之后才跑；把「用户没反对」当合并批准。

### 交付

- **目标**：把实现变成可验收的 PR / 分支。
- **完成（按项目形态取适用分支，全部为真）**
  - 有 issue：issue 分支验收通过；四类逐项满足，或按事实记不适用及原因——缺失 / 未知 / 失败不算完成。
  - 有 issue 且 staging 线：合入预演绿（结果树与真实 merge 树一致）；无未合入的实现 PR。
  - 无 issue（直接干）：按项目实际需要完成可判定验收；有测试环境则部署验收，无则写不适用及事实理由。
  - 采用 release：候选就绪——单主线 = 待合入主线的任务分支；三层 = 待挑入候选分支的任务 PR；staging 线 = 待合入 staging 的 issue 分支；四类已核。
  - 不采用 release：交付验收后本段即完成，不新增分支、tag 或发布义务。
  - 文档改动已跑文档检查（同上三态口径）。
- **证据**：PR 列表、构建结果、验收证据、四类逐项、合入预演结果（staging 线）、worktree/锁记录、文档检查结果、审核结论与修订记录。
- **出口**：整条合入 staging（仅 staging 线，D5）/ 任务 PR 合并（D4）/ 无发布义务任务关单。
- **常见失败**：实现 PR 合了就报 issue 完成；四类用「没改就是不需要」填；预演没在真实 merge 树上跑；文档检查只在主仓跑。

### 发布

- **目标**：把候选变成可复现的生产版本。
- **完成（仅采用 release 的项目，全部为真）**
  - 批次测试通过（当前候选；最终 tag 前重跑）。
  - rc 验收通过（从 rc tag 构建，不做 15 分钟监控）。
  - 生产发布已获用户批准（D6）。
  - 生产监控正常通过；崩溃或异常按 L0-4 停住上报，不进入完成。
- **证据**：批次记录、rc tag、最终 tag、监控结果、发布记录。
- **出口**：生产验证通过 + 生产分支快照；用户确认后关单（D7/标签规则）。
- **不适用**：不采用 release 的项目本段跳过——跳过是「不适用」，不是「未完成」，也不因此补 tag 或部署。
- **常见失败**：从 HEAD 构建；rc tag 后不重跑批次测试；监控崩溃后自动回滚；移动或删除生产 tag。

## 三、交付前置条件

- **分支起点与 PR 目标按项目形态**：staging 线从 `origin/staging` 开 `issue/<N>`，实现 PR 回该 issue 分支；三层从 `origin/<集成>` 开任务分支，PR 回集成分支；单主线从 `origin/<主线>` 开短期分支，PR 回主线。实际映射以项目指令为准；映射不明按 L0-7 问。
- **锁键 = 精确分支名**：`issue/<N>`（无 slug、无前缀），worktree 目录 `issue-<N>`；该分支已被检出 = 有人在做，撞锁停，不双写同一工作区。
- 直接干 `task/<slug>`；批次修复 `fix/<N>-<slug>`（直接干 `fix/<slug>`）；hotfix 从生产 tag 切 `hotfix/<tag>-<slug>`，修复提交打临时 tag、从该 tag 构建，不立即打生产 tag，跟下一班车。
- **发行安全不变式**（仅采用 release 的项目；违反任一条即是 L0-1 的不可逆动作）：
  - 只从不可变 tag 构建，不从任何 HEAD 构建。
  - 三层/staging：生产分支的树必须等于最近成功生产 tag 的树；不用 merge / reset / read-tree 覆盖生产快照。单主线不要求主线树等于旧 tag，只要求 tag 不可变、构建自 tag。
  - 生产 tag 不移动、不删除；打错 tag 保留并在发布记录标废弃。
  - 不在生产分支 revert 未上线内容；不在共享主仓切分支或做快照；不直改另一个 worktree 已检出的引用。
  - 保护分支直推不在普通授权范围内。

## 四、入口与跳过

- 这一单从哪段进：新需求从澄清进；已有获批 spec 的执行单从交付进；直接干从澄清或交付进（跳过设计）；hotfix 从交付段进，修复完成后走 D4 合回集成分支。
- 入口由 agent 判定并报告，用户可按 L0-6 否决；不把已砍掉的「入口选择卡」装回来。
- 跳过不等于免验收：跳过的段没有完成条件，但所到之段的完成条件照旧；L0-6 的计划说明不因跳过而免。
- 段与段之间没有固定顺序要求；同一段可多次进入（如返修回到设计），完成条件不因重复进入而降低。
