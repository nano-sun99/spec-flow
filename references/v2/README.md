## 每层怎么用

- **L0 铁律**：上限 8 条；只有用户能改。铁律与其它层冲突时以 L0 为准。
- **L1 阶段合同**：用完成条件判断这一单能否出段，不按固定步骤走；对外仍是方案期 / 实施期两段。
- **L1 记录**：记录沿用原 issue 交接区；无 issue 由任务 PR 承接；不另建台账。
- **L2 决策目录**：硬闸 = D0-D7 八类决定；八类之外遇到 L0-7 承重缺口同样停。agent 能判的入口/落点/非关键标签不进目录。
- **L3 playbook**：示例，不是必须顺序；标「（规范性）」的闸口章节引用 L0-L2，不新增、不放宽。
- **L4 案例**：只叙述 + 提议，不是法条，不能被引用为授权；影响提议默认无。
- **项目接入**：只做形态映射；采用动作仍以 v1 `references/apply-to-project.md` 为准。

## 边界

- P8 前根 `SKILL.md` 不动；旧 `references/` 不删、不移动。
- v1 与 v2 冲突按 [SKILL.md](SKILL.md) 的规则处理，不静默二选一。
- 本目录只放运行文档与参考正文；盘点、覆盖审计、剧本回放放 `docs/rebuild/`。
