# 规格文档治理总纲

> 本页是「决定索引 / 唯一活动 ID」「跨切面范围盘点表」「摘要与视图权威顺序」「草案替换与重开边界」的**唯一正文 owner**。
> L0–L2、playbook 与审核契约只引用本页，不复述字段或规则定义。按需读取：仅写 / 改 / 审 spec 或执行替换式变更时读。

## 一、单一决定正文与唯一活动 ID

### 1. 正文归属与索引字段

- **已采用 ADR 的项目**：长期决定正文在现行 ADR，spec 只放**决定索引**；未入 ADR 的短期决定仍由 spec **决定节**承接，不强行建 ADR。
- **未采用 ADR 的项目**：spec 设**决定节**，它就是正文，不另建索引。
- **共用字段**：`ID | 决定（一句话） | 来源（用户原话/日期，或 ADR 链接） | 状态（已拍板 / 待核） | 覆盖（章节 / 验收 / 范围盘点表）`。
  - 「覆盖」列合起来即**覆盖图**，按本 spec 记；同一 ADR 被多份 spec 引用时，各自记本 spec 覆盖，不合成全局覆盖图。
  - spec **决定节**另含：适用范围、重开条件。
  - **决定索引**只记本 spec 视角下的拍板状态，不复述 ADR 自身的生效状态、适用范围或重开条件（这些只从现行 ADR 读）。

### 2. 唯一活动 ID

- 格式沿用项目既有约定（ADR 用项目命名，spec 决定节用项目前缀）；同一决定在 ADR 与 spec 间共用同一 ID，不各编一套。
- **短期决定升级为 ADR**：ADR 按项目命名建新 ID，spec 改为引用新 ID，并留一行「原 `<旧 ID>` → `<新 ADR ID>`」迁移别名。
  - 未合并 spec 直接改；已合并 spec 的 ID 迁移只加迁移链接与状态，不改正文（改旧正文须用户确认并按 D3 记录）。
- **ADR 取代**：新 ADR 是新记录、新 ID，旧 ADR 标「已被取代」并互链；取代链与迁移别名不算双编号。
- **命名空间隔离**：闸口 ID（`D0`–`D7`）不属于决定 ID 空间，决定 ID 必须与闸口 ID 可区分。
- **存量双 ID**：在索引补一行映射，不强制重编号；新决定不得再产生双 ID。

## 二、跨切面范围盘点表

- **适用**：同一行为在多入口 / 调用方 / 数据范围重复出现，或访问控制按项目自定义维度（角色 / 租户 / 记录范围等）分层且开 spec。
- **不适用**：非跨切面范围由 D1 目标 / 范围 / 非目标承接；直接干、hotfix、批次修复不建表，写不适用及事实理由。

### 1. 表结构与双重角色

- 一行 = 一个可枚举项（入口、菜单、写入入口或角色 / 租户 / 记录范围等，代码入口作交叉引用）。
- 推荐列：对象 / 范围、调用方 / 数据形态、主处置（项目自定义枚举、优先级与组合规则，一行一值）、附加处置、阶段（单列）、证据、验收。
- **双重角色**：表在「范围枚举」上是唯一正文；在「处置 / 阶段 / 授权 / 例外规则」上只是决定索引的视图。
  - 行项不得超出索引决定覆盖；表自己长出的规则按 spec bug 报。

### 2. 生命周期（seed → 展开对账 → 冻结 → 解冻）

| 时点 | 要求 |
|---|---|
| D1（方案起点） | 确定并冻结项目自定义**枚举口径**（枚举来源 + 匹配规则）与**数量对账计划**（各来源取数命令与总数）；提交表 seed（每来源至少 1 行真实项，只有组名不算）。**视图不得先于表 seed 出现。** |
| D2 确认前 | 按枚举口径展开到逐项，做**数量对账**（每来源条目数 vs 表行数，差异逐条写处置），完成后**冻结**表。D2 证据含：表行数 / 枚举来源数 / 未处置差异数。 |
| D3 合并与实施 | D3 合并的是已冻结的表；实施只交付表内行。 |
| 冻结后新发现（解冻） | 冻结不是停止查漏。影响本期已承诺场景的漏项——**口径内**补表（D2 前重跑对账更新卡；D2 后回 D2；已合并走 D3）；**口径外**新增回 D1。 |

## 三、摘要、视图与唯一权威顺序

- **唯一权威顺序**（全套文档唯一定义）：
  `决定 owner（ADR 或 spec 决定节） > 范围盘点表 > 视图（改造范围 / 分期 / 白名单 / 覆盖矩阵 / 验收清单 / 附录 A.x） > 摘要 / 总纲`
- **规范性句子**（全套文档唯一定义）：含「必须 / 不得 / 一律 / 默认 / 以…为准」的句子。

### 1. 摘要 / 总纲边界

- 仅适用于 D2 起送审的设计终稿内的摘要 / 总纲（旧称总览，同义）；D1「需求摘要」与拆分 spec 的父总纲除外（父总纲是独立 spec）。
- 摘要 / 总纲不是第五种载体，只是 spec 内的一节；只引用 ID，不得新增范围、条件或例外。
- 不含规范性句子且不自称权威的简化复述允许；含规范性句子或自称最高权威 = **多 owner 阻断**；与索引冲突时改摘要。

### 2. 视图回指与引用闭环

- **视图回指率 100%**：按范围行展开的白名单 / 覆盖矩阵 / 验收清单 / 附录 A.x 每行必须回指表行 ID。
  - 单行回指 1 个 ID；聚合 / 负例 / 重叠行回指 ID 列表并标注类型；无法回指任何表行 = **阻断**。
  - 视图与表计数不必相等，但每项差异须写明类型与处置，未写处置 = **阻断**。
  - 全局验收项、非范围附录行标「非范围项」并写事实理由，不算表外行。
- **决定引用闭环**：规范性段落与验收行至少回指 1 个决定 ID（视图行回指表行 ID）。
  - 引不出 = spec bug：D2 确认前标「待核」并补齐，D2 确认后阻断，已合并回 D3。
  - 索引里有、正文无落点的**孤儿 ID** = **阻断**。
- **测试句边界**：验收 / 批次 / 附录写可判对错的测试句，不复述决定理由或范围；同一决定两处出现冲突的结论 / 范围 / 条件 = **阻断**。

### 3. 决定 owner 对账字段（D2 与审核共用唯一定义）

| 字段 | 含义 |
|---|---|
| 决定数 | 本 spec 决定索引 / 决定节的活动决定条数 |
| owner 文件:节 | 每个决定 ID 对应的唯一正文位置 |
| 摘要处 | 文内摘要 / 总纲的位置清单及是否含规范性句子 |
| 视图数 | 改造范围 / 分期 / 白名单 / 覆盖矩阵 / 验收清单 / 附录 A.x 的数量与回指核对结论 |
| 规范性复述处 | owner 之外出现规范性句子的清单及回指状态 |

## 四、草案替换、重开边界与替换式变更

- **草案原位替换**：未合并、无人依赖的草案，可按现行决定原位替换旧条款和相反验收，不算重开。
- **已拍板 / 已生效决定的重开边界**：除 L0-6 范围变化外，仅在以下情形触发重开回对应闸口（不等于直接改设计）：
  1. 新查到的代码或生产事实（含既有代码）；
  2. 决定正文自相矛盾；
  3. 本期已承诺场景会失败。
  - 纯审核角度或实现细节不构成重开。
- **替换式变更**：修改判据、术语、范围、owner、边界或分类（含改变既有行为的新增与退役旧规则）时：
  - 须建立旧→新处置台账、按载体表分流（[15-records](15-records.md) §四）、跑双扫描（活跃残留 + 反向冲突）与重建判定。
  - 只改错字 / 措辞且不改变判定 / 范围 / 默认 / 权限的，不触发。
  - 具体 manifest schema 与跨项目校验工具 `scripts/check-change.py` 见 [change-protocol](30-playbooks/change-protocol.md)。
- **一般同步（非替换式）**：不改变判定 / 范围 / 默认 / 权限的措辞或引用修正，按语义核对规则正文、实现 / 数据源、验收、跨文档锚点与历史取代链接，不建 manifest。
