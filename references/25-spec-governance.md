# 规格文档治理总纲

> 本页是「精简底座 + 3 按需治理组件」「决定索引 / 唯一活动 ID」「跨切面范围盘点表」「摘要与视图权威顺序」「草案替换 / 重开边界与中途平滑升级」的**唯一正文 owner**。
> 阶段完成条件、反熵增三问与竣工回写见 [10-stages](10-stages.md)。写 / 改 / 审 spec 或替换式变更时按需读。

**单一精简底座 + 3 个客观事实触发组件**（不开场主观猜轻重）：
- **精简底座（所有开 spec 共用）**：4 列简版决定表（§一.1），守单 owner、无双活动 ID 与权威顺序底线。
- **组件 1（跨切面范围盘点表，§二）**：同一行为跨多入口 / 调用方 / 数据范围，或按角色 / 租户 / 记录范围分层权控时触发。
- **组件 2（多文档 / 多视图治理，§一完整列 + §三）**：拆子 spec、新增 / 取代 / 协同现行 ADR 或文内出现派生视图（§三）时触发；未触发不强制覆盖列、5 字段 owner 对账、视图回指与逐句规范性回指。
- **组件 3（替换式变更 manifest，§四 + [change-protocol](30-playbooks/change-protocol.md)）**：修改 PR `base` 既有判据 / 术语 / 范围 / owner / 边界 / 分类时触发；未改既有规则或旧 ADR 的纯新增功能 / 纯新增 ADR 不触发。

## 一、单一决定正文与唯一活动 ID

### 1. 正文归属与索引字段

- **已采用 ADR**：长期决定正文在现行 ADR，spec 放**决定索引**（触发组件 2）；未入 ADR 的短期决定仍由 spec **决定节**承接。**未采用 ADR**：spec **决定节**即正文，不另建索引。
- **简版决定表（精简底座，4 列）**：`ID | 决定（一句话） | 来源（用户原话/日期） | 状态（已拍板 / 待核）`。保留简洁 ID 以便中途升格零重编，不强求覆盖列、适用范围 / 重开条件或 5 字段对账。
- **完整字段（组件 2）**：在简版补 `覆盖（章节 / 验收 / 范围盘点表）` 列（合称**覆盖图**，按本 spec 记，多 spec 不合全局图）；spec 决定节另含适用范围与重开条件；决定索引来源写 ADR 链接、只记本 spec 视角拍板状态，不复述 ADR 生效状态 / 范围 / 重开条件。

### 2. 唯一活动 ID

- 沿用项目命名约定，同一决定在 ADR 与 spec 共用 ID；闸口 ID（`D0`–`D7`）与决定 ID 命名空间隔离。
- **短期决定升格 ADR**：ADR 建新 ID，spec 改引新 ID 并留一行「原 `<旧 ID>` → `<新 ADR ID>`」迁移别名（未合并直接改；已合并只加迁移链接与状态，改旧正文走 D3）。
- **ADR 取代**：新 ADR 建新 ID，旧 ADR 标「已被取代」并互链；取代链与迁移别名不算双编号。存量双 ID 在索引补映射，新决定禁双 ID。

## 二、跨切面范围盘点表

- **适用**：同一行为跨多入口 / 调用方 / 数据范围，或按自定义维度分层权控且开 spec。非跨切面由 D1 范围承接；直接干 / hotfix / 批次修复不建表并写理由。
- **结构与双重角色**：一行 = 一个可枚举项（代码入口作交叉引用）；推荐列：对象 / 范围、调用方 / 数据形态、主处置（一行一值）、附加处置、阶段、证据、验收。表在「范围枚举」上是唯一正文，在「处置 / 阶段 / 授权 / 例外」上只是视图——行项不得超底座 / 索引决定，自长规则按 spec bug 报。

| 时点 | 生命周期要求（seed → 展开对账 → 冻结 → 解冻） |
|---|---|
| D1 | 定并冻结**枚举口径**（来源 + 匹配）与**数量对账计划**（取数命令与总数）；交表 seed（每来源 ≥ 1 真实行，组名不算）。**视图不得先于 seed。** |
| D2 前 | 展开至逐项并做**数量对账**（每来源条目 vs 表行数，差异逐条写处置），完成后**冻结**。D2 证据含表行数 / 来源数 / 未处置差异数。 |
| D3 与实施 | 合并已冻结表；实施仅交付表内行。 |
| 冻结后解冻 | 影响已承诺场景的漏项：**口径内**补表（D2 前重对账；D2 后回 D2；已合并走 D3）；**口径外**新增回 D1。 |

## 三、摘要、视图与唯一权威顺序

- **唯一权威顺序**（全套唯一定义）：`决定 owner（ADR 或 spec 决定节） > 范围盘点表 > 派生视图 > 摘要 / 总纲`
- **派生视图界定**（触发组件 2）：独立摘要 / 总纲节，或按盘点表 / 决定表重复展开的白名单、覆盖矩阵、分期表、改造范围表、按范围展开的验收清单 / 附录 A.x；**显式排除**单文档底座常规验收标准与改动文件表。
- **规范性句子**（全套唯一定义）：含「必须 / 不得 / 一律 / 默认 / 以…为准」的句子。
- **摘要 / 总纲边界**：仅指 D2 起终稿内摘要 / 总纲（非 D1 需求摘要或独立父总纲）；只引 ID、禁新增范围 / 条件 / 例外；不含规范性句子且不自称权威的复述允许，反之 = **多 owner 阻断**；冲突时改摘要。
- **视图回指与闭环（组件 2）**：
  - **视图回指 100%**：按范围展开视图每行须回指表行 ID（单行 1 ID；聚合 / 负例 / 重叠行 ID 列表 + 类型；无回指 = **阻断**）；差异未写处置 = **阻断**；全局 / 非范围项标「非范围项」及理由。
  - **引用闭环**：规范性段落与验收行至少回指 1 决定 ID（引不出 = spec bug：D2 前标「待核」补齐，D2 后阻断，已合并回 D3）；索引有正文无落点的**孤儿 ID** = **阻断**。
  - **测试句边界**：验收 / 附录写可判对错测试句，不复述理由；同决定两处结论 / 范围 / 条件冲突 = **阻断**。
- **决定 owner 对账（组件 2 必填 5 字段，单文档底座免填）**：`决定数`（活动条数）｜ `owner 文件:节`（每 ID 唯一正文）｜ `摘要处`（位置与是否含规范性句）｜ `视图数`（数量与回指结论）｜ `规范性复述处`（owner 外规范性句与回指状态）。

## 四、草案替换、重开边界与替换式变更

- **草案原位替换**：未合并、无人依赖草案可按现行决定原位替换旧条款与相反验收，不算重开。
- **已拍板重开边界**：除 L0-6 范围变化外，仅三类触发重开回对应闸口：① 新代码 / 生产事实；② 决定自相矛盾；③ 本期已承诺场景会失败（纯审核角度 / 实现细节不算）。
- **替换式变更（组件 3）**：修改 PR `base` 既有判据 / 术语 / 范围 / owner / 边界 / 分类（含改既有行为的新增、退役旧规则、取代旧 ADR），须建旧→新处置、按载体表（[15-records](15-records.md) §四）分流、跑双扫描与重建判定，校验详见 [change-protocol](30-playbooks/change-protocol.md)。纯改错字 / 措辞不改判定 / 范围 / 默认 / 权限，或未改既有规则 / 旧 ADR 的纯新增功能与纯新增 ADR 不触发。
- **一般同步**：不改判定 / 范围 / 默认 / 权限的措辞或引用修正，语义核对正文 / 验收 / 锚点 / 取代链，不建 manifest。

## 五、治理组件中途平滑升级

澄清 / 设计 / 审核修订（R1–R3）中首次出现组件 1 / 2 / 3 客观事实时，按两步升格：

1. **前置防假膨胀（L0-6 + #158）**：先停问用户是否真要扩范围或引新机制（可选「砍扩张路径 / 写明本期不保证」），禁借审核滚成重工程。
2. **确认后原位升格（零推倒、不重编底座 ID）**：
   - **组件 1**：回 D1 冻枚举口径与对账计划，原位补 seed → 展开对账 → 冻结。
   - **组件 2**：底座 4 列决定表原位补「覆盖」列、范围 / 重开条件（未入 ADR 时）、5 字段 owner 对账与回指闭环；短期决定升 ADR 按 §一.2 留迁移别名。
   - **组件 3（含取代 PR `base` 旧 ADR 或改既有规则 / owner）**：在触发**当轮修订提交内**以当前 PR `base` 起草 manifest（`head: "HEAD"`）跑 `check-change.py --draft` 带入复审，禁拖到合并前才后补；
     - 全部修订闭合、摆 D3 / D4 ② 卡前补 `approval` 做 `manifest-only` 钉扎提交跑正式校验绿；**纯新增 ADR**（未改既有规则 / 未取代旧 ADR）仅走组件 2，不触发 manifest。
   - **闸口与轮次**：升格改文档结构 / owner / 盘点表使 D2 失效（口径外新增回 D1）；下轮按 [26-review-contract](26-review-contract.md) §二 全量重核，仍计入当前 R1–R3 额度，不重置轮次。
