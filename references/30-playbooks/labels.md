# Playbook: 标签（阶段与类型，选修）

> **适用**：仅已采用 `issue-status` 或 `issue-type` 项目；标签是视图非状态机，不证任务完成。

## 一、阶段与卡点标签（`issue-status`）

流向：`未开始 → 进行中 → 待测试 → 测试完成 → 待上线 → 待验证`（**关单是动作，非标签**）；卡点 `等拍板` / `受阻` 可叠加任一阶段。

| 标签 | 对应事实 | 下一步谁动 |
|---|---|---|
| `未开始` | 已开单未认领 | 认领者 |
| `进行中` | 已认领，改动未合入 issue 分支 | 实施者 |
| `待测试` | 预期 PR 均合入 issue 分支且构建过 | 实施者（按 spec 验） |
| `测试完成` | issue 分支验收通过、证据已回填 | 实施者 / 合并者 |
| `待上线` | 整条已合入候选（staging；不可逆） | owner 同意跟班车 |
| `待验证` | 已上线，剩主动生产验项或获批长尾项 | 实施者 |
| `等拍板` / `受阻` | 卡 owner 决策 / 卡外部条件 | 解除即摘 |

- **「下次看」行**：`⏰ 下次看：YYYY-MM-DD · 看什么`，放 issue 正文首行，`待验证` / `受阻` 必填。
- **上线分拣**：逐条问未勾验收项能否主动验——能留 `待验证`；不能但方案期已批留至截止日；未批转出不挡关单并评论核对时机。
- **只读盘点**：「盘一下 issue」按到期 → 等拍板 → 分阶段输出并列可疑项（缺 / 多阶段标、缺「下次看」、无效日期、停滞 ≥ 14 天），只报不改，批量改标须过目。老单旧标只报不自动迁。

## 二、类型标签与迁移（`issue-type`）

8 类小写裸名，一单 1 主类型（`security` 可叠加 `bug` / `feat`），拿不准先问（坏了是 `bug`，预期新增是 `feat`）：
`feat`（原 `enhancement`/`type:feat`）｜`bug`（保留默认；并入 `type:fix`，不建 `fix`）｜`docs`（原 `documentation`/`type:docs`）｜`refactor`（原 `type:refactor`）｜`perf`（须有可比指标）｜`test`｜`chore`（原 `type:chore`）｜`security`（可叠加）。

- **机械迁移（open + closed）**：目标不存在直接 `gh label edit` 改名；目标已存在先报，点头后逐单加目标再删旧标；任一 `gh` 失败即停。
- **语义回填（仅 open，closed 不补）**：拉无类型 open 单交用户抽检（不明标「待定」），点头挂标；中文旧词只报不自动映射。同名已存在不覆盖颜色描述，删旧标须过目。

## 三、常见坑与指针

- **坑**：标签当状态机或静默盖过交接区冲突；PR 写 `Closes`/`Fixes`/`Resolves` 自动关单跳分拣；盘点顺手改标或篡改已关历史单。
- **指针**：三确认项（[20-decisions](../20-decisions.md#标签确认与观察式例外)）、[15-records](../15-records.md) #10 与 §三、[10-stages](../10-stages.md)、采纳命令见 [50-adapters](../50-adapters/README.md) §三。
