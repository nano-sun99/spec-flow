# Playbook: 标签（阶段与类型，选修）

> **适用条件**：仅对已采用 `issue-status` 或 `issue-type` 模块的项目生效；标签是视图而非状态机，不证明任务完成。

## 一、阶段与卡点标签（`issue-status`）

阶段流向：`未开始 → 进行中 → 待测试 → 测试完成 → 待上线 → 待验证`（**关单是动作，不是标签**）；卡点标签 `等拍板`、`受阻` 可叠加在任一阶段上。

| 标签 | 对应事实 | 下一步谁动 |
|---|---|---|
| `未开始` | 已开单尚未认领 | 谁认领谁动 |
| `进行中` | 已认领，改动未合入 issue 分支 | 实施者 |
| `待测试` | 预期交付 PR 均已合入 issue 分支且构建通过 | 实施者（按 spec 验收） |
| `测试完成` | issue 分支验收通过、证据已回填 | 实施者或合并者 |
| `待上线` | 整条 issue 已合入候选（staging 线；不可逆） | owner 同意后跟班车发版 |
| `待验证` | 已上线，剩我方主动在生产验证项或获批长尾项 | 实施者 |
| `等拍板` / `受阻` | 卡在 owner 决策 / 卡在外部条件 | 解除即摘 |

- **「下次看」行**：`⏰ 下次看：YYYY-MM-DD · 看什么`，放 issue 正文首行；`待验证` / `受阻` 必填。
- **上线时分拣**：逐条问未勾验收项「现在能否由我方主动验」——能则留 `待验证`；不能但方案期已批则留到截止日；未批则转出不挡关单，当场评论核对时机。
- **盘点（只读）**：「盘一下 issue」按到期 → 等拍板 → 分阶段输出，并列可疑清单（无阶段标、多阶段标、缺「下次看」、日期无效、停滞 ≥14 天）；盘点只报不改，批量改标须先过目。
- **老单不自动迁**：语义重叠旧状态标只报告；迁老单另开 issue 并先过目清单。

## 二、类型标签与迁移（`issue-type`）

8 类裸名小写，一单一个主类型（`security` 可叠加在 `bug` / `feat` 上）；类型不是阶段、范围或优先级，拿不准先问（行为坏了是 `bug`，按预期新增是 `feat`）。

| 标签 | 适用含义 | 边界 / 迁移来源 |
|---|---|---|
| `feat` | 新功能或能力变更 | 原 `enhancement`、`type:feat` |
| `bug` | 行为不符合预期（含故障 / 回归） | GitHub 默认保留；原 `type:fix` 并入此项，不建 `fix` |
| `docs` | 文档、spec、README | 原 `documentation`、`type:docs` |
| `refactor` | 不改外部行为的重构 | 原 `type:refactor` |
| `perf` | 性能优化（须有可对比指标） | 新建 |
| `test` | 测试、用例、测试基建 | 新建 |
| `chore` | 依赖、构建、CI、配置、杂务 | 原 `type:chore` |
| `security` | 安全整改或漏洞 | 可叠加在 `bug` / `feat` 上 |

**首次采用迁移与回填口径**：
- **机械迁移（覆盖 open + closed）**：目标名不存在则直接 `gh label edit` 改名保留挂单；目标名已存在则先报告，用户点头后逐单加目标标再删旧标。任一 `gh` 写操作失败即停，不跳过。
- **语义回填（仅 open，closed 不补）**：拉全部无类型 open 单，提议清单交用户抽检（判不准标「待定」），点头后挂标；中文旧词只报告不自动映射。
- **幂等保护**：同名已存在不覆盖颜色与描述，只报差异；删旧标前须先过目清单。

## 三、常见坑

- 把标签当状态机，或在标签与交接区正文冲突时静默选一边继续。
- PR 写 `Closes` / `Fixes` / `Resolves` 导致合并瞬间自动关单跳过分拣。
- 盘点顺手批量改标签，或回填类型时篡改已关闭历史单。
