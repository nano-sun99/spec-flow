# Playbook: 新需求开 spec（含成熟度与拆分）

> **示例非必须**：本页是参考走法与表达指南，不新增格式闸或审批阶段；闸口以 L0–L2 及专项总纲为准。

- **适用**：新需求值得先设计（多端、承重规则、外部契约、不可逆动作），或用户选择开 spec；以及评估「拆 / 不拆」与组织交付物地图。既有 issue 实施不从本页开场。

## 一、从澄清到终稿（同一份 spec、同一个 PR）

草稿骨架、对照、终稿是同一份文件的成熟度，不是三道审批或三次派审。

1. **入口澄清**：先核用户原话、项目事实与获批材料；已有答案直接引用，不追问。仅对影响目标、范围、验收、权限或数据的真实缺口，按 [20-decisions](../20-decisions.md#交互卡片契约) 发业务选项卡。
2. **定范围与结构（D1）**：一次列齐目标、范围、非目标、验收、页面 / 无页面、拆 / 不拆、观察式例外（如适用）、承重未知与**反熵增三问初稿**（[10-stages](../10-stages.md)）；跨切面需求按 [25-spec-governance](../25-spec-governance.md) §二 附范围盘点表 seed 与枚举口径。
3. **公共骨架**：按 [25-spec-governance](../25-spec-governance.md) 精简底座起草简版决定表与最少正文承接已定范围与验收，标出未解问题；仅在客观触发组件 1 / 2 / 3 时补齐对应组件（中途触发按 §五 原位升格，不重编底座 ID）。跨切面需求先立表 seed，再写视图。
4. **对照**：
   - **有页面**：等用户设计稿到位，沿实际行为核对角色、交互、状态、数据、异常、权限与接口读写；不代画、不猜完整接口。
   - **无页面**：用最便宜可判对错的材料（命令 / 输入输出 / 退出码、接口请求响应与错误重试、决策表）；不为凑样例数虚构数据。
   - **能判错的业务例子**：两种形态都先选 1 个能推翻方案的具体例子（如历史值 123 / 当前值 456），沿真实读写路径核入口、取值来源与最终显示 / 写入，分清用户决定、已查事实与待核假设。
5. **终稿**：回写同一正文，写实反熵增三问（具体路径 / 规则节 / 唯一现状文档），确保规则、接口、异常 / 兼容、数据迁移 / 回滚与验收一致；按 [25-spec-governance](../25-spec-governance.md) 补齐简版决定表及实际触发的按需组件（未触发组件 2 不强求覆盖图与 5 字段 owner 对账）；触发组件 3 按 [change-protocol](change-protocol.md) 交 manifest。
6. **送审、合并与停（D2 → D3 → D0）**：先跑文档检查，再按 D2 选审核档位与修订范围（审核按 [26-review-contract](../26-review-contract.md)）；修订完成后走 D3 合并 spec 并建执行 issue，然后**停下等 D0 明确实施委托**。

## 二、拆分评估与交付物地图

1. **按可验收成果拆**：看目标、改动面与语义依赖，不按行数、目录或会话长度硬拆。
2. **给真实比较（作为 D1 推荐输入）**：对比每个候选子件的产出、范围、阶段、依赖、并行能力及维护代价；工期不确定标估计。
3. **拆后组织**：拆成 N 份对应 `1 总纲 + N 执行 spec + N 执行单 + 1 跟踪父单`；总纲只留共享设计与索引，不重复派全范围任务。
4. **交付物地图与依赖边**：写清稳定身份编号（不随排期重编）、产出 / 消费边界、共享件归属与「提供方 → 消费方」有向依赖边（具体契约 / 数据 / 运行时产物、就绪条件、证据、责任方、挡哪一步）。
5. **三种就绪分开**：能开工 ≠ 能合入 ≠ 能上线；文件重叠不自动等于语义依赖；父子归属不是阻塞（不必等父单关才开工）。
6. **后加子件**：对照现行设计来源写清变化并同步地图 / 依赖；需改已合并正文时回 D3 / D2，不借新子件悄悄覆盖旧决定。

## 三、DoR 表达边界

允许表格、段落或图表达，固定列数 / 样例数 / 岔路数均不是格式闸（项目明确约定的格式除外）。终稿须可核：承重规则一致且无未解承重项、关键决定来源可核、行为有触发 / 响应 / 失败态、验收可执行、数据与外部契约影响明确（或写不适用及理由）、文档治理与已采用 ADR 符合 [25-spec-governance](../25-spec-governance.md)。

## 四、常见坑

- 把未答推荐项写成已定范围；或把骨架 / 对照版当合同送合并。
- 把「方案确认」当成送审、合并或实施授权（L0-5 三者独立）。
- 把 CLI 输出 / 报表 / 接口误判为页面，或借「无页面」跳过接口分析。
- 把跨切面盘点表留到实施期再展开；或在已合并 spec 上直接改正文。
- 漏填反熵增三问（重叠盘点 / 减法清单 / 现状真身落点），或对普通单文档底座强套重型覆盖图与盘点表。
- 拆完只划文件地盘、不写语义依赖，或把「需同批上线」误判成拆分失败。
