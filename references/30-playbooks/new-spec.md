# Playbook: 新需求开 spec（含成熟度与拆分）

> **示例非必须**：本页是参考走法，不新增格式闸或审批段；闸口以 L0–L2 与 [25-spec-governance](../25-spec-governance.md) 为准。

- **适用**：值得先设计的新需求（多端、承重规则、外部契约、不可逆动作）或用户选择开 spec；以及评估拆 / 不拆。既有 issue 实施不从本页开场。

## 一、从澄清到终稿（同一份 spec、同一个 PR）

骨架、对照、终稿是同一份文件的成熟度，不是三道审批或三次派审。

1. **澄清**：先核原话 / 事实 / 获批材料，已有答案直接引；仅对承重缺口按 [20-decisions](../20-decisions.md#交互卡片契约) 发业务选项卡。
2. **定范围（D1）**：列目标 / 范围 / 非目标 / 验收 / 页面 / 拆不拆 / 观察式例外 / 承重未知与**反熵增三问初稿**（[10-stages](../10-stages.md)）；跨切面另附 seed 与枚举口径（[25-spec-governance](../25-spec-governance.md) §二）。
3. **骨架**：按精简底座起草 4 列决定表与最少正文；仅客观触发组件 1/2/3 时补齐（中途按 25-spec-governance §五 原位升格，不重编 ID）。跨切面先 seed 后视图。
4. **对照**：有页面等设计稿沿行为核角色/状态/权限/接口；无页面用最便宜可判材料（命令/输入输出/退出码/决策表）；均选 1 个可推翻方案的具体业务例子沿真实读写路径核对。
5. **终稿与送审（D2 → D3 → D0）**：回写同文写实三问终稿、异常 / 迁移 / 回滚与触发组件（组件 3 走 [change-protocol](change-protocol.md)）→ 跑文档检查 → D2 选审 → D3 合并并建执行单 → **停等 D0 委托**。

## 二、拆分与 DoR

- **按可验收成果拆**（不按行数 / 目录 / 会话长度）；D1 对比子件产出、依赖、并行与维护代价。N 份对应 `1 总纲 + N 执行 spec + N 执行单 + 1 跟踪父单`，写稳定编号、边界与有向依赖边；能开工 ≠ 能合入 ≠ 能上线，文件重叠 ≠ 语义依赖，父子归属不挡开工；后加子件同步地图，改冻结正文回 D3 / D2。
- **DoR 与常见坑**：表达形式不限，须无悬空承重项、来源可核、验收可执行、治理合规。**坑**：把未答推荐当范围；方案确认当送审/合并/委托（L0-5）；CLI/报表误判页面；盘点留实施展开；直改冻结 spec；漏三问或对单文档强套覆盖图；拆完漏语义依赖。
