# Playbook: 发布（常规批次 / 批次失败修复 / 生产分支快照）

> **适用条件**：仅对**已采用 `release` 模块**的项目生效（单主线 / 三层 / staging 线）；未采用项目跳过发布段，不新增分支、tag 或部署义务。
> **规范性范围**：§一 为「发布安全不变式」的**唯一正文 owner**；§二–§四 为参考走法，硬闸见 L0–L2。

## 一、发布安全不变式

> 规范性，唯一正文。违反以下任一条均属 L0-1 不可逆 / 高风险动作，未经用户明确确认严禁执行：

1. **只从不可变 tag 构建**：不从任何分支 HEAD 构建生产版本。
2. **生产分支树一致性**：三层 / staging 线生产分支的树必须等于最近成功生产 tag 的树；不用 `merge` / `reset` / `read-tree` 覆盖生产快照。单主线只要求 tag 不可变且构建自 tag，不要求主线树等于旧 tag。
3. **tag 不可变**：生产 tag（及已验证临时 tag）不移动、不删除；打错的 tag 原位保留并在发布记录标废弃。
4. **工作区与历史安全**：不在生产分支 revert 未上线内容；不在共享主仓切分支或做快照；不直改另一个 worktree 已检出的引用。
5. **保护分支边界**：保护分支直推不在普通授权范围内。

## 二、常规发布（批次 → rc → 生产）

1. **读项目映射**：核项目指令里的分支形态、实际分支名、版本规则、发布手册与监控口径，不硬套示例名。
2. **定批次范围**：范围 = 上一个实际生产 tag（含 hotfix tag）..当前候选；按 PR「关联 issue：#N」归位；**直接干任务按分支、PR、commit 与验收证据手工列入**；未知 / 搭车项显式纳入或移出；已随 hotfix 上线的提交排除。
3. **批次测试**：在当前候选 HEAD 构建、部署测试环境跑回归与跨 issue 验收；候选有新合入即失效，打最终 tag 前须重跑。
4. **rc 附注 tag 与验收**：在通过批次测试的提交打附注 tag（如 `-rc.1`），从该 tag 构建并部署测试环境跑验收（不做 15 分钟监控）。
5. **D6 发布批准**：按 [20-decisions](../20-decisions.md) D6 摆齐全部证据（最终 tag 须指向与 rc 同一提交，批准后才创建）。
6. **最终 tag、部署与监控**：批准后在同一提交打附注最终 tag，只从该 tag 构建并部署生产；启动 15 分钟生产监控（按项目手册）；崩溃或异常按 L0-4 停住上报，**不自动回滚**。
7. **生产分支快照与回填**：监控通过后按 §四 做生产分支快照，回填发布记录，并经用户确认更新标签与关单。

## 三、批次测试失败修复（fix）

1. **停住记录**：失败即停（L0-4），按 [15-records](../15-records.md) 原任务字段记录输入、预期、实际、证据、结论与范围，不改写成通过或静默重试。
2. **定位归属**：凭真实日志 / 构建 / 验收证据判定归属（某 issue、环境或组合交互）。
3. **切修复分支**：从当前候选切 `fix/<N>-<slug>`（直接干切 `fix/<slug>`），**不回已冻结的 issue 或 task 分支**。
4. **最小修复与 D4**：只修失败点，修复 PR 按 D4 审核并合回候选；**「待上线」标签不回退**（失败记入记录）。
5. **重跑批次**：合入候选后重跑完整批次测试；若范围、排除项或回滚目标变化，原 D6 批准失效，须重新摆卡。

## 四、生产分支快照（main 分叉处理）

1. **核事实**：`git fetch origin --tags`，核成功 tag 为附注 tag（`git tag -a`）及其完整提交、生产分支当前提交。
2. **单主线且可快进**：将生产分支快进到最终 tag 同一提交。
3. **三层 / staging 分叉快照**：在独立 worktree 中，以成功 tag 的树为内容、以原生产分支 HEAD 与 tag 提交为双父创建快照提交并推送（保留 tag 祖先链以维持 `git describe` 可达性），不移动 tag、不碰共享主仓引用。
4. **核树一致**：`git fetch` 后跑 `git diff --quiet <tag> origin/<prod>` 必须退出码 0；不一致即停。快照后的台账与开发提交进开发线，不倒灌固定 tag。

## 五、常见坑

- 从 HEAD 构建，或 rc 与最终 tag 指向不同提交。
- 批次失败回退「待上线」标签，或在已冻结的 issue 分支继续提交。
- 把 `待上线` 标签或 `tag 已打` 当成已验证 / 所有服务实时同版。
- 用 merge / reset / read-tree 覆盖生产分支，或快照提交丢失 tag 父提交。
