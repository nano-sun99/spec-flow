# Playbook: 发布（常规批次 / 批次失败修复 / 生产分支快照）

> **适用**：仅已采用 `release` 模块的项目（单主线 / 三层 / staging 线）；未采用跳过发布段。§一 为「发布安全不变式」**规范性唯一正文**；§二–§四 为参考走法。

## 一、发布安全不变式

> 规范性唯一正文。违反任一条均属 L0-1 不可逆 / 高风险动作，未经用户明确确认严禁执行：

1. **只从不可变 tag 构建**：禁从任何分支 HEAD 构建生产版本。
2. **生产分支树一致**：三层 / staging 线生产分支树须等于最近成功生产 tag 树，禁 `merge` / `reset` / `read-tree` 覆盖；单主线只要求 tag 不可变且构建自 tag。
3. **tag 不可变**：生产 tag 及已验临时 tag 不移动、不删除；打错原位保留并在发布记录标废弃。
4. **工作区与历史安全**：不在生产分支 revert 未上线内容；不在共享主仓切分支或做快照；不直改另一 worktree 已检出引用。
5. **保护分支边界**：保护分支直推不在普通授权内。

## 二、常规发布（批次 → rc → 生产）

1. **映射与范围**：按项目指令取真实分支、版本与监控手册；范围 = 上个生产 tag（含 hotfix）..当前候选，按「关联 issue：#N」归位，**直接干手工列入**，显式处置搭车项，排除已随 hotfix 上线提交。
2. **批次测试与 rc**：候选 HEAD 部署测试跑回归与跨单验收（新合即失效，最终 tag 前重跑）；通过提交打附注 `-rc.1` 构建验收（不做 15 分钟监控）。
3. **D6、部署与监控**：摆齐 [20-decisions](../20-decisions.md) D6；批准后同提交打最终附注 tag，只从该 tag 部署并监控 15 分钟（异常按 L0-4 停报，**不自动回滚**）；通过后按 §四 做快照、回填并确认换标关单。

## 三、批次测试失败修复（fix）

1. 失败按 L0-4 停并按 [15-records](../15-records.md) 原任务字段留证，凭真实日志 / 验收定位归属。
2. 从当前候选切 `fix/<N>-<slug>`（直接干 `fix/<slug>`），**不回冻结 issue / task 分支**；最小修复走 D4 合回候选，**「待上线」不回退**；合回后重跑批次（范围 / 回滚变则重摆 D6）。

## 四、生产分支快照（main 分叉处理）

1. `git fetch origin --tags`，核成功附注 tag（`git tag -a`）与生产分支提交。
2. **单主线可快进**：快进生产分支至最终 tag 同一提交。
3. **三层 / staging 分叉**：在独立 worktree 以成功 tag 树为内容、原生产 HEAD 与 tag 提交为双父建快照提交并推送（保 `git describe` 祖先链），不移 tag、不碰主仓。
4. **核树一致**：`git fetch` 后 `git diff --quiet <tag> origin/<prod>` 须退出码 0；后续提交进开发线，不倒灌 tag。

## 五、常见坑与指针

- **坑**：从 HEAD 构建或 rc ≠ 最终 tag；批次失败退「待上线」或在冻结分支续提；拿标签 / tag 当已验证；用 merge/reset/read-tree 覆盖生产或快照丢 tag 父提交。
- **指针**：D4 / D6（[20-decisions](../20-decisions.md)）、[10-stages](../10-stages.md) 发布段、[15-records](../15-records.md) §五–§七、[labels](labels.md)、[incident](incident.md)。
