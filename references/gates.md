# 三道闸（规格 / 范围 / 完成）

> 默认面 3 份之一。只写判定；四档差异见 `gate-details.md`，完成例外见 `done-criteria.md`，撞锁见 `worktree-lock.md`。

## 闸一：规格过检查（开工前）

- `spec-check` 绿（E1–E4）；有 error 不开工。
- 三行锚用户点头；「改 / 不改」写清；每条 AC 有验证方法。
- 不审也算过：摆卡即算；agent 不自派审。

## 闸二：范围冻结（实施中）

- 规格冻结后，「改」清单只走变更单。
- 每轮结束跑 `spec-check --base <起点>`：E5 越界 → 停，报告文件，不解释成「顺手」。
- 新东西先写「不做 / 待定」，用户点头才做。

## 闸三：完成（合并 / 关单前）

- AC 表无 ❌；有 ❌ 必须同条写处置（修 / 变更单 / 用户豁免）。
- 验证证据齐全（命令 + 输出 / 截图 / 断言）。
- 观察式收尾：写清观察项、观察期、谁看；否则不算完成。
- 文档检查：有入口就跑，卡上固定一行「绿 / 红+摘要 / 无入口」。

## 审核：四进三出（每份 PR 单独点）

**输入只有四样**（多一样都不给）：

1. AC 清单；
2. 本次 diff + 证据；
3. 上轮 findings；
4. 已拍板决定（D01…）。

**输出只有三列**：`AC | 证据 | 过/不过`；外加一行「范围外 N 条 → 建议池」。

**只判两件**：AC 满足没有；diff 越界没有。风格 / 更优解 / 以后可以 → 建议池。

**轮次**：最多 2 轮；第 3 次不派审，只做「重画 / 砍范围 / 停」三选一，用户拍。

**建议池**：只记录，不派修订、不进下一轮；范围外建议不阻塞合并。

## 三行判定（细则见场景包）

- 修订：改判据 / 定义 / 常量 / 术语 → 全文同步（`spec-revision-sync.md`）。
- 撞锁：分支已存在 = 有人在做；目录没了才 `prune` 接手（`worktree-lock.md`）。
- 观察式完成：不能命令化的验收，写观察项 / 周期 / 责任人（`done-criteria.md`）。
