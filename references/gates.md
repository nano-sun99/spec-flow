# 三道闸（规格 / 范围 / 完成）

> 默认面 3 份之一。只写判定；四档差异 / 多份叠加见 `gate-details.md`，完成例外见 `done-criteria.md`，撞锁见 `worktree-lock.md`。

## 闸一：规格过检查（开工前）

- `spec-check` 绿（E1–E4）；有 error 不开工。
- 三行锚用户点头；「改 / 不改」写清；每条 AC 有验证方法；两张清单有占位。
- DoR 七条（第 1–4 条不得「不适用」）：

1. 承重规则一个结论，无 `TBD`；
2. 每步有触发 → 响应与失败 / 空态；
3. 每条写路径单一入口；状态有字段、有读侧；
4. 每条验收可执行（命令 / 截图 / 断言）；
5. 数据迁移 / 回填 / 回滚 / 兼容写了，或「不适用」；
6. 外部合同影响与版本写了，或「不适用」；
7. ADR 已采用的 supersede 链清楚，未采用写「不适用」。

## 闸二：范围冻结（实施中）

- 转 Ready 后「改」清单冻结；只走变更单。
- 每轮跑 `spec-check --base <起点>`：E5 越界 → 停，报告文件，不解释成「顺手」。
- 新东西先写「不做 / 待定」，用户点头才做。

## 闸三：完成（合并 / 关单前）

- 测试通过；无未处理阻断；AC 表无 ❌；有 ❌ 必须同条写处置（修 / 变更单 / 用户豁免）。
- 验证证据齐全（命令 + 输出 / 截图 / 断言）。
- 观察式收尾是例外，默认不进单；确要观察，写清观察项、观察期、谁看，否则不算完成。
- 文档检查：有入口就跑，卡上固定一行「绿 / 红+摘要 / 无入口」。

## 审核：四进三出（每份 PR 单独点）

**输入**：AC 清单；本次 diff + 证据（含 PR head 代码工作区）；上轮 findings；已拍板决定（D01…）。

**输出**：`AC | 证据 | 过/不过`；外加一行「范围外 N 条 → 建议池」。

**只判两件**：AC 满足没有；diff 越界没有。风格 / 更优解 / 以后可以 → 建议池。

**但阻断 / 高必须转问题，不进建议池**：走不通、证据不可执行、同一决定多 owner、岔路未选、数据 / 安全 / 权限问题一律阻断；会导致返工或跨份不一致的标高。阻断 / 高不合并。

**轮次**：最多 2 轮；第 3 次不派审，只做「重画 / 砍范围 / 停」三选一，用户拍。

**建议池**：中 / 低只记录，不派修订、不进下一轮；范围外建议不阻塞合并。

**记录**：结论原样贴 PR 评论；处置进 spec 末尾「审核修订记录」。不审也要拿 diff 对 spec 改动面自查，范围外停下报告。

## 四档（用户点，agent 不自派）

| 档 | 派什么 | 代价 |
|---|---|---|
| 不审 | 无；agent 自查 diff | 0 |
| 轻审 | 1 个：规格符合性 + 两张清单 | 约 5 分钟 |
| 重审 | 2 个：规格符合性 + 对抗找 bug | 约 10 分钟 |
| 重审 + 变异 | 重审 + 一次变异 | 同重审 + 约 18 秒 |
