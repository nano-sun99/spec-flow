# 审核契约总纲

> 本页是审核档位派发、轮次上限、#158 五机制、严重度、文档检查、文档组织前置检查、豁免 / 写回边界与 Lane A/B 派审模板的**唯一正文 owner**。
> 本页引用 L0–L2 与 [25-spec-governance](25-spec-governance.md)，不新增 D 类型或放宽硬闸。按需读取：准备派审、执行审核或修订复审时读。

## 一、审核档位与派发

档位选择权在用户（[20-decisions](20-decisions.md) D2 / D4 ①），默认「不审」，每份 PR / 阶段当场选，不沿用规格期档位；项目禁用的档位不展示。

| 档位 | agent 数 | 派发方式 |
|---|---|---|
| 不审（默认） | 0 | 主 agent 按 diff 对获批范围与已采用约束自查 |
| 轻审 | 1 | 按交付物类型浅审：文档做 Lane A 浅审（规格符合性 + 方案 / 自定细节）；代码做 Lane B 浅审（对抗找 bug + 范围外对账）；两者都有做 A+B 浅审 |
| 重审 | 2 | Lane A（规格符合性，含适用清单 / 范围）与 Lane B（对抗找 bug）各 1 份，带同一份决定索引 / 决定节与同一组 `base/head` |
| 重审 + 变异 | 2 + 主 agent | 重审 + 主 agent 在独立测试工作区换错判据跑全量相关测试（仍全绿说明没护栏，测完恢复）；无可跑测试如实报无法变异 |

成本口径建议：规格期文档 PR 可建议轻审，重审才 2 个；文件多不自动加人；批次审核须在卡上列每份 PR / 分支并写「N 份 × 该档 = X 个 agent」，文档检查逐成员在其工作区跑并列结果。

## 二、轮次与范围检查

- **R1 全量**：核完整路径、正常 / 失败 / 证据及遗漏分支。
- **R2 默认仅复核**：只核上轮发现是否闭合及新增阻断 / 高；新中 / 低只记录。
- **R3 停**：仍有阻断 / 高即停，由用户选「重画 / 砍范围 / 停」，不派第 4 轮。
- **轮次绑 PR，不绑人或文件**：换 agent、换角度、拆文件均不重置 R1–R3。
- **整案（全文重审）例外**：用户明确要求整案时，当轮给全文并按全量执行，仍占当前轮次。派审前须对齐本次回答「整案」还是「仅复核」；能找到上轮约定则沿用，找不到先问清，不默认缩窄。只做修订复核时标题写「仅复核」，不提前请用户定稿，不简称整案通过。
- **结构变化**：spec 的章节、决定 owner、范围盘点表或权威顺序变化使 D2 失效；回 D2 后下一轮按 R1 全量执行，但仍占当前 R1–R3 额度（已是 R3 则停）。

## 三、严重度与 #158 五机制

### 严重度

- **阻断**：走不通；必要证据不可执行；同一决定多 owner；承重选择未定；数据 / 安全 / 权限问题（不因标中 / 低降格）。
- **高**：导致返工或跨份不一致，但本轮可修。
- **中 / 低**：不挡合并，留未处理项；扩展建议不自动成新机制。

### #158 五机制

1. **成因列**：每条发现标 `甲 · 同步失误` / `乙 · 设计固有` / `丙 · 岔路没拍`（严重度答「挡不挡合并」，成因答「怎么修」）。
2. **能不能不修列**：每条发现标 `必须加规则` / `可砍路径` / `可写明本期不保证` / `不适用（按处置类型走）`。
3. **修订卡可砍范围**：用户可在 D2 / D4 修订卡选「砍掉相关路径」「写明本期不保证」。
4. **甲类只做五问对账，不改设计**：引用的锚点 / 文件 / 章节真的存在吗？机制清单每项都有正文吗？路径每步别处覆盖了吗？声明已建的真建了吗？需人拍板的写进未定项了吗？
5. **每轮范围检查 + 轮次上限**：每轮后问「本轮新增规则里有几条是原问题必需？答不出就是扩了」，并严格执行 R1–R3 上限。

## 四、文档检查与文档组织前置检查

### 1. 文档检查（唯一正文）

- **时点**：交付物为 spec / 纯文档或代码 diff 含文档改动时，**摆派审卡前**在交付物自己工作区跑；选「不审」也先跑。
- **入口发现顺序**：项目指令自报且真实存在 → `scripts/check-docs.sh` → `scripts/check-doc-links.sh` → 无入口（自报路径不存在落下一档；存在但跑不起来 = 红，不冒充无入口）。
- **三态**：`绿` / `红 + 摘要` / `无入口`，卡上固定写结果。
- **处置**：本次 diff 引入的红须修绿再摆卡；无关存量红注明数量 / 摘要与不相关依据，交用户处置（用户可当场明示豁免并记理由）。检查绿与豁免都不授权合并。

### 2. 文档组织四项前置检查

审含 spec / 决定索引 / 范围盘点表的 PR 时，先按 [25-spec-governance](25-spec-governance.md) 做四项对账（无这些对象写「不适用及事实理由」）；下列标「阻断」项任一不成立即直接报阻断、不进逐条内容审核，标「spec bug」项按 [25-spec-governance](25-spec-governance.md) §三.2 阶段判定（D2 前标「待核」补齐，D2 后阻断）：

1. **决定 owner 唯一（阻断）**：无双 owner、摘要不含规范性句子且不自称最高权威、有 spec 不缺决定索引。
2. **范围盘点表唯一**：视图回指 100%、差异逐条处置、跨切面不缺表（不成立 = 阻断）；视图先于表 seed 出现按 spec bug 处理（D2 前补表，D2 后阻断）。
3. **权威顺序唯一（阻断）**：spec 内不改写唯一权威顺序（L0–L2 层级声明不在此列）。
4. **复述处清单（spec bug）**：owner 外规范性句子均能回指决定 ID 或表行 ID；引不出按 spec bug 阶段判定，不算新岔路。

## 五、给材料、报告格式与审核边界

### 1. 给材料清单（主 agent 提供，审核方只读不改、不冻结材料）

- 当前 spec（草稿或获批版；无 spec 用 PR 正文目标 / 范围 / 验收替代并写不适用及事实理由）；
- 决定索引 / 决定节（采用 ADR 时另附短期决定节或写无及理由）与决定 owner 对账（字段见 [25-spec-governance](25-spec-governance.md) §三.3）；
- 范围盘点表相对本 PR `base/head` 或上次冻结版本的 diff（无表写不适用及事实理由）；
- 替换式变更时附 change manifest + `check-change.py` 输出（开发 / 审核期 `--draft`；合并前正式模式；含 rules / whitelist / scans / unresolved 计数与校验摘要）；
- `base/head` 完整 SHA、工作区 / diff 基准、项目入口、已采用约束、现行 ADR（如适用；已作废或已被取代的 ADR 不审）。
- R1 给全文；R2/R3 默认只给上轮发现、闭合证据与新增 diff（整案例外给全文）。

### 2. 报告结构（Lane A / Lane B 区分）

- **报告头（两道共用）**：日期、档位、agent 数（本份 / 总派发）、lane（A/B/A+B）、整案 / 仅复核、阻断 / 高 / 中低计数、核了什么 / 没核什么（结论只覆盖证据证明的范围）；Lane A 另含文档组织对账摘要与关闭项 N 条。
- **Lane A 四段正文**：`已拍板清单`（ID / 来源 / 状态 / 覆盖）→ `关闭清单`（决定 ID / 来源 / 推导链 / 结论）→ `发现列表` → `写回清单`（如有）。
- **Lane B 正文**：仅按 §六 Lane B 契约输出报告头与发现列表（不做推导 / 关闭 / 写回）；主 agent 汇总时按需补决定 ID 映射。
- **关闭项与发现严格分流**：引决定 ID 核对且实现 / 表述未偏离的候选，**只进关闭清单，不进发现列表**；正文与 ID 矛盾或偏离的进入发现列表，数据 / 安全 / 权限 / 不可逆偏离尤其不得关闭。
- **Lane A 每条发现必填字段**：`文件:行` / 问题 / 证据（现状 vs 期望）/ 推导链或「无决定 ID」/ 处置类型 / 严重度 / 成因 / 能不能不修 / 依据决定 ID / 新事实 / 主动改范围。
  - **处置类型（7 类）**：`口径内漏项` / `口径外新增` / `新事实·仅换实现方法` / `新事实·影响已拍板决定` / `按现行决定替换旧条款` / `需裁决` / `实现细节`。
  - 判定顺序：先问「不修，本期哪个已承诺场景会失败」；索引足够且为未合并无人依赖草案时按现行决定替换；「实现细节」不得用于已承诺场景失败；依据决定 ID / 新事实 / 主动改范围三栏均写不出时按 spec bug 处理；无法推导的待核项标状态「待定」，由主 agent 汇总一次问。
- **贴评与收尾**：结论原样贴 PR 评论（无 PR 贴对话），不改写、不删条、不降级；零发现不摆修订卡。修订记录追加到 spec 末尾或原 PR，不重写冻结正文；每次复审重新摆派审卡。

### 3. 边界、豁免与派生条写回

- **独立审核边界**：子 agent 是执行分身，自测 / 草拟 / 检索不能冒称独立审核。审核方只查一致性与找 bug，不产出新决定；需另一方裁决时材料备好后停。
- **免审核闸**：以下三类免单摆审核卡（拿不准时摆卡问；**无 PR 的交付前仍须摆审核卡并给 diff**）：
  - 无新内容的机械编号 / 状态 / 索引 / 验收回填、不进仓草稿（按 D4 默认「不审」处理并报告，含文档改动仍跑文档检查）；
  - D3 / D4 ② 合并确认前按 [change-protocol](30-playbooks/change-protocol.md) 执行的 `manifest-only` 钉扎提交（须跑 `check-change.py` 正式模式绿，合并卡单列内容提交与钉扎提交）；
  - worktree 豁免规则见 [10-stages](10-stages.md) §三（agent 不自判、不主动建议，真并行仓锁仍执行）。
- **派生条写回边界**：审核推导出仅改表述或覆盖图的「由 `<决定 ID>` 推出」派生条（不改范围 / 验收 / 决定正文；仅写草案期 spec 视图或基线 spec 的 issue/PR 修正记录），属 L0-6 机械补稿：
  - 若用户在修订卡明确选「不改」，尊重选择，**不改动文件**；
  - 其余情形（零发现或选改）由主 agent 机械回填并在评论记录，合并卡单列回填提交；机械回填不触发重选审核档位，但须跑文档检查绿。
- **豁免不免合并**：批次审核与任何免审豁免都不免实际存在 PR 的独立合并确认（L0-5）。

## 六、可复制派审契约

### Lane A（规格符合性 / 决定与范围一致性）

```text
你是本次交付的 Lane A 审核方（规格符合性 / 决定与范围一致性）。
只审给出的 diff 与材料，只读不改；修复不由你执行。
「决定 ID」指决定索引 / 决定节的活动 ID（取代链与迁移别名除外，闸口 ID D0-D7 不在此空间）。

1. 先读决定索引 / 决定节与范围盘点表，输出「已拍板清单」（ID / 来源 / 状态 / 覆盖）。
   无 spec 用 PR 正文目标 / 范围 / 验收替代并写不适用及理由。
   材料缺失、字段不全、与正文矛盾或同决定双活动 ID 未给映射时报阻断，不自行补决定。
2. 审核范围：本次 diff、标「待核」的行、已拍板来源之间的矛盾；已拍板决定不复审，但实现落地仍要审。
   先做文档组织四项前置检查（owner 唯一、盘点表与视图回指、权威顺序唯一、复述处清单），任一不成立即阻断。
3. 候选先过已拍板清单，写出推导链（决定 ID → 条款 / 验收 → 结论）：
   - 覆盖且未偏离：记入「关闭清单」（写 ID / 来源 / 推导链 / 结论），不进发现列表；
   - 偏离或矛盾：进发现列表按严重度报（数据 / 安全 / 权限 / 不可逆偏离不得关闭）；
   - 引不出决定 ID：有新事实或主动改范围则进发现并标注；否则按 spec bug 或实现细节处理。
4. 仅三类情况可报「需裁决」（汇总一次，不逐条问）：
   ① 索引不足 / 多 owner / 无法唯一推导；② 新代码或生产事实且既有决定覆盖不到；③ 主动改范围。
5. 摘要与总纲只作视图，与索引冲突先判视图错；范围盘点表枚举是范围正文，处置 / 阶段 / 权限只引决定 ID。
6. 每条发现写齐：文件:行 / 问题 / 证据（现状 vs 期望）/ 推导链或无决定 ID /
   处置类型（7 类之一）/ 严重度 / 成因 / 能不能不修 / 依据决定 ID / 新事实 / 主动改范围。
   数据 / 安全 / 权限问题不降格；轻审文档时发现即报阻断，但不承诺深审。
7. 整案（全文重审）按全量执行，只核一致性不产出新决定；审核方不冻结或修改索引 / 视图。
8. 报告按「报告头 → 已拍板清单 → 关闭清单 → 发现列表 → 写回清单」输出。
   只改表述 / 覆盖图的推导答案进写回清单（标「由 <ID> 推出」）；改变范围 / 验收的标「新决定」。
   零发现、检查绿、审核通过都不等于用户同意合并。
```

### Lane B（对抗找 bug）

```text
你是本次交付的 Lane B 审核方（对抗找 bug）。只审给出的 diff 与材料，只读不改；修复不由你执行。
只报可复现失败场景（文档：按文档执行会失败；代码：输入 / 期望 / 实际）、范围外改动机械对账与测试缺口。
决定与范围一致性判定归 Lane A；不产出决定、不做推导 / 关闭 / 写回、不向用户提问。
每条发现写：文件:行 / 问题 / 复现步骤 / 证据（现状 vs 期望）/ 严重度 / 成因 / 能不能不修；
文档无运行行为时只做链接 / 矛盾 / 范围外机械核对，不硬造复现步骤。
零发现、检查绿、审核通过都不等于用户同意合并。
```
