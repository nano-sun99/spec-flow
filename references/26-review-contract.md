# 审核契约总纲

> 审核档位、轮次上限、#158 五机制、严重度、文档检查、文档组织前置检查、豁免 / 写回边界与 Lane A/B 契约的**唯一正文 owner**；不增 D 类型。派审、审核或复审时按需读。

## 一、审核档位与派发

档位由用户当场选（[20-decisions](20-decisions.md) D2 / D4 ①），默认「不审」，不沿用规格期；禁用档不展示。

| 档位 | agent 数 | 派发方式 |
|---|---|---|
| 不审（默认） | 0 | 主 agent 按 diff 对获批范围与约束自查 |
| 轻审 | 1 | 文档 = Lane A 浅审；代码 = Lane B 浅审；两者皆有 = A+B 浅审 |
| 重审 | 2 | Lane A（规格符合性）与 Lane B（对抗找 bug）各 1 份，共用决定表与 `base/head` |
| 重审 + 变异 | 2 + 主 agent | 重审 + 主 agent 在独立测试区换错判据跑测试（仍绿 = 缺护栏，测完恢复）；无测试如实报 |

成本建议：规格期文档 PR 可建议轻审；文件多不加人；批次审核列每份 PR / 分支并写「N 份 × 该档 = X 个 agent」，文档检查逐成员工作区跑。

## 二、轮次与范围检查

- **R1 全量**：核完整路径、正常 / 失败 / 证据及遗漏分支。
- **R2 默认仅复核**：只核上轮闭合及新增阻断 / 高；新中 / 低只记录。
- **R3 停**：仍有阻断 / 高即停，交用户选「重画 / 砍范围 / 停」，**不派第 4 轮**。
- **轮次绑 PR**：换 agent / 角度 / 拆文件不重置 R1–R3。
- **整案例外**：用户明示整案给全文全量审，仍占当轮。派审前对齐「整案 / 仅复核」（能找上轮约定沿用，否则先问）；仅复核标题写「仅复核」，不提前请定稿，不简称整案通过。
- **结构变化与升格**：章节 / owner / 盘点表 / 权威顺序变或按 [25-spec-governance](25-spec-governance.md) §五 升格使 D2 失效；回 D2 后下轮全量审，仍占 R1–R3（已 R3 则停）。

## 三、严重度与 #158 五机制

- **严重度**：**阻断** = 走不通 / 证据不可执行 / 多 owner / 承重未定 / 数据·安全·权限（禁降格）；**高** = 致返工或跨份不一致但本轮可修；**中 / 低** = 不挡合并留未处理项，建议不自动成新机制。
- **#158 五机制**：
  1. **成因列**：`甲 · 同步失误` / `乙 · 设计固有` / `丙 · 岔路没拍`。
  2. **能不能不修列**：`必须加规则` / `可砍路径` / `可写明本期不保证` / `不适用（按处置类型走）`。
  3. **修订卡可砍范围**：可选「砍掉相关路径」「写明本期不保证」。
  4. **甲类只五问对账不改设计**：锚点 / 文件 / 章节存在吗？机制有正文吗？步骤别处覆盖吗？声明已建真建吗？需拍板入未定项吗？
  5. **每轮范围检查 + 轮次上限**：每轮问「新增规则几条是原问题必需？答不出即扩」，严守 R1–R3。

## 四、文档检查与文档组织前置检查

### 1. 文档检查（唯一正文）

- **时点**：spec / 纯文档或 diff 含文档，**摆派审卡前**在其工作区跑（选「不审」亦跑）。
- **入口**：项目自报且存在 → `scripts/check-docs.sh` → `scripts/check-doc-links.sh` → 无入口（自报不存在落下一档；存在但跑不起来 = 红）。
- **三态与处置**：`绿` / `红 + 摘要` / `无入口` 固定上卡。本 diff 引入红须修绿再摆卡；无关存量红列数量 / 摘要 / 依据交用户（可当场豁免记理由）。绿与豁免不授权合并。

### 2. 文档组织前置检查（底座 + 按需组件）

审含 spec / 决定表 / 盘点表 PR 时，先按 [25-spec-governance](25-spec-governance.md) 对账（无写理由）；「阻断」不成立即停、「spec bug」按 §三 阶段判（未触发组件禁判阻断）：

- **底座必核**：① 简版决定表齐备、承重无悬空、无双活动 ID / 多 owner / 篡改权威顺序（阻断）；② 同文档结论 / 范围 / 验收无矛盾（阻断）；③ 反熵增三问齐备（spec bug）。
- **组件 1（盘点表，可叠加组件 2）**：不缺表（阻断）；表行不超决定（spec bug）；视图不先于 seed（spec bug）；仅组件 1 不因缺覆盖列判阻断。
- **组件 2（多文档 / ADR / 派生视图，可叠加组件 1）**：① owner 唯一（阻断：无双 owner、摘要无规范性句不自称权威、齐覆盖列与 5 字段对账）；② 视图回指 100% 与差异处置（阻断）；③ 权威顺序唯一（阻断，L0–L2 声明除外）；④ 复述处均回指决定 / 表行 ID（spec bug）。

## 五、给材料、报告格式与审核边界

### 1. 给材料清单（主 agent 给，审核方只读不改不冻结）

- 当前 spec（无用 PR 目标 / 范围 / 验收代并写理由）；简版决定表（组件 2 附覆盖列、短期决定与 5 字段对账）；盘点表 diff（无写理由）；`base/head` 完整 SHA、工作区、约束与现行 ADR（作废 / 被取代不审）。
- 触发组件 3（含中途）须当轮附 manifest + `check-change.py --draft` 输出（合并前正式模式；含 `rules / whitelist / scans / unresolved` 计数与摘要）。
- R1 给全文；R2/R3 默认只给上轮发现、闭合证据与新增 diff（整案给全文）。

### 2. 报告结构（Lane A / Lane B）

- **报告头（共用）**：日期、档位、agent 数（本份 / 总）、lane、整案 / 仅复核、阻断 / 高 / 中低计数、核了 / 没核什么；Lane A 另含文档组织摘要与关闭项 N 条。
- **Lane A 四段**：`已拍板清单`（ID / 来源 / 状态；单文档底座可省覆盖列）→ `关闭清单`（ID / 来源 / 推导链 / 结论；覆盖未偏离**只进关闭不进发现**，数据/安全/权限/不可逆偏离禁关闭）→ `发现列表` → `写回清单`（如有）。
- **Lane B**：仅报告头与发现列表（不做推导 / 关闭 / 写回）；主 agent 按需补 ID 映射。
- **Lane A 发现必填**：`文件:行` / 问题 / 证据（现状 vs 期望）/ 推导链或无 ID / 处置类型 / 严重度 / 成因 / 能不能不修 / 依据 ID / 新事实 / 主动改范围。
  - **7 类处置**：`口径内漏项` / `口径外新增` / `新事实·仅换实现方法` / `新事实·影响已拍板决定` / `按现行决定替换旧条款` / `需裁决` / `实现细节`。先问「不修哪个已承诺场景失败」；未合并无人依赖草案按现行决定替换；已承诺失败禁归「实现细节」；三依据空按 spec bug 报；待定项汇总一次问。
- **贴评与收尾**：原样贴 PR 评论（无 PR 贴对话），不改写 / 删条 / 降级；零发现不摆修订卡；修订追 spec 末或原 PR；每次复审重摆派审卡。

### 3. 边界、豁免与派生条写回

- **独立边界**：子 agent 是分身，自测 / 草拟不冒充独立审核；审核方不产出新决定。
- **免审核闸**（拿不准摆卡；**无 PR 交付前仍摆卡给 diff**）：① 无新内容机械编号 / 状态 / 索引 / 验收回填或不进仓草稿（改文档仍跑检查）；② D3 / D4 ② 前 `manifest-only` 钉扎提交（正式绿，合并卡单列）。
- **worktree / 合并边界**：worktree 豁免见 [10-stages](10-stages.md) §三（不免审核与合并）；**任何豁免不免合并确认（L0-5）**。
- **派生条写回**：仅改表述 / 覆盖图的「由 `<ID>` 推出」属 L0-6 机械补稿；选「不改」不动，余机械回填记评论、合并卡单列并跑检查绿，不重选档位。

## 六、可复制派审契约

### Lane A（规格符合性 / 决定与范围一致性）

```text
你是 Lane A 审核方（规格符合性 / 决定与范围一致性），只审给出 diff 与材料，只读不改不修复。
严格按 references/26-review-contract.md §四.2、§五.2 执行：
1. 读决定表 / 盘点表输出「已拍板清单」（单文档底座 4 列即完备，禁因缺覆盖列 / 5 字段对账 / 逐句 ID 判阻断；底座缺项 / 多 owner / 双活动 ID 报阻断；D0-D7 不在决定 ID 空间）。
2. 先做 §四.2 底座 3 项 + 实际触发组件前置检查；只审本次 diff、待核项与已拍板矛盾（实现落地必审）；摘要冲突判视图错。
3. 候选过已拍板写推导链：未偏离只进「关闭清单」；偏离按严重度报（数据/安全/权限/不可逆不降格禁关闭）；仅索引不足 / 覆盖不到新事实 / 主动改范围报「需裁决」（汇总一次）。
4. 按 §五.2 填齐发现字段与 7 类处置，输出「报告头 → 已拍板清单 → 关闭清单 → 发现列表 → 写回清单」（纯表述/覆盖标「由 <ID> 推出」，改范围/验收标「新决定」）。
零发现、检查绿、审核通过都不等于用户同意合并。
```

### Lane B（对抗找 bug）

```text
你是 Lane B 审核方（对抗找 bug），只审给出 diff 与材料，只读不改不修复。
只报可复现失败（文档按执行失败；代码给输入/期望/实际）、范围外改动机械对账与测试缺口；不做决定一致性 / 推导 / 关闭 / 写回 / 提问。
每条写：文件:行 / 问题 / 复现步骤 / 证据（现状 vs 期望）/ 严重度 / 成因 / 能不能不修（无运行行为文档仅核链接 / 矛盾 / 范围外）。
零发现、检查绿、审核通过都不等于用户同意合并。
```
