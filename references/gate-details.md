# 闸口：选项、批准、放行与停止

> 本文件是通用闸口与权限判据的唯一正文；当前流程见 [one-path](one-path.md)，记录字段见 [phase-handoff](phase-handoff.md)，完成判据见 [done-criteria](done-criteria.md)。动作前读取；压缩丢失或版本变化重读。结构搬家不改变审核档位或原有安全授权（依据：rationale R37）。

## 一、选项交互与权限

闸口只回答：决定什么、对象/范围、谁决定、需要什么事实、怎样放行、未满足停哪里。用户决定目标、范围、结构、审核、修订和授权；agent 查事实、给推荐、组织获准工作，不替用户批准。

- 有选项工具时用选项卡；没有时给等价明确选项，等待明确选择。推荐项在前，说明解决什么、不选的影响、主要代价，允许补充；资料不能穷举时允许补充输入，不制造假选项。
- 只问用户能定或必须提供的信息，能查的先查。已有有效确认不因内部方法、写法或节点迁移重问；用户自发明确指令可满足对应决定，不为了使用卡片要求再答一次。
- 卡未答只执行该卡已明确的安全默认，不从沉默扩大授权。用户暂停、撤销或关闭卡时停止受影响动作；没有工具不视为同意。
- 批准绑定当次列明的对象、范围和版本。新增实质内容、换目标、返修、暂停、撤销或要求重审使旧批准不再覆盖；先核差异，回对应确认。单纯补齐既定决定或改变内部方法不自动使有效确认失效。
- 方案、结构、送审、派审、修订、合并、实施、安装和生产是不同权限，不能相互替代。标签、检查绿、零发现、另一个 agent 的意见都不是用户批准。

### 卡片与未答后果

| 决定 | 选项与放行对象 | 未答 / 拒绝时 |
|---|---|---|
| 新需求入口 | 直接干 / 开 spec；选择写当前任务 PR | 不写文件、不代选；明确直接干不重问 |
| 缺梳理依赖安装 | Yes / No；仅卡上列明文件、位置和用途 | 不安装、暂停所需梳理路径，不挡既有实施交付 |
| 同一方案 | Yes / No；当前目标、范围、做法与验收 | 首次 Yes 前不写 spec；No 可重新构思，再确认 |
| 页面 | 有页面 / 无页面；在公共骨架/Draft 后选择 | 停在该选择，不猜设计或自动转分支；已有骨架保留 |
| 公共缺口 | 针对真实未决问题给可行口径及补充入口 | 不把未知写成已决定，不进入结构定稿 |
| 拆分 | 拆 / 不拆；公共缺口闭合后选择结构 | 不推进终稿、不开执行单，不代选 |
| 同意送审 | 送审 / 继续完善；可实施的当份终稿 | 保持 Draft，不转 Ready、不派审 |
| 当份派审 | 不审 / 轻审 / 重审 / 重审 + 变异 | 按不审自查，不派 agent；不含合并同意 |
| 按发现修订 | 全改 / 只改阻断 + 高 / 不改 | 不自动改、不合并；选不改且有阻断/高也不合并 |
| 观察式例外（条件性） | 纳入 / 不纳入；适用类型和必要信息见 done-criteria | 默认不纳入，不以未答补批准 |
| 改已合并 spec（条件性） | 新开一份 spec / 改旧的 | 不动已冻结正文；未合并的同稿完善不触发 |
| 合并 | 合并 / 先不合；当份 PR、目标和最终版本 | 不合并，保留工作 |
| 本批发布（仅适用项目） | 发布 / 先不发；已核候选、风险和生产动作 | 不打新发布 tag、不部署、不推进成功快照 |

这些是不同决定，不合成一次点头；只在触发时提问，不为走齐卡片凭空制造问题。卡片语义不要求固定提问顺序或重复汇总。

## 二、方案与可实施判据

### 入口、页面与结构

新需求写文件前由用户选入口，不因改动小由 agent 自动免方案。直接干只免方案期，不补 spec / 执行 issue，仍有实施交付与合并闸；既有 issue 委托及未合并稿续接按当前事实，不重开入口。

首次方案确认须说清改哪里/怎么改、问题/能力、目标/非目标、真实备选及代价和验收；新增做法交代没有它会怎样。同一方案 No 可重组；实质改变已批准目标/范围/能力回对应确认。例外、改旧 spec 不由普通方案 Yes 代替。

页面选择前已有公共骨架及同一 Draft PR；有页面须等用户设计后结合骨架分析，不代画、不凭猜测补完整接口。两支都核设计/接口/业务/验收的待决定缺口；无页面不豁免接口分析，公共缺口未闭合不定最终结构。

拆分决定前给基于真实交付物、里程碑、改动面和依赖的评估、候选拆法、推荐及代价；多个需分别推进/验收/安排节奏的交付里程碑必须提醒，子件仍多阶段同样说明并由用户选。普通编码/测试/PR 步骤和开始/合入/发布三项就绪本身不算多阶段。卡上说明拆成 N 份对应总纲、N 份执行 spec/issue 与跟踪父单的成本，不拆为 1 spec + 1 执行 issue；不以工时/行数硬阈值强制拆。

选拆按独立可验收成果划分，尽可能并行但不要求全独立；不拆不得偷换成一份大 spec 下的多张阶段单。共享契约与同一决定未冻结不算可并行；依赖方向、产物、就绪条件、证据和唯一 owner 要清楚，不能带未解实施环/归属缺口开单。同批合入/发布要有明确安排与责任方，不伪装各自独立；父子归属不冒充阻塞，仅部分产物或发布相关不误挡全部开发。身份与引用可追溯，平台原生关系未建如实报告。表达形态见拆分指南，指南表格列数不是新闸口。

结构实质变化（范围、里程碑、依赖或 owner 变化影响既有拆法）回结构选择；普通补稿/同步不重问。已有获批 spec 变更按改旧卡，机械状态/编号/验收回填或末尾审核修订记录追加不触发改旧卡。

### 可实施与送审（DoR）

可实施不是“照抄了模板”。当份终稿需要可核的下列信息，允许表格、段落、图或其他充分表达：

- 承重规则和已确认做法一致，无未决定的承重问题；agent 自定的默认值、判断、命名、落点可识别，不夹带方案外承诺。
- 行为有触发、响应及必要失败/空态处理；适用写路径有明确入口与唯一归属，状态有承载字段及读侧，不虚构本任务没有的数据状态机。
- 验收能判对错，有命令、断言、截图或适用人工确认入口，正常/异常/边界和必要回归覆盖充分。
- 适用的数据迁移、回填、回滚、兼容及外部合同/版本影响明确；没有则写不适用及事实理由。
- 已采用 ADR 时当前决定/取代链与正文一致；未采用不新增 ADR 前置。已采用文档分工、依赖与项目明确格式遵守原约定。

上述信息齐备、承重缺口闭合且用户同意送审，才将同一 Draft 转 Ready、进入规格审核；骨架/对照不据此合并。不固定四列表、三个例子、3–5 条岔路、每条挂步号或每次逐字复述起终点。不同但充分的方法不是违规；项目/用户明确约定的具体格式仍有效。

## 三、实施授权与停止

### 委托识别

- 对象必须是执行 issue；父/总览单只跟踪，PR 号不当实施委托。方案合并、开单、已有锁或规格审核不等于委托。
- **所有执行 issue 的共同前提**：登记生效授权、认领前须实查 issue 仍为 `open`；已关闭则停，不能从“开工”推定重开许可，也不在已关闭任务登记生效授权或认领。含交接区时还须核正文 `SPEC_READY`、规格最新合并版本及当前范围一致、尚无另一份生效授权。共同前提同时适用于定向、同窗口交接和适用的既有 issue 入口；无交接区旧单不补造 `SPEC_READY`。
- **定向入口 `issue-direct`**：任何窗口“请做 #N”“开始实施 #N”“按 #N 开工”等明确绑定 issue 的话识别为定向委托；仍先满足上述共同前提，不因说出编号省事实核对。
- **同窗口入口 `same-window-handoff`**：本 agent 的交接报告是当前上下文最后一条 agent 消息，用户开始意图紧接，且恰好一张未授权执行交接，三条件同时满足。“开始实施”“开始干”“开工”是闭集，礼貌前缀不改变含义；“继续”“开始吧”“就按这个做”不替代该闭集。
- 中间有问答、工具结果、压缩/摘要、报告不逐字可见、新窗口/其他 agent 或多执行单时，要求点名 `#N` 或给选项；全局只有一个候选不能替代相邻性。交接创建失败不成立同窗口入口。
- 无交接区的既有 issue：明确“做 #N”有效，不补造 `SPEC_READY`，不适用同窗口入口；按交付正文把授权记录在原 issue。
- 无 spec/issue 的直接干任务以当场明确入口为范围授权，PR 承接适用记录；用户点名执行 issue 则仍走定向入口，不借直接干省授权留痕。

按 phase-handoff 核事实、写授权记录后才认领，不追加第二份同时生效授权。已有授权/锁冲突先停；接管需新用户明确委托并留接管记录，不冒用旧授权。范围缩小按更窄者；范围扩大、返修或当前规格冲突停受影响部分交用户决定，不擅改冻结依据。取消后重开不自动恢复实施授权。

范围内调整算法、探索或验证方法不逐内部阶段求许可；实质触发 one-path 已声明停止点才停受影响部分，记录恢复条件。生产写、不可逆迁移、外部契约变更不从普通实施委托外推。临时测试只证明当次验证，不授权安装工具、写采用仓或执行生产。

## 四、审核、修订与轮次

每份、每阶段当场选档，不沿用规格期档位到实施期；判断权在用户，agent 不自判核心、不自动派审。项目禁用的档位不展示。子 agent 是执行分身，自测、草拟和检索不能冒称独立审核；真正要求另一方裁决时材料备好后停，等用户指定方。

| 档位 | 当份派发 | 大致成本 |
|---|---|---|
| 不审 | 不派 agent；主 agent 按 diff 对获批范围及已采用约束自查 | 0 |
| 轻审 | 1 个：规格期符合性+方案/自定细节两项核对；实施期对抗找 bug+范围外对账 | 约 5 分钟 |
| 重审 | 2 个：规格符合性（含适用清单/范围）+ 对抗找 bug | 约 10 分钟 |
| 重审 + 变异 | 重审 + 主 agent 换错判据并跑全量相关测试；仍全绿说明没护栏 | 同重审 + 约 18 秒，实测耗时另报 |

变异不是多派一个 agent；只在独立测试工作区做、恢复变异、不把坏判据带入交付。无可跑测试如实报无法验证，不编造变异通过。测试和草拟不替代用户当份审核选择。

审核只读不改文件。提供当前获批 spec、真实工作区/diff 基准、相关项目入口、已采用约束和现行 ADR 依据（如适用）；逐条核 file:line 与现状断言，不拿未经实测假设当事实。规格符合性核同一方案说明、agent 自定细节及必要共享依赖，与正文对应；实施对抗找具体行为缺陷。ADR 冲突报告来源，不代裁业务。范围外对账只报超出获批改动面的变更，不膨胀成质量建议或新的防御层（依据：rationale R3–R5）。

R1 全量走路径，核正常/失败/证据及是否有该走没走的分支；R2 只核上轮闭合与新增阻断/高，新中/低只记录；R3 仍有阻断/高则停，由用户选重画/砍范围/停，不派第 4 轮。复审每次重摆当份派审卡，修订同意不授权再派。

**严重度与范围**：走不通、必要证据不可执行、同一决定多 owner、承重选择未定、数据/安全/权限问题为阻断；导致返工或跨份不一致但可修为高；中/低不挡合并，留未处理项。发现须对应具体获批要求、行为、交付或证据，不强求步号；可直接修正的表达/同步/操作瑕疵不因偏离示例升格阻断。扩展建议只作建议，不自动成为新机制。数据/安全/权限问题不因标中/低而降格。

审核结论（含变异结果）先原样贴 PR 评论，无 PR 则贴对话；有发现再由用户选全改/只改阻断+高/不改，不自动改。零发现只贴结果、不加修订卡；不审免审核产物，不免自查与合并卡。处置追加到规格末尾审核修订记录；无可写规格时放原任务 PR，不重写获批正文。仍有阻断/高不合并；仅中/低且用户选不改可在合并卡列明后合并；修订未答不合并。

### 批次与豁免

一卡盖实施批次须列每份 PR/分支，写「N 份 × 该档 = X 个 agent / Y 分钟」，逐份算不审0/轻审1/重审2，文档检查逐成员在其工作区跑并列结果。未声明按份；规格多份仍按份数累计。批卡只管审核，不授权批量合并。

无新内容的机械编号/状态/索引/验收回填、不进仓草稿/PR底稿免审核闸；归属拿不准摆卡问，不自判。无 PR 的交付前仍摆审核卡并给 diff；平台机械回填不凭空新造 PR。worktree 豁免只有用户当场明确“直接改/不开 wt”，agent 不自判或建议；真并行仓的认领锁仍执行。以上均不免实际存在 PR 的合并确认。

## 五、文档检查

交付物为 spec/纯文档，或代码 diff 含文档改动时，**摆派审卡前**在交付物自己的工作区跑文档检查，卡上固定写「文档检查：绿 / 红+摘要 / 无入口」，选不审也先跑。免审核闸的机械回填无卡，免此检查。

入口按顺序发现：项目指令自报且真实存在的入口；否则首个存在的 `scripts/check-docs.sh`、`scripts/check-doc-links.sh`；都无则写无入口。不存在的自报路径落下一档；存在但跑不起来/崩溃是红，不冒充无入口。

本次 diff 引入红须修复重跑绿再摆卡；无关存量红注明数量/摘要与不相关依据，不阻本次合并、交用户处置。用户可当场明示一次豁免，记录理由；检查绿/标存量/豁免都不授权合并。静态绿不证明客户端或生产行为。

## 六、独立合并与生产批准

每份 PR 无论目标、文档/配置/资源/机械回填都单独合并确认：自查/审核 → 按用户选择修订验证 → 合并卡 → 明确同意 → 执行。卡上列 PR、目标分支、当前完整提交、最终摘要、验证及未处理项；执行前重核实际对象/版本/diff，不明差异先停。

不审、零发现、同意改、已修完、需求认可或 reviewer 说可合并均不等于用户同意。合并未答、关闭、先不合、暂停/撤销/重审均不合；不催答。不提前启用 auto-merge、入自动队列、直推目标或用保护分支绕开确认。旧同意失效按 §一 重核；既有阻断条件不会因点了合并自动消失。一份同意不扩展到同批其他 PR（依据：rationale R30）。

采用发布模块时，本批发布批准须有已核的当前候选、范围/排除、必要依赖、通过证据、tag/完整提交、产物与部署单元、风险/回滚/验证；缺交付或来源未知不放行。批准只覆盖列明批次与动作，变更后回对应确认。合入开发/候选、标签、tag 存在和成功快照均不替代实际生产验证。Git 危险操作、保护分支、项目生产权限和已声明停止点继续有效，不因本文件给出命令即获授权。
