# 决策目录（L2，D0–D7）

> 硬闸 = 下方 8 类用户决定（类型不增）；之外遇 L0-1 / L0-7 同样停。自判细节不进目录。
> 共同失效（L0-6）：批准绑当次对象 / 范围 / 版本；范围变、返修、暂停、撤销或重审即失效，各条只列特有失效点。

## D0 实施委托

- **触发**：spec 已合并、执行单已建且用户明确委托（「请做 `#N`」「开始实施 `#N`」等）；父单 / PR 号 / 锁 / 审核通过均不算。
- **同窗口闭集**：交接报告为末条 agent 消息 + 紧接闭集「开始实施 / 开始干 / 开工」（礼貌前缀不改义；「继续」「开始吧」「就按这个做」不替代）+ 恰好一张未授权单；中间有问答 / 工具输出 / 压缩 / 新窗口 / 多单须点名 `#N`。
- **证据**：spec 合并提交一致、issue `open`、范围、锁、无第二份授权（同窗口另核相邻性）。**选项 / 默认**：委托 / 先不委托（默认不委托）。
- **失效**：issue 关、扩范围、spec 偏离、第二份授权、不再相邻。

## D1 范围与结构（开 spec 适用；直接干不走 D1）

- **触发**：开 spec 新需求，或既有范围 / 结构实质变化。直接干走 L0-6 说明改动面 + D4。
- **证据**：目标、范围、非目标、验收、页面 / 无页面、拆 / 不拆、观察式例外、承重未知、反熵增三问初稿（[10-stages](10-stages.md)）；跨切面按 [25-spec-governance](25-spec-governance.md) §二 附 seed 与枚举口径。
- **选项 / 默认**：确认 / 调整 / 不做（默认不做）。**失效**：目标或验收变、结构变影响拆法、跨切面超枚举口径。

## D2 设计与规格确认

- **触发**：方案 / 规格草稿完成。
- **证据**：方案、备选与代价、三问终稿、验收、依赖、DB 变更、文档检查、审核档位、修订范围；治理证据见 [25-spec-governance](25-spec-governance.md)；替换式变更附 manifest 摘要；审核输入见 [26-review-contract](26-review-contract.md) §五。
- **选项 / 默认**：确认 / 改 / 重做；档位：不审 / 轻审 / 重审 / 重审 + 变异；修订：全改 / 只改阻断 + 高 / 不改 / 砍路径 / 写明本期不保证（默认不审、不改、不合）。
- **失效**：方案实质变、换档 / 修订范围、新阻断 / 高、盘点表解冻、中途升级组件或文档结构变化。

## D3 spec 合并

- **触发**：审核与修订完成。
- **证据**：审核修订记录、最终提交与目标分支、文档检查、治理证据、manifest 与正式校验（合并前钉扎）。
- **选项 / 默认**：合并 / 先不合（默认不合）。改已合并 spec：新开 / 改旧（默认不动冻结正文；勘误限事实写错，改范围 / 验收一律新开）。
- **失效**：内容提交变（合并前按 [change-protocol](30-playbooks/change-protocol.md) 执行的 `manifest-only` 钉扎提交除外，须单列提交且正式绿）；仍有未处理阻断 / 高。

## D4 每份 PR（含直接干与 hotfix 合回）

- **触发（两时点）**：① 提 PR 后选档与修订范围；② 审核修订后确认合并。
- **证据**：① PR、目标、完整提交、范围；② 修订提交、审核修订、文档检查、验证、未处理项与竣工回写（[10-stages](10-stages.md)）；有 spec / 盘点表 / manifest 按 [26-review-contract](26-review-contract.md) §五 附证，无以 PR 目标 / 范围 / 验收与 diff 替代并写理由；hotfix 附生产 tag / 修复提交 / 临时 tag / 验证。
- **选项 / 默认**：① 同 D2；② 合并 / 先不合（每份单选不沿用规格期，L0-5；默认不审、不改、不合）。
- **失效**：PR 有新提交（仅两类除外，合并卡单列并验绿：① [26-review-contract](26-review-contract.md) §五.3 纯派生条机械回填；② D4 ② 前 `manifest-only` 钉扎提交正式绿）、目标前进需重核、未处理阻断 / 高、擅改冻结盘点表。

## D5 整条 issue 合入 staging（仅 staging 线）

- **触发**：issue 验收 + 合入预演绿 + 四类齐。
- **证据**：`#N`、`issue/<N>`、提交、预演分支 / 提交、staging 基线与当前提交、合并验收、四类、竣工回写与减法核销、未处理项。
- **选项 / 默认**：合入 / 先不合（默认不合）。**失效**：staging 前进需重预演、分支新提交、四类 / 回写缺效、未合实现 PR。

## D6 生产发布（仅采用 `release` 的项目）

- **触发**：批次测试 + rc 验收通过。
- **证据**：批次提交与结果、批次范围（上个生产 tag..候选）、排除与搭车项、依赖、四类、rc 与最终 tag（同提交）、产物 / 部署单元、验证、回滚目标、直接干清单。
- **选项 / 默认**：发布 / 先不发（默认不发）。**失效**：候选新合、批次失效、rc ≠ 最终 tag、范围或回滚目标变。

## D7 回滚

- **触发**：生产异常。**证据**：目标 tag / 快照、影响范围、异常原文、目标可用性。
- **选项 / 默认**：回滚 / 不回滚（默认不回滚）。**失效**：异常范围变、目标快照不可用或树不一致。

## 交互卡片契约

计划卡、业务选项卡与未答处理的**唯一正文**；优先客户端选项工具，无工具列等价文字选项，授权边界相同。

- **计划卡三触发**（任一才发）：① 新任务不平凡；② 将触不可逆；③ 预计问超 3 次。只读检查 / 核既有结果 / 单处小改不发。
- **计划卡模板**（仅换花括号，两按钮不变；确认只改计划状态，不代实施委托）：

~~~json
{"question":"计划覆盖{交付物}，用{场景}验收。待核事项：{事实缺口或无}。是否确认这份计划？","options":["确认计划","调整计划"]}
~~~

- **业务选项卡**：2–3 选项、差别与推荐，允许自填；答复只作用于声明范围（选范围不授权写入）。
- **未答或取消**：立即结束本轮；只交代待定与已停动作，保留原卡。已答即引原话完结，收尾不追问「是否继续」或重复选项。

## 标签确认与观察式例外

- **标签**：视图非状态机，与交接区冲突停报；「待上线」「待验证」「关单」须确认，其余无歧义可换并报告（[labels](30-playbooks/labels.md)）。
- **观察式例外**：仅方案期 D1 可申，默认不纳入（[15-records](15-records.md) §六）。
