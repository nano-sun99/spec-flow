# 决策目录（L2，D0–D7）

> 硬闸 = 下方 8 类用户决定类型（每类可多次触发，类型不增）。八类之外遇 L0-1 不可逆动作或 L0-7 承重缺口同样停。
> agent 可自判的入口 / 落点 / 非关键标签 / 分支格式不进目录。共同失效规则（L0-6）：批准绑定当次对象、范围与版本；范围变化、返修、暂停、撤销或重审即失效，以下各条只列特有失效点。

## D0 实施委托

- **触发**：spec 已合并、执行 issue 已建，且用户明确表示实施（「请做 `#N`」「开始实施 `#N`」等）。父单、PR 号、已有锁、审核通过都不算委托。
- **同窗口入口闭集**：交接报告是最后一条 agent 消息 + 用户紧接闭集「开始实施 / 开始干 / 开工」（礼貌前缀不改含义；「继续」「开始吧」「就按这个做」不替代）+ 恰好一张未授权执行单。中间有问答、工具输出、压缩、新窗口或多单时，必须点名 `#N`。
- **证据**：spec 合并提交与应实施版本一致、issue 仍 `open`、本次范围、当前锁、无第二份生效授权；同窗口另核相邻性。
- **选项**：委托 / 先不委托。**默认**：不委托。
- **失效**：issue 关闭、范围扩大、spec 版本不再一致、出现第二份生效授权、交接报告不再相邻。

## D1 范围与结构（开 spec 适用；直接干不走 D1）

- **触发**：需开 spec 的新需求进入，或既有确认范围内发生范围 / 结构实质变化。直接干走 L0-6 说明改动面 + D4，不走 D1。
- **证据**：目标、范围、非目标、验收、页面 / 无页面、拆 / 不拆、观察式例外（如适用）、承重未知清单；跨切面需求另按 [25-spec-governance](25-spec-governance.md) §二 附范围盘点表 seed 与枚举口径。
- **选项**：确认 / 调整 / 不做。**默认**：不做。
- **失效**：目标或验收含义改变；结构变化影响既有拆法；跨切面新增范围类型或超出枚举口径。

## D2 设计与规格确认

- **触发**：方案或规格草稿完成。
- **证据**：方案、备选及代价、验收、依赖、数据库变更清单（如适用）、文档检查结果、审核档位、修订范围；治理证据（决定索引 / 决定节、owner 对账、跨切面冻结盘点表与数量对账）按 [25-spec-governance](25-spec-governance.md)；替换式变更附 manifest 校验摘要；审核输入按 [26-review-contract](26-review-contract.md) §五。
- **选项**：确认 / 改 / 重做；审核档位：不审 / 轻审 / 重审 / 重审 + 变异；修订范围：全改 / 只改阻断 + 高 / 不改 / 砍掉相关路径 / 写明本期不保证。**默认**：不审、修订不改、不合并。
- **失效**：方案实质改变、换档位或修订范围、出现新阻断 / 高发现、冻结盘点表解冻、文档结构（章节 / owner / 权威顺序）变化。

## D3 spec 合并

- **触发**：审核与修订完成。
- **证据**：审核结果、修订记录、最终版本与目标分支、文档检查结果、治理证据（索引 / 冻结盘点表，如适用）、change manifest 与正式模式校验输出（如适用；须在合并确认前完成钉扎）。
- **选项**：合并 / 先不合。改已合并 spec：新开一份 / 改旧的（默认不动冻结正文；勘误限事实写错，改范围 / 验收一律新开）。**默认**：不合并。
- **失效**：修订后内容版本变化（D3 合并确认前按 [change-protocol](30-playbooks/change-protocol.md) 执行的 `manifest-only` 钉扎提交除外，须单列内容与钉扎提交且正式校验绿）；仍有未处理阻断 / 高。

## D4 每份 PR（含直接干与 hotfix 合回）

- **触发（两次时点）**：① PR 提交后、审核前选审核档位与修订范围；② 审核与修订完成后确认合并。
- **证据**：① PR、目标分支、完整提交、本次范围；② 修订后完整提交、审核结论与修订记录、文档检查、验证结果、未处理项；有 spec / 盘点表 / manifest 时按 [26-review-contract](26-review-contract.md) §五 附对应证据，无则以 PR 目标 / 范围 / 验收与 diff 替代并写不适用及理由；hotfix 另附生产 tag、修复提交、临时 tag 与验证。
- **选项**：同 D2 审核档位与修订范围；② 合并 / 先不合。每份单独选档，不沿用规格期（L0-5）。**默认**：不审、修订不改、不合并。
- **失效**：PR 有新提交（仅以下两类除外，须在合并卡单列提交且跑对应检查绿：① 按 [26-review-contract](26-review-contract.md) §五.3 执行的纯派生条机械回填；② D4 ② 合并确认前仅改 manifest 的 `manifest-only` 钉扎提交且 `check-change.py` 正式模式绿）、目标分支前进需重核、仍有未处理阻断 / 高、擅改冻结盘点表。

## D5 整条 issue 合入 staging（仅 staging 线）

- **触发**：issue 分支验收通过 + 合入预演绿 + 四类核对齐。
- **证据**：issue `#N`、`issue/<N>`、完整提交、预演分支 / 提交、staging 基线、合并后构建验收、四类逐项（含文档检查）、未处理项、staging 当前提交。
- **选项**：合入 / 先不合。**默认**：不合入。
- **失效**：staging 基线前进需重跑预演、issue 分支有新提交、四类缺有效结论、仍有未合入实现 PR。

## D6 生产发布（仅采用 `release` 的项目）

- **触发**：批次测试通过 + rc 验收通过。
- **证据**：批次测试提交与通过结果、批次范围（上个生产 tag..候选）、排除项与搭车项处置、必要依赖、四类结论、rc tag、最终 tag（同一提交）、产物 / 部署单元、验证、回滚目标、直接干任务清单。
- **选项**：发布 / 先不发。**默认**：不发布。
- **失效**：候选有新合入、批次测试失效、rc 与最终 tag 不同提交、范围或回滚目标变化。

## D7 回滚

- **触发**：生产异常。
- **证据**：目标 tag / 快照、影响范围、异常证据（监控 / 日志 / 验收失败）、回滚目标可用性。
- **选项**：回滚 / 不回滚。**默认**：不回滚。
- **失效**：异常范围变化；目标快照不可用或与生产树不一致。

## 交互卡片契约

本节是计划卡、业务选项卡与未答处理的**唯一正文**。所有用户决定优先用客户端选项工具，无工具时列等价文字选项，两者授权边界相同。

- **计划卡三触发条件**（满足任一才发）：① 新任务且范围不平凡；② 即将发生不可逆动作；③ 预计向用户提问超过 3 次。只读检查、核对既有结果、单处明确小改默认不发。
- **计划卡模板**（仅替换花括号，两个按钮保持原样；确认只改计划状态，不替代实施委托）：

~~~json
{"question":"计划覆盖{交付物}，用{场景}验收。待核事项：{事实缺口或无}。是否确认这份计划？","options":["确认计划","调整计划"]}
~~~

- **业务选项卡**：给 2–3 个可行选项、差别与推荐，允许自填；答复只作用于声明的范围（如选定规格导出范围不授权实际取数或写入）。
- **未答或取消**：立即结束本轮；只交代哪项待定、哪些动作已停，保留原卡供回答。卡片已答即引原话完成本轮，收尾不再追加「是否继续」或重复文字选项。

## 标签确认与观察式例外

- **标签规则**：标签是视图，不是状态机；与交接区正文冲突时停住报告。「待上线」「待验证」「关单」必须用户确认，其余标签无歧义时 agent 可换并报告。细则见 [labels playbook](30-playbooks/labels.md)。
- **观察式例外**：仅方案期 D1 可申请，默认不纳入；适用类型与字段见 [15-records](15-records.md) §六。
