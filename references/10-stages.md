# 阶段合同（L1）

> 本页是「什么算完成」的唯一正文，不规定段内步骤。对外仍是两段：澄清 + 设计 = 方案期，交付 + 发布 = 实施期。
> 2026-11-13 重建总纲为历史设计稿，现行运行口径以本页、铁律（[00-constitution](00-constitution.md)）、决策目录（[20-decisions](20-decisions.md)）、记录（[15-records](15-records.md)）及专项总纲为准。

## 一、核心术语

| 术语 | 定义 |
|---|---|
| 四类 | spec、实现 / 必要测试、配套文档、必要依赖 |
| 页面 | 只有可交互 GUI 才算；CLI 输出、导出报表、接口响应不算。判错只影响是否等用户设计，不影响接口与业务分析 |
| 候选 | 三层：候选分支 HEAD；staging 线：staging HEAD；单主线：生产主线 HEAD |
| 合入预演 | 仅 staging 线：把当前 staging 合入 issue 分支（或临时预演分支），在真实 merge 树上构建并跑本 issue 验收；允许 rebase/CI，但须证明结果树与真实 merge 树一致 |
| 批次测试 | 在当前候选构建、部署测试环境，跑回归与跨 issue 验收；候选有新合入即失效，最终 tag 提交须等于最近通过批次测试的候选 HEAD |
| rc 验收 | 从 rc 附注 tag 构建、部署测试环境跑验收；不做 15 分钟监控 |
| 生产监控 | 从最终 tag 部署生产后监控 15 分钟（按项目手册）；崩溃或异常停住上报，不自动回滚 |
| 生产分支快照 | 单主线：主线前进到同一提交并打 tag；三层 / staging：生产分支的树等于最近成功 tag 的树，不用 merge / reset / read-tree 覆盖 |
| 搭车项 | 候选里未列入本批、来源未登记的改动 |
| 交接区 | issue 正文的「spec-flow 交接」区或等价字段；无 issue 由任务 PR 承接 |
| 授权方式 | `issue-direct`（点名做 `#N`）；`same-window-handoff`（交接报告紧接闭集开始意图）；`takeover`（接管已认领工作，需新委托） |
| 反熵增三问 | 开 spec 必填：① 已有重叠盘点；② 减法清单（拟删 / 替 / 并 / 归档对象，无写理由）；③ 现状真身落点（交付后更新的唯一现状文档，无写理由） |
| 竣工回写 | 交付出口按最终实际实现（as-built）同步唯一现状文档并核销减法清单（未清理转遗留须经用户确认） |

> 规格治理术语（精简底座、按需组件、跨切面、盘点表、枚举口径、数量对账、决定索引、冻结/解冻、规范性句子）唯一定义见 [25-spec-governance](25-spec-governance.md)；审核档位、严重度、文档检查三态唯一定义见 [26-review-contract](26-review-contract.md)。

## 二、四段合同

### 澄清

- **目标**：把需求变成可判断的范围、验收和约束。
- **完成（全部为真）**
  - 改哪里 / 怎么改 / 带来什么能力或优化，具体到能被否掉；范围与非目标明确。
  - 验收可判对错：有命令、断言、截图或人工确认入口。
  - 承重未知已闭合：数值、接口、范围、权限、数据无悬空。
  - 开 spec 时：页面 / 无页面、拆 / 不拆、观察式例外（如适用）已定并交**反熵增三问初稿**；跨切面另按 [25-spec-governance](25-spec-governance.md) §二 交盘点表 seed 与枚举口径。
  - 入口（直接干 / 开 spec）已判定并报告，用户可按 L0-6 否决。直接干免 D1、免盘点表与三问，按 L0-6 一句话说明改动面后直进交付。
- **证据**：需求摘要、验收清单、决定及来源（[15-records](15-records.md) 第 2 类）；开 spec 含三问初稿，跨切面另含表 seed 与枚举口径。有真实追问才记问答。
- **出口**：开 spec 经 D1 确认进入设计；直接干说明改动面后进入交付。

### 设计

- **目标**：把方案变成可执行的 spec / 计划。
- **完成（全部为真）**
  - 方案、备选及代价、反熵增三问终稿（具体路径 / 规则节 / 唯一现状文档，无写理由）、验收（正常 / 异常 / 边界 / 回归）、依赖、数据库变更清单（如适用）齐备；行为有触发、响应与失败 / 空态处理。
  - 承重规则与已确认做法一致，无未解承重问题；承重取值路径已用能判错的业务例子核过，未核项标明。
  - 数据迁移、回滚、兼容、外部契约影响已写明，或写不适用及事实理由；已采用 ADR 时取代链与正文一致。
  - 文档治理合规（[25-spec-governance](25-spec-governance.md)）：守精简底座（简版决定表、单 owner、无双活动 ID 与自相矛盾）；触发组件 1 / 2 时按需补齐（中途按 §五 升格）。
  - 触发组件 3 替换式变更（改 PR `base` 既有规则 / 旧 ADR / owner 等）时，按 [change-protocol](30-playbooks/change-protocol.md) 交 manifest 并跑校验器绿（未处置 = 0）。
  - 审核档位与修订范围已选（D2），审核与修订按 [26-review-contract](26-review-contract.md) 完成；文档检查已跑且本次 diff 引入的红已修复。
- **证据**：spec（含三问终稿）、决定表（组件 2 含覆盖列与 owner 对账）、盘点表与对账（组件 1）、承重路径核对、manifest 与校验输出（组件 3）、审核 / 修订记录、文档检查。
- **出口**：spec 合并（D3）+ 执行 issue 已建 + 等待明确实施委托（D0）。

### 交付

- **目标**：把实现变成可验收的 PR / 分支。
- **完成（按项目形态取适用分支，全部为真）**
  - 有 issue：issue 分支验收通过，四类逐项满足或记不适用及事实理由；staging 线另须合入预演绿且无未合入实现 PR。
  - 无 issue（直接干）：完成可判定验收；有测试环境则部署 PR 分支验收，无则写不适用及事实理由。
  - 有冻结范围盘点表时，实施只交付表内行；表外新增按 [25-spec-governance](25-spec-governance.md) §二 路由。
  - **竣工回写（开 spec）**：整单出口（最终 `D4 ②` / `D5`）与关单前须按最终实现回写唯一现状文档并核销减法清单（未清理转遗留须经用户确认，禁单方跳过）；多 PR 中间子 PR 仅核本 PR 对应变更并注明剩余项归属整单出口。
  - **竣工回写（直接干）**：纯内部 bugfix / 重构零额外文书税；仅改变对外行为 / 命令 / 架构 / 接口 / README 时于 `D4 ②` 前同步现状文档唯一 owner（看似触及无需更新则一句说明）。
  - 采用 `release`：候选按形态就绪（单主线 = 待合任务分支；三层 = 待挑任务 PR；staging 线 = 待合 staging 的 issue 分支）且四类已核；不采用 `release` 则交付验收后完成。
  - 文档改动已跑文档检查（三态见 [26-review-contract](26-review-contract.md) §四）；触发替换式变更时按 [change-protocol](30-playbooks/change-protocol.md) 交 manifest 并跑校验器绿。
- **证据**：PR 列表、构建与验收证据、四类逐项、竣工回写结果（如适用）、合入预演（staging 线）、worktree / 锁记录、审核与修订记录、文档检查、表行核对与 manifest 校验（如适用）。
- **出口**：整条合入 staging（仅 staging 线，D5）/ 任务 PR 合并（D4）/ 无发布义务任务关单。

### 发布（仅采用 `release` 的项目适用）

- **目标**：把候选变成可复现的生产版本。未采用 `release` 的项目跳过本段（属「不适用」，非「未完成」）。
- **完成（全部为真）**
  - 批次测试通过（当前候选；打最终 tag 前重跑）且 rc 验收通过。
  - 生产发布已获用户批准（D6），并遵守 [release playbook](30-playbooks/release.md#一发布安全不变式) 的全部安全不变式。
  - 生产监控正常通过；崩溃或异常按 L0-4 停住上报，不进入完成。
- **证据**：批次记录、rc tag、最终 tag、监控结果、发布记录与生产分支快照核对。
- **出口**：生产验证通过 + 生产分支快照 + 用户确认后关单。

## 三、交付前置条件

- **独立 worktree**：文件变更在独立 worktree 完成，不在共享主检出上改；仅用户当场明示「直接改 / 不开 worktree」豁免，须记理由（agent 不自判、不主动建议；真并行仓的认领锁仍执行）。
- **锁键与命名**：issue 锁键 = 精确分支名 `issue/<N>`，目录 `issue-<N>`；已检出即撞锁，停且不双写。直接干 `task/<slug>`；批次修复 `fix/<N>-<slug>`（直接干 `fix/<slug>`）；hotfix `hotfix/<tag>-<slug>`。
- **分支起点与 PR 目标**：staging 线从 `origin/staging` 开 `issue/<N>`，实现 PR 回 `issue/<N>`；三层从 `origin/<集成>` 开分支、PR 回集成；单主线从 `origin/<主线>` 开分支、PR 回主线。实际映射以项目指令为准，不明按 L0-7 问。
- **发布安全不变式**：已采用 `release` 的项目必须遵守 [release playbook](30-playbooks/release.md#一发布安全不变式)，违反任一条属 L0-1 不可逆动作。

## 四、入口与跳过

- 新需求从澄清进；已有获批 spec 的执行单从交付进；直接干从澄清或交付进（跳过设计）；hotfix 从交付进并按 D4 合回开发线。
- 入口由 agent 判定并报告，用户可按 L0-6 否决；跳过不免所到阶段的完成条件。
- 段间无固定顺序要求；返修可重入设计，完成条件不因重入降低。
