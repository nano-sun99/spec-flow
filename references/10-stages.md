# 阶段合同（L1）

> 本页是「什么算完成」的唯一正文，不规定段内步骤。对外两段：澄清 + 设计 = 方案期，交付 + 发布 = 实施期。
> 现行口径以本页、[00-constitution](00-constitution.md)、[15-records](15-records.md)、[20-decisions](20-decisions.md) 及专项总纲为准。

## 一、核心术语

| 术语 | 定义 |
|---|---|
| 四类 | spec、实现 / 必要测试、配套文档、必要依赖 |
| 页面 | 仅可交互 GUI；CLI / 报表 / 接口不算（判错仅影响是否等设计稿） |
| 候选 | 三层 = 候选 HEAD；staging 线 = staging HEAD；单主线 = 生产主线 HEAD |
| 合入预演 | 仅 staging：合当前 staging 入 issue（或临时预演）分支，在真实 merge 树构建验收；rebase/CI 须证树一致 |
| 批次测试 | 当前候选部署测试环境跑回归与跨单验收；候选新合即失效，最终 tag 须等于最近通过批次测试的候选 HEAD |
| rc 验收 | 自 rc 附注 tag 构建部署测试环境验收；不做 15 分钟监控 |
| 生产监控 | 自最终 tag 部署生产后监控 15 分钟（按手册）；异常停住上报，不自动回滚 |
| 生产分支快照 | 单主线快进并打 tag；三层 / staging 生产树 = 最近成功 tag 树，禁 merge / reset / read-tree 覆盖 |
| 搭车项 | 候选内未列本批、来源未登记改动 |
| 交接区 | issue「spec-flow 交接」区或等价字段；无 issue 由任务 PR 承接 |
| 授权方式 | `issue-direct`（点名 `#N`）；`same-window-handoff`（交接报告紧接闭集词）；`takeover`（接管，需新委托） |
| 反熵增三问 | 开 spec 必填：① 已有重叠盘点；② 减法清单（拟删/替/并/归档，无写理由）；③ 现状真身落点（唯一现状文档，无写理由） |
| 竣工回写 | 交付出口按最终实现（as-built）同步唯一现状文档并核销减法清单（未清理转遗留须用户确认） |

> 规格治理术语见 [25-spec-governance](25-spec-governance.md)；审核档位 / 严重度 / 文档检查三态见 [26-review-contract](26-review-contract.md)。

## 二、四段合同

### 澄清

- **目标**：把需求变成可判范围、验收与约束。
- **完成（全真）**
  - 改哪里 / 怎么改 / 带来什么能力具体到可否决；范围、非目标与可判验收齐备；承重未知闭合。
  - 开 spec：定页面 / 拆不拆 / 观察式例外并交**反熵增三问初稿**；跨切面按 [25-spec-governance](25-spec-governance.md) §二 交盘点表 seed 与枚举口径。
  - 入口（直接干 / 开 spec）已判定报告，用户可按 L0-6 否决。直接干免 D1 / 盘点表 / 三问，按 L0-6 一句说明改动面直进交付。
- **证据**：需求摘要、验收、决定及来源（[15-records](15-records.md) #2）；开 spec 含三问初稿，跨切面另含 seed 与枚举口径（有追问才记问答）。
- **出口**：开 spec 经 D1 进设计；直接干说明改动面进交付。

### 设计

- **目标**：把方案变成可执行 spec。
- **完成（全真）**
  - 方案、备选与代价、三问终稿（具体路径 / 节 / 唯一现状文档，无写理由）、验收（正常/异常/边界/回归）、依赖、DB 变更（如适用）齐备；行为含触发 / 响应 / 失败与空态。
  - 承重规则一致无悬空，经可推翻方案的业务例子核过（未核标明）；迁移 / 回滚 / 兼容 / 外部契约明确（或不适用及理由）；ADR 取代链一致。
  - 文档治理合规（[25-spec-governance](25-spec-governance.md)）：守精简底座，触发组件 1/2 按需补齐（中途 §五 升格）；组件 3 按 [change-protocol](30-playbooks/change-protocol.md) 交 manifest 验绿。
  - 审核与修订按 D2 与 [26-review-contract](26-review-contract.md) 完成；文档检查跑绿（本 diff 引入红已修）。
- **证据**：spec（含三问终稿）、决定表、盘点表对账（组件 1）、承重例子、manifest 校验（组件 3）、审核修订记录、文档检查。
- **出口**：spec 合并（D3）+ 建执行 issue + 停等 D0 明确委托。

### 交付

- **目标**：把实现变成可验收 PR / 分支。
- **完成（按形态全真）**
  - 有 issue：分支验收通过、四类满足（或不适用及理由）；staging 线另须合入预演绿且无未合实现 PR。
  - 无 issue（直接干）：可判验收通过；有测试环境部署 PR 分支验收，无写理由。
  - 有冻结盘点表仅交付表内行；表外新增按 [25-spec-governance](25-spec-governance.md) §二 路由。
  - **竣工回写（开 spec）**：整单出口（最终 `D4 ②` / `D5`）与关单前按最终实现回写唯一现状文档并核销减法（未清理转遗留须用户确认，禁单方跳过）；多 PR 中间子 PR 仅核本 PR 并注明剩余归整单出口。
  - **竣工回写（直接干）**：纯内部 bugfix / 重构零额外文书税；仅改对外行为 / 命令 / 架构 / 接口 / README 时 `D4 ②` 前同步唯一现状 owner（看似触及无需更新一句说明）。
  - 采用 `release` 候选就绪且四类已核；未采用验收即完。文档改跑文档检查；替换式变更按 [change-protocol](30-playbooks/change-protocol.md) 验绿。
- **证据**：PR、构建验收、四类、竣工回写、预演（staging）、worktree / 锁、审核修订、文档检查、表行与 manifest（如适用）。
- **出口**：合 staging（D5）/ PR 合并（D4）/ 无发布义务关单。

### 发布（仅采用 `release`）

- **目标**：把候选变可复现生产版；未采用跳过（不适用，非未完成）。
- **完成（全真）**：批次测试（最终 tag 前重跑）与 rc 验收通过；获 D6 批准并守 [release playbook](30-playbooks/release.md#一发布安全不变式) 全部不变式；生产监控通过（异常按 L0-4 停报）。
- **证据**：批次、rc / 最终 tag、监控、发布记录与快照核对。**出口**：生产验证 + 快照 + 确认关单。

## 三、交付前置条件

- **独立 worktree**：改动在独立 worktree 完成，不在主检出改；仅用户当场明示「直接改 / 不开 worktree」豁免记理由（不自判、不主动建议；真并行锁仍执行）。
- **锁键与命名**：`issue/<N>`（`issue-<N>`），已检出即撞锁停不双写；直接干 `task/<slug>`；批次修 `fix/<N>-<slug>`（直接干 `fix/<slug>`）；hotfix `hotfix/<tag>-<slug>`。
- **起点与目标**：staging 自 `origin/staging` 开 `issue/<N>`、PR 回 `issue/<N>`；三层自 `origin/<集成>` 开、PR 回集成；单主线自 `origin/<主线>` 开、PR 回主线（以项目指令为准，不明按 L0-7 问）。
- **发布不变式**：采用 `release` 须守 [release playbook](30-playbooks/release.md#一发布安全不变式)，违者属 L0-1。

## 四、入口与跳过

- 新需求进澄清；获批 spec 单进交付；直接干进澄清或交付（跳设计）；hotfix 进交付按 D4 合回。
- 入口由 agent 判报，用户按 L0-6 否决；跳过不免目标段完成条件；段间无定序，返修标准不降。
