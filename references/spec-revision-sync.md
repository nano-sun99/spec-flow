# 工作指南：修订后核对现行落点

> 这是同步修改的推荐方法。批准对象、改旧规格、修订与复审权限在 [gate-details](gate-details.md)，当前流程在 [one-path](one-path.md)，记录责任在 [phase-handoff](phase-handoff.md)。方法可替换，现行判据与真实产物一致性的要求不因写法不同消失（依据：rationale R1、R25、R37）。

改判据、定义、常量或术语时，可以先搜关键词、旧值、章节引用及调用方，再按语义找间接落点，而不是只改眼前一句。常见需要对照的地方：

- 规则/原理：同一判定的唯一正文、理由与适用条件。
- 实现/数据源：实际键、接口、脚本或产物是否存在，与文字相符。
- 工作与验收：真正做了什么、如何判对错，相关失败路径是否仍成立。
- 跨文档：总纲、共享合同、兄弟规格及引用锚点是否指向当前 owner。
- 历史：旧决定确被取代时保留原内容与来源，以取代说明或链接区分，不批量改成新口径。

父文档、唯一 owner 和“文档有、实物无”最容易漏。改章节前可先搜谁引用其编号/锚点；改表格后检查列是否错位，长文本宜拆出表格而非挤成不可读大单元格。也可以用精确链接检查、测试或另一种足够的核对方法，不要求一张固定清单才算做过。

同步表达/引用的修正不自动成为新机制；实质改变获批目标/范围、冻结决定或外部合同则回对应闸口，不借“全文同步”绕过批准。验证结果和未测边界落原 PR/issue，指南自身不承接新的完成判据。
