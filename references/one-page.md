# 一页纸（开工前写，用户点头才往下）

> 默认面 3 份之一。只写判定；8 卡默认值见 `one-path.md`，拆分见 `split-large-spec.md`，完成例外见 `done-criteria.md`。

## 1. 三行锚（缺一行不开工）

- **目标**：当……时，系统……（可观察，不写实现手段）
- **不做**：至少一条明确不做的；写「无」也算一条
- **验收**：验收场景，不写实现

三句里任何一句写不成可验证的句子 = 目标没定，停，先问清。

## 2. 范围

- **改**：文件 / 目录 / 模块，一行一个；脚本按这份清单比对 diff
- **不改**：显式列出容易被顺手改的；写「无」也算一条
- **新东西**：不拒绝、不答应，先写进「不做 / 待定」；用户点头才进「改」

范围冻结后，只有变更单能改这份清单。

## 3. 需求与验收

| ID | 需求 | 验收 | 验证方法 | 结果 |
|---|---|---|---|---|
| R-01 | … | … | 命令 / 断言 / 截图 |  |

- 每条 R 至少一条 AC；每条 AC 必须有验证方法。
- 结果列只在完成时填 ✅ / ❌；❌ 未处置 = 不能宣布完成。
- 没有表格的活（改一行、纯查事实）免填，但仍要三行锚。

## 4. 四个选择（各自独立点，不合并）

| 选择 | 选项 | 没点 |
|---|---|---|
| 页面 | 出设计稿 / 不出，用样例 | 停住，等用户选 |
| 机制 | 全要 / 全砍 / 逐项挑 | 不出 spec |
| 例外 | 纳入 / 不纳入 | 按「不纳入」走 |
| 改旧 spec | 新开一份 / 改旧的 | 不动笔 |

## 5. 变更单（范围冻结后唯一入口）

规格外请求：不拒绝、不答应，先写一行：

```text
要什么：
为什么现在：
不加会怎样：
```

用户点头后，才改「改」清单和 AC；没点头就做 = 越界，`spec-check` 的 E5 会按 diff 抓。
