# 记录与证据（L1）

> 「交付与授权要留什么」唯一正文（15 类 = 11 核心 + 4 补充）；完成条件只在 [10-stages](10-stages.md)。
> 沿用原 issue 交接区（无 issue 用任务 PR）；除 manifest 外不新建台账或固定报告文件。

## 一、11 类交付 / 授权与决定记录

| # | 信息组 | 必要内容 | 时点 |
|---|---|---|---|
| 1 | 获批依据 | spec 路径、获批完整提交、方案 PR、修订适用版本 | 开单填；开工核 |
| 2 | 澄清记录 | 决定与可核来源（原话 / 材料 / 事实）；有追问才记问答，未答记待定 | 写 spec / 直接干 PR |
| 3 | 预期交付 | 实现模块、必要测试入口、减法清单、现状真身落点、共享约定 | 提自 spec；实施同步 |
| 4 | 全部实际来源 | 全部实现 / 补充 PR 与完整合入提交；文档真实位置（含改名 / 归档） | 每次合入追加 |
| 5 | 必要依赖 | 所需 issue、共享契约、版本、就绪条件与证据 | 沿用 spec；实施补 |
| 6 | 就绪证据 | 通过的测试 / 验收结果与链接；是否仍有部署义务 | 验证后填（失败不算） |
| 7 | 候选结果 | 挑选 PR、候选结果提交；四类三态（纳入 / 已核 / 不适用及原因） | 合入候选后填 |
| 8 | 合入预演 | 仅 staging：预演分支 / 提交、staging 基线、合并验收及树一致证明 | D5 前填；失败重做 |
| 9 | 四类核对 | spec、实现 / 测试、文档、依赖逐类结果与证据 | release 时 D5/D6 前 |
| 10 | 标签证据 | 当前标签、事实证据、用户确认（三确认项须留证） | 换标签时记 |
| 11 | 授权与决定 | D0 授权（8 字段见 §二）；D1–D7 拍板（对象 / 原话 / 时间 / 范围 / 结论） | 认领前 / 硬闸后追加 |

**「不适用及原因」**：仅述真实未发生 / 不需要，不可免已发生证据；跨记录只引位置，不猜值不造账。

## 二、授权与决定记录（只追加不篡改）

### D0 授权（8 字段）

- **1–4**：① **对象**（issue 或直接范围）；② **方式**（`issue-direct`/`same-window-handoff`/`takeover`，见 [10-stages](10-stages.md)、[20-decisions](20-decisions.md) D0）；③ **原话与可核时间**；④ **本次范围**（缩小须写明，禁扩）。
- **5–8**：⑤ **同窗口摘录**（Spec/issue/下一步；定向不适用）；⑥ **Spec 合并 commit 核对**（无规格不适用）；⑦ **基线与锁核对**（`fetch`/`status`/`worktree list`/`branch --list 'issue/<N>'` 与映射）；⑧ **生效状态**（生效/未生效/撤销及因）。

### D1–D7 拍板

记决定 ID、对象、版本 / 提交（审核含 `base/head` 完整 SHA）、原话与时间、范围、结论，贴原 issue / PR 评论（不代合并）。变更只追加「取代 `<旧记录>`」及因，旧正文不改不删，禁并存两份生效授权。

## 三、4 类补充记录

| 信息组 | 必要内容 | 时点 |
|---|---|---|
| 原任务字段 | 状态（4 段+`paused`/`cancelled`/`completed`）、停止点、暂停/恢复因与范围、工作区/分支/提交、未做项、接手条件、交接要点、测试（输入/预期/实际/证据/结论/范围） | 暂停 / 恢复 / 接管 / 交接 |
| PR 关联 | 只写「关联 issue：#N」（无写范围）；**禁写** `Closes`/`Fixes`/`Resolves` 自动关单词 | 开 PR |
| 事故记录 | 仓内真实事故位置与摘要；无写「无」 | 首登；后迁案例 |
| 收尾 / 关单 | 验收全勾、遗留项、观察式例外、发布记录链接 | 按 §五 |

- **交接要点**：方案已交付、是否获委托、spec 链接/完整提交、执行单、范围、批次、未做与限制、下一步谁做。
- **审核 / 发布**：审核修订贴 PR 评论（无 PR 贴对话），spec 末可追加；发布用项目现有记录，直接干手工列入。

## 四、文档载体、读序与替换处置

### 1. 四种载体与读序

| 载体 | 回答 | 更新口径 |
|---|---|---|
| 现状文档（含运维） | 现在是什么、怎么操作 | 交付出口按最终实现（as-built）同步唯一 owner，他处只链 |
| spec | 本次批准需求与验收 | 批准前可改；合并开单冻结，默认只加状态 / 勘误 / 链接（改旧走 D3） |
| ADR（若采用） | 跨任务长期决定与原因 | 新 ADR 取代旧 ADR，不静默改旧正文 |
| issue / PR | 做到哪、改了什么、证据 | 随实施持续更新 |

- **读序**：先核现状与生效 ADR；实施前必读获批 spec 与验收；历史记录头标「历史快照（日期）：现状见 X」，与实测冲突以现状与实测为准，不取消获批目标或改现行 ADR；承重冲突交用户（L0-7）。
- **基线后修正**：不改范围 / 验收的小修记 issue/PR 链 spec；**勘误限事实写错误导读者**并加带日期链接；改范围 / 验收新开 spec 走 D3。规格治理见 [25-spec-governance](25-spec-governance.md)。

### 2. 替换式变更载体处置表（唯一正文）

| 载体 | 处置 | 证据 |
|---|---|---|
| 未合并草案 / 现行文档 | 原位删替旧句；单决定单正文 | diff + manifest 规则行 |
| 已合并 / 冻结 spec | 默认不改；确「改旧」走 D3；事实错勘误；范围 / 验收变新开 spec | 勘误或 D3 记录 |
| 拍板 / 授权 / 审核 / 修订 | 只追加不篡改；新记「取代 `<旧记录>`」 | 追加记录链接 |
| 历史记录 / 案例 / 旧规格 | 保留；头标「历史快照（日期）：现状见 X」互链 | 标记 + 链接 |
| 迁移别名 / 旧 ID | 仅留「原 `<旧>` → `<新>`」迁移行，不作现行引用 | 迁移行链接 |
| 外部契约 / 已发布 API | 不静默删旧名；兼容层或废弃公告标「已废弃」 | 契约 / 公告链接 |

## 五、关单收尾

**关单 = [10-stages](10-stages.md) 交付完成 + 下述核对全过**（缺失 / 未知 / 失败不算完成）：

- 以获批范围与预期交付核产物与全来源，不以合并 / diff / 标签 / PASS 代验收；必要记录同属交付。
- **竣工回写核对**（[10-stages](10-stages.md)）：开 spec 须核现状真身已按最终实现同步且减法落实或经用户确认（L0-2 / L0-6）登记遗留；缺项不关单，禁以「spec 已写」或笼统「不适用」跳过。
- 采用 `release` 无部署义务文档进候选验收即可关单，代码禁借 docs 标豁免；只勾已满足项，回填后放锁，不删验收凑完成。

## 六、观察式例外

「上线观察 N 天」类仅靠「没出事」判定条目，默认不进验收、不挡关单、不自动开单；线索记「不在本单验收」与核对时机。
仅**方案期 D1** 可申请：**真实时间** / **合规要求** / **必要持续负载测试**（模拟/压测不可替），批准写验什么、异常信号、理由、截止与通过条件。纳入挡关单，到期无结论交用户定（不顺延不判通），不免当下生产验证；实施期不补批。

## 七、#158 三判据（发布与关单验收例）

1. `git fetch` 后 `git diff --quiet <tag> <生产分支>` = 0（三层 / staging 树 = tag）。
2. 能答「线上带没带 `#N`」：tag 到 issue 全来源可追；直接干手工列入发布记录。
3. 出事有确定动作：回滚目标 tag / 快照已列明，只按 D7 执行。
