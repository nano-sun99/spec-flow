# 完成判据：有限承诺、证据与已批准例外

> 本文件是完成与关单判据的唯一正文，随核心流程适用，不走选修采用。流程进度见 [one-path](one-path.md)，交付证据字段见 [phase-handoff](phase-handoff.md)，批准/例外选项见 [gate-details](gate-details.md)。写验收、判断完成、关单时读取；压缩后不可见或版本变化重读（依据：rationale R18、R23、R37）。

## 一、完成判据

**完成是有限承诺**：约定功能/成果已交付，相关正常、异常、边界和回归测试通过，无未处理的已知阻断缺陷，必要证据齐全。不是保证永远不出 bug，也不是“没测过所以没问题”。

- 以获批范围与预期交付对照真实产物及全部来源，不能只看实现 PR 合并、某次 diff、标签或一句 PASS。
- 本任务需要的代码、测试、规格与配套文档以及必要依赖均已满足；不适用的对象说明原因，不补造产物。缺失、未知、失败的证据仍是未完成。
- phase-handoff 定义的适用必要记录同属交付：例如已走候选却缺挑选 PR/候选完整结果提交，不能先判完成、再称“待补但不阻塞”。先回原记录补齐并核实；补前可报告产物已在，不宣称任务完成或关单。
- 按项目实际需要完成测试环境、候选分拣、部署及可判定验收；实现合并只证明实现合并，不证明候选齐全或已部署成功。
- 已采用三层发布的无部署义务文档，所需分支交付（包括进入候选）和验收完成后可关单，内容留候选随下次正常版本进快照，不为此单独造文档热修/tag/部署。
- 仍需部署但本次暂不发的代码不能冒充无部署义务；文档站点、生成输入、运行配置等按实际影响，不按 docs 标签或文件后缀豁免。
- 未采用发布模块或已选单主线的项目按实际约定义务收尾，不强制新建三层。标签、tag、成功快照都不能证明每个服务实时同版。

关单前核适用验收及来源/证据真实齐全，只勾已满足项，回填原任务；锁释放见 worktree-lock。遇缺口补原记录或补交付并验证，不把验收删掉让任务看起来完成，不以等待未约定的下一次真实生产发布拖住已完成的中央规则/普通文档交付。

## 二、观察式收尾默认不进单

“上线后观察 N 天”“等真实用户用后再确认稳定”等通过条件只有“没出事”的条目，默认不写验收、不当关单条件，也不自动开观察单。需要线索可记“不在本单验收”及何时核对；上线后实际出问题再开 bug 单并链接。

这不是免掉当前可判定的生产验证、已承诺部署或已批准例外；能主动验证的必要信号仍要验。把所有未来风险都挂为未完成与把未验证写成成功同样不成立。

## 三、已批准例外

观察式条目只有下列例外类型可在**方案期**请求纳入：

| 类型 | 适用事实 |
|---|---|
| 真实时间 | 结论本身依赖时间流逝，模拟时间替代不了 |
| 合规要求 | 外部合规/审计明确要求观察或留存期 |
| 必要持续负载测试 | 结论需要长时真实负载，回放或压测不能替代 |

批准需写清验什么/异常信号、为什么替代不了、明确截止时间、可判定通过条件；gate-details 负责纳入/不纳入的选项与批准，不因本文举例推定已获准。拿不准适用性不自判，交用户决定；三类之外不擅自扩成常驻例外。

纳入后挡关单，直到有通过或失败结论；到期无结论就报告请用户定，不默认顺延或判通过。实施期新冒出的观察需求走正常可判验收或另开任务，不事后自行补批。未纳入的长尾仍按第二节处理，不自动开跟踪单。
